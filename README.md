# 名もなき文明 v0.5 — 自動で見守る・文明の記憶

ひとつの架空文明の歴史を眺めるブラウザシミュレーター。勝利条件はありません。v0.5ではドット絵・イベントの種類は増やさず、観察の操作性と過去から未来への因果関係を強化しました。

## 開発方針（プロトタイプ）

本作は現在、個人利用の試作段階です。**旧バージョンのセーブデータ・世界生成規則・描画規則との後方互換性は保証しません。** 開発中の破壊的な保存形式変更や、旧互換のためだけに存在するコード・テストの整理を許容します。既存の保存が読み込めなくなった場合は、新しい世界から開始する運用です。

一方、**現行仕様における決定性、保存・再開、過去観測、保存内容の厳格な検証は必須**です。旧セーブの保証をやめることと、現行の歴史を不正に書き換えることは区別します。

開発AI・コントリビューター向けの共通ルールは [AGENTS.md](AGENTS.md) に定めています。Claude向けの入口は [CLAUDE.md](CLAUDE.md) です。以下のv0.5／v0.6の節は当時の開発記録を含み、現在の旧版互換性の保証を意味しません。

## 起動

Node.js 20以上。ZIPにはビルド済みの `dist/` が入っています。

```sh
node scripts/serve.mjs
```

`http://127.0.0.1:5173` を開きます。ソースを変更した場合は `npm run build`、テストは `npm test`。

## v0.6 Phase 1 開発版

v0.6 Phase 1では、地域・居住地・共同体別の人口や、確定した年の観測を導入しました。当時の移行設計では、旧セーブの地理を未確定として引き継ぎ、移行年まで「推定情景」と表示していました。これは歴史的な実装記録であり、現行仕様の旧保存互換を保証するものではありません。

人口の増減には従来の文明単位のルールを使います。

### Phase 2A

近隣との食糧交易、食糧事情による移住、交易路の共同管理を年末に計算する仕組みを導入しました。河川の氾濫で交易路が途絶える場合があり、年代記から関連する記録を開けます。当時は旧セーブの地理未確定人口を、受け入れ余力のある居住地へ少しずつ定住させる移行処理も設けていました。

### Phase 2B・3

川辺、丘陵、入り江の情景を切り替えられます。各地では食糧不足や結束の低下が続くと共同体が分立し、生活が安定すれば再統合できます。寄り合いと記録の慣習は別の共同体に伝わり、穀物庫の備蓄はその土地に残ります。

建物は区画ごとの履歴から描画します。居住規模の変化には人口に加えて施設と周辺地域での役割が必要です。過去を開くと、その年の住民、制度、建物の状態を確認できます。以前のセーブに個別の建物記録がない年は推定情景になります。

Phase 4の試走結果と再現手順は [長期観察の検証](docs/v0.6-phase4-results.md) にまとめています。

ブラウザー回帰テストは `npm ci`、`npx playwright install chromium` の後に `npm run test:browser` で実行できます。

## 自動選択モード

- 「選択も自動にする」をオンにして「自動で見守る」を押すと、選択肢が発生してから **2・4・7秒**（既定4秒）後、選択肢の一つを自動で選びます。
- 自動選択後は **それまでの進行速度のまま** 次の出来事へ進みます。自動選択はオン・オフ切り替え可能です。
- 自動選択をオフにすると選択肢のところで待機し、手で選択すると自動進行を再開します。
- 「自動進行を停止」で進行と選択待ちタイマーを停止します。年代記から過去を見る場合も停止します。
- 選択肢を選ぶ乱数はセーブデータに含めるシード付き乱数を使用。同じシードと同じ操作・設定なら同じ歴史を再現可能です。
- 選択待ちの残り秒数はセーブ対象ではありません。読み込み直したときは自動進行を再開してください。

## 文明の記憶

過去の出来事は、その場の数値変化だけで終わりません。以下の慣習・社会基盤が世代を超えて残ります。

| 記憶 | 生まれる契機の例 | 後世への作用の例 |
|---|---|---|
| 共同の穀物庫 | 穀物庫の建設・食糧の分配 | 飢饉・干ばつ時の食糧への影響を緩和 |
| 水路と堤の管理 | 灌漑・橋の修繕 | 食糧生産と人口許容量を補助 |
| 継続した交易網 | 交易所・渡し舟 | 人口許容量と文化交流に影響 |
| 記録の習慣 | 記録文化・文字の利用 | 知識の蓄積を後押し |
| 寄り合いの制度 | 共同の寄り合い | 制度の履歴として残る（直接効果は限定的） |
| 看病と衛生の知恵 | 看病など | 疫病による人口損失を部分的に緩和 |
| 移住者との共生 | 移住者の受け入れ | 文化的な履歴として残る（直接効果は限定的） |
| 分かれた共同体の記憶 | 分裂など | 文化的な履歴として残る（直接効果は限定的） |

これらは永続するとは限らず、社会や環境の条件に応じて徐々に弱まり、消えることもあります。画面の「文明の記憶」で現在の記憶を閲覧でき、過去観測中は当時の記憶が表示されます。年代記には成立・消滅が記録されます。

**重要な限界**：v0.5は社会制度の精密な数理モデルではありません。記憶の成立率や強度、効果は仮説的なゲームパラメータです。疫学・人口動態・地質学の実測値に校正したものではありません。また、建物の建設・修復履歴はv0.4と同じ簡略化モデルです。

## セーブデータと互換性についての過去の開発記録

v0.5当時は、v0.4以前の保存形式（`version:2`）を読み込むための互換処理を実装していました。ただし、**現在および今後の旧セーブ読込保証ではありません**。現在の開発では、過去版の移行処理を保持するためだけに新しいコード・テストを追加する必要はありません。

### BGM「名もなき朝」

完成済みのオリジナル音源 `assets/audio/namonaki_asa_v3.mp3` をそのまま使用します。
風景の「動き」の隣にある「BGM」で再生・停止と音量を操作できます。曲名は表示しません。停止すると曲の先頭へ戻ります。
音量（初期値30%）と再生設定は専用キー `namonaki-bunmei:music:v1` に保存しますが、
ページを開く・再読み込みするたびに停止状態から始まり、保存された再生設定から自動再生しません。
ブラウザ保存が使えない場合も、そのページ内での操作は可能です。

音楽は歴史・文明の乱数・ゲームセーブから独立しています。Safariで音声の再生許可を一つの経路に統一するため、
クリック内でAudioContextを開始し、原曲MP3を取得・デコードしてAudioBufferSourceNodeのloopで余韻を含めて反復します。
GainNodeで音量を調整します。読み込み中に停止した場合も、後から勝手に再生を始めません。
音色の合成や再作曲、音源の加工は行いません。

`npm run build` は既存の `scripts/copy-assets.mjs` で音源を `dist/assets/audio/` にコピーし、
Pagesワークフローは `dist` 全体を配信します。ビルド時にHTML・全JSモジュール・CSS・音源から内容ハッシュを作り、
画面は `releases/<hash>/` の同じ版のファイル一式を相対URLで参照します。`/namonaki-bunmei/` 配下にも対応します。
更新後に旧CSSや旧JSがキャッシュに残っても、新HTMLと混ざりません。`dist/release.json` で現在の識別子を確認できます。
ルートのJSは既存のモデルテストとの互換のため維持します。BGMはゲームと別のモジュール入口で読み込み、
音楽モジュールの取得・初期化に失敗しても、文明の表示と進行を止めません。
`node --test tests/browser/music.test.mjs`（ビルド後、PlaywrightのChromium/WebKitが必要）でPC・Pixel 7相当のChromium、PC・iPhone相当のWebKit、
サブディレクトリ配信、実音源再生、音量、末尾からのループ、停止、再訪時無音、保存データの不変、
保存拒否・読み込み失敗からの再試行を検証します。既存のブラウザCIにもこのテストが含まれます。
WebKitでは実音源の出力信号、ループ、音量変更、再訪時の無音と読み込み中の停止も検証します。
スマートフォン検証はエミュレーションであり、実機iOS/Safariでの聴感確認は別途必要です。
