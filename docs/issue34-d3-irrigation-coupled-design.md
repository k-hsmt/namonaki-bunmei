# Issue 34 D3-C2：地域経済と水路が互いに変わる独立試走

基準はPR #84統合後のmain `ae90cd6`。ユーザーのC2着手指示に基づく実装前の設計である。C1の式・定数を保ち、単年の地域経済の差を翌年の暮らし・建築・水路へ戻して比較する。本書の統合だけでC2やD3全体を完了せず、通常画面・本番v6の経済policyも切り替えない。

## 1. C1から引き継ぐもの

[C1の設計と結果](issue34-d3-irrigation-economy.md)では、5世界の川辺の全期間収穫に対する差は約0.0000292〜0.00999%だった。一方、seed 1の単年の丘陵→川辺の移動は、2736年に44人→26人、8152年に40人→209人となる例があった。C1は翌年にBの入力へ戻すので、この結果だけでは将来の都市や人口の差を判断できない。

C2では次の4条件をそれぞれ独立した世界として進める。C1と同じ名前だが、**条件ごとの備蓄・地域人口・社会・敷地・環境を翌年へ持ち越す**。

| policy | 追加収穫 | 工事・維持の機会費用 | 役割 |
| --- | --- | --- | --- |
| baseline | 0 | 0 | 年次runnerを変えてもBを完全再現できる対照 |
| yield-only | あり | 0 | 供水だけのフィードバック |
| cost-only | 0 | あり | 負担だけのフィードバック |
| combined | あり | あり | 採用候補の差引と歴史差 |

係数はC1の `irrigation-economy-single-year-v1` を固定し、最大追加100bp、費用上限300bp、建設200／点検50／修復100／埋戻し50／日常管理5bp、乾燥尺度40、長さ尺度64、一年遅れを保持する。位置を持つBの建築優先・取水・寿命40／80／20年・探索予算も保持する。違いを大きく見せるための増幅、`state.food`への別ボーナス、伝承効果の置換は行わない。

地域経済の差を入力にする既存の社会・建築処理は使うが、今回新たに「地域の食糧不足から総人口を直接減らす」等の式は作らない。人口総数や災害年が最後まで同じで、地域配分や敷地だけが変わる場合も結果として残す。

## 2. 本番と分けた入口

新設予定の入口は `src/irrigation/coupled-progression-v1.ts`、型は `coupled-types-v1.ts`、readerは `coupled-history-v1.ts`、独立保存は `coupled-storage-v1.ts` とする。

`createCoupledReview(validatedV6, policy, choiceProtocol)` は記録済み環境・灌漑・生成地形を持つBのv6だけを起点にする。4条件は同じ導入元ハッシュ、確定年J、未確定の選択を含む同じ初期状態から開始する。C1の試走保存、legacy-fixed、環境のない世界、他policyで進めたC2世界をBの起点として受理しない。途中で係数・policy・選択方式を変えるAPIは初回に含めない。

C2のrootは `format: irrigation-coupled-review-v1 / schemaVersion: 1 / status: review-only`、経済の接続ruleは `irrigation-economy-coupled-v1` とする。計算式の版と、フィードバックの版を分け、全定数も保存して厳密に照合する。

内部worldは `irrigation-coupled-review-world-v1` とし、通常の `GeneratedBridgeReview` や `WorldSession` として返さない。land reviewにも、複製で消えない値の `trialBoundary` を付ける。`generatedSession`、本番の進行・保存factory、`createGeneratedSaveDraft`、本番の所有cache入口は、この印がある入力を明示的に拒否する。rootの型名だけに頼って通常のv6へ昇格させない。

描画は読み取り専用のC2 projectionから共通のground・paint部品へ渡す。表示adapterが通常のshapeを使っても境界印は残し、保存・進行の入口へ渡すテストでは拒否させる。通常UI・ブラウザ保存キー・v6 readerの許可リストにC2を追加せず、本番へ変換する操作も作らない。これは誤った経路での混入を防ぐ境界であり、署名のないJSONを人が手作業で作り替えられないという意味ではない。

## 3. 観測hookと経済作用を区別する

C1の `EconomyObserver` は引き続き読み取り専用で、戻り値を無視する。C2の作用は別の `CoupledAnnualEconomyPolicy` として、C2の内部runnerだけが作成する。

現行の `GeneratedAdvanceOptions` へ自由な係数callbackを追加し、通常の `advanceGeneratedBridgeReview` から経済を変えられるようにはしない。engineの内部land policyにはC2の判別可能なmodeと係数を渡せる共通入口を設けるが、本番factoryはC2 mode・境界印・未知の経済設定を拒否する。旧modeの計算分岐と演算順は保持する。

modifierは前年の確定prefixから生成した整数 `gainBp / requestedCostBp / costBp` と出典だけを持つ。callbackの中からlive文明stateを書き換える方式は使わない。engineは地域経済の直前で、その年・policy・係数の範囲を照合し、川辺のharvestFactorに一度だけ適用する。他の2地区の係数はその時点では変更しないが、交易・移住による間接差は許す。

## 4. 一年の順序

Y年に入る前、最後の確定年はY−1とする。

1. **前年の作用を準備**：自分の枝のY−1年のchannel、実在する畑、土壌・水分、工事イベントからC1と同じ式で係数を求める。Bや他の枝の未来の台帳を使わない。
2. **年の開始**：既存の `step` と同じ順で短期降雨、伝承、全体の食料・人口、抽選、選択の発生を進める。ここに新たな乱数を加えない。
3. **選択待ちなら停止**：未確定のY年では、地域経済・社会・建築・水路・生態系と確定receiptをまだ進めない。作用の準備は計算であって、費用の適用済み記録ではない。
4. **地域経済**：選択がなければ通常の確定経路、あれば選択後の `finishYear`で、当年の既存harvestFactorに `(1 + (gainBp − costBp)/10000)` を一度だけ掛ける。更新した地域経済と人口配列を、その枝の実状態へ採用する。
5. **社会と土地**：同じ年の社会・施設・橋・住宅・共同空地・観測を現行の順序で確定する。変わった供給率や地域人口から成立／不成立が変わり得る。
6. **水路と環境**：当年の自分の土地変更を読み、後発占有、時計、休止、新設・点検・修復、再開の順をBどおり適用する。その状態・工事攪乱と当年の気候・土地利用で環境を一度進める。
7. **確定**：経済receipt、乱数診断、必要なcheckpointとcurrentを確定してからY+1へ進む。途中で失敗した場合は呼出元の試走を変更しない。

575年にできた水路は576年から作用する。615年の破損は616年から利益・日常管理の対象外になる。作用導入年J以前の工事費は遡及せず、原因年がJより後の費用だけを対象にする。J年に既に稼働していた水路の利益・日常管理はJ+1年から始められる。

現行 `economyEffectReader` はC1の観測範囲内だけを許可するため、C2からその上限を緩めて呼ばない。式と前年入力の抽出を純粋helperへ分け、C1 adapterは現在の観測境界を保持、C2 adapterは `effectYear = confirmedThrough + 1` を検査する。未確定年の観測を許可したことにしない。

## 5. 選択待ちと途中導入

`confirmedThrough` は `lastObservedYear`、環境・灌漑・経済receiptの上限も同じ年にする。pendingがあるworking文明の年だけが、その翌年になれる。描画と経済の確定グラフはconfirmedThroughまでとし、pending自体は選択画面用の未確定データとする。

未確定年へ入った後のworking state、準備済み係数の出典、部分的な乱数診断を保存できる。再読込で年の開始をもう一度実行せず、選択を確定した時にだけ地域経済を適用する。同じ年の経済receiptは1件、pending中の再描画・書出し・`advance(0)`は適用0件。手動・自動の選択の出典も保存する。

導入元のv6がすでにpendingの場合は、その未確定working stateもそのまま起点にする。導入前に済んだ降雨や抽選を巻き戻さず、次の`finishYear`から作用する。導入前の乱数消費数を0と推定しない。Bの同じpending起点と対照を組み、J以前の履歴・敷地・景観を保持する。

advanceの年数・stop／automatic・最後のpending処理は現行Bの契約に合わせる。新たにattemptする年は10000年以内とし、10000年の工事が10001年に作用する分は集計外として別に件数を示す。範囲外を進めて費用だけ計上したり、最後の工事を無償だったと解釈したりしない。

## 6. 年次runnerを二乗の計算量にしない

`advanceGeneratedBridgeReview(world, 1)` を10000回呼ぶ構成は採らない。現在のAPIは呼出しごとに文明・履歴を複製し、環境のsourceを構成し直すため、長期ほど重くなる。

内部batchでは一度だけ所有するworking stateを作り、施設のpolicyと年次driverを共有する。確定年ごとの終端だけをC2の制御へ戻し、水路・環境を進めてから次の年へ入る。公開APIの返却時にだけ不変なsnapshotを作る。Bの複数年進行は従来の経路を保ち、C2のための処理を通常UIへ常時追加しない。

環境のstepも、毎年全履歴から `landUseEvents`や植生を再生成しない。初期prefixを一度読み、年次deltaとsource cursor、土地revision、占有・農地のpatchカウンタを更新する。土地利用の同年順序は現行のカテゴリ順と各台帳順に合わせ、単なる記録ID順へ変更しない。`stepPatch`、気候の進行、wetセル、ライフサイクル、幾何・歩行の検証は共有する。

新設の原因が生じた年にだけ、実在する自分の枝の敷地から探索する。無作用C2ではBの全保存の意味が一致しなければ、このrefactorは統合しない。境界で公開された値を後からmutableなrunnerへ渡して書き換えず、callback・await中にも呼出元の値を所有し直す。

## 7. 保存するもの

各policyは独立した試走保存を持つ。4つの全世界を1つの保存へ詰めず、同じorigin hashを持つmanifestで比較対象を関連付ける。

| 項目 | 内容 |
| --- | --- |
| 識別 | root/schema/status、feedback rule、C1の計算式と全定数、policy、choice protocol、kernel・乱数診断の版 |
| 起点 | Bの導入元ハッシュ、導入年J、初期mutable state、起点の各append-only台帳の長さ・cursor、初期の経済・環境境界 |
| 現在の枝 | 地形・河川・plansを1つずつ、文明・土地・水路・植生・環境の自分の履歴とcurrent、あればpending working state |
| 経済receipt | 年、前年の確定参照、供水・畑・土壌・工事の出典、候補の整数係数と実際に適用した係数、実際の経済入力tuple・発行記録参照、丸め・上限・0人口のflags |
| 選択・乱数 | pendingの内容fingerprint、選択肢と手動／自動、step／choiceの前後の乱数状態と消費数、未確定phaseの区別 |
| checkpoint | Jから100年ごとの経済・source cursor・診断状態とcurrent。環境は既存の灌漑導入年を起点にしたcheckpointを保持し、同じ全patchを重複格納しない |

初期のB世界と最新世界に同じ地形や履歴prefixを二重格納しない。最新の枝に不変の導入前prefixを一度だけ持ち、初期mutable stateと台帳長から導入時のB payloadを再構成してorigin hashを検証する。pending起点には未確定年の既存記録もあり得るため、年の比較だけで切り取らず長さ・cursorを使う。この原点の再構成は検証内部に限定し、作用後の枝を本番v6として返す操作にはしない。

毎年の全世界・全patch・全地域経済を保存しない。経済の直前人口・干ばつ・flags・記録参照はC1と同じcompactなtupleにし、その枝の前年度の経済から次を再生する。備蓄・coverageの浮動小数を独自に丸めず、食糧単位の丸めは既存の収穫計算で一度だけ行う。JSON16MiB／gzip目安4MiBは**各枝**に要求し、超えたらcodecを見直して履歴を省略しない。

## 8. readerと検証範囲

readerはwriter・経済作用の実行hook・新設探索・気候目標生成をimportせず、保存済みの入力と決定を読む。自然保存への制御原因の混入、未知版、混在policy、途中の定数変更、未来参照、重複年・重複適用、原因の欠落、他枝のgeometry・receipt、壊れたoriginとcheckpointを拒否する。

検証は次の範囲を明示して行う。

1. 導入元のv6構造・origin hash・不変prefixと各台帳、現在の文明stateの構造・出典を検証する。本番の所有cacheへC2を登録しない。
2. 各年の確定prefixから係数を再計算し、記録した入力と実際のC2記録IDで地域経済を再生する。経済state・地域人口・収穫・交易・移動・集計とcheckpoint/currentを照合する。
3. 自分の枝の土地・原因・記録済み経路で水路と環境を再生し、物理・占有・歩行・順序・全snapshotを照合する。不成立の最適性を新探索で証明することはせず、Bと同じ有界receipt検証を行う。
4. 乱数状態の連鎖、phase、選択の内容と状態遷移の範囲を検証する。署名なしの資料だけで、保存されていない全ての文明抽選・候補重みの真正性を証明したとは扱わない。

共通の幾何・環境のvalidatorを中立部品として使い、rootの本番境界・所有証明は分ける。原点・全sourceを固定してからawaitし、長い再生はブラウザへ制御を返す。検証済みの深く凍結した正確なrootだけが観測・再開できる。read→writeと、一括／分割／pending保存／gzip再開が完全一致することを別に確認する。

## 9. 乱数と共通の選択

追加収穫・費用・配水の式自体は乱数を消費しない。現在の `SeededRng` はMulberry32で、nextごとにstateへ `0x6d2b79f5` を加える。C2ではstepと選択の呼出し前後のstateから、既存の有界な1phaseの消費数を検査できる診断を作る。診断案は `imul((after − before) >>> 0, 0xdc58aa5d) >>> 0`（増分の32bit逆元）で消費数を得る。既知kernelの各phaseが4096呼出し以下であることをコードと検証で確認し、その上限と全体100万呼出し以内を初期の診断契約とする。これを超えるkernelは別版として扱い、黙って剰余だけを採用しない。乱数器へ診断のためのnext呼出しを加えない。前後state・消費数・演算版を保存し、単体で既存乱数器の実測と照合する。大きすぎる消費数や未知の乱数版は拒否し、32bitの周回を無視して同じstateを常に0消費と断定しない。

気候targetは現在のseed・気候rule・開始年から決まるため、同じ年のglobal targetと温湿度は枝間で一致するはずである。一方、短期降雨や出来事のeligible条件・選択出現・乱数消費は文明stateに依存して変わり得る。災害年やRNG状態の一致を強制しないし、違いが出なければその事実を記録する。

主比較は `automatic-per-branch-v1` とし、各枝が自分のRNGで自動選択する。補助比較 `common-explicit-v1` では、両方に同じ分岐がある場合だけ明示選択を適用する。現行の `Decision.id` は `choice-年` で、選択肢には独立IDがないため、IDやindexだけでは同じ内容と判定しない。年・決定IDに加え、版付きtemplate indexと質問・選択肢の内容fingerprintを照合する。

片方にしかない分岐・異なる内容が出た場合、補助比較は共通に進められる境界で停止して理由を示す。片方だけ自動選択へ切り替えて共通選択と呼ばない。主比較と補助比較では自動選択の乱数消費も異なるため、別manifest・別の対照を用いる。Bの未来の選択・災害・敷地・水路をC2へ固定しない。

## 10. 比較する結果

自然seed 1／21／29／42／198を0〜10000年、4条件で比較し、不成立・未到達・差が0の世界も残す。固定年0／100／300／1000／2000／10000の3地区と、最初の意味のある分岐前後を同じ年で表示する。

- 年別の実際の収穫、備蓄、供給率、輸入、交易、地域人口・未所在人口・総人口、社会・都市段階と到達年。
- 系統数、稼働・停止・埋戻し、配水率、工事と日常管理、要求／適用費用、0人口の工事、上限超過、末尾で効果年が範囲外となる工事。
- 最初の経済差・地域移動差・敷地差・水路差・出来事差・選択差・RNG差を、原因年／作用年／phaseとともに記録。
- C1の「同じ入力ならその年だけどう違うか」と、C2の「違いが翌年へ戻った実際の枝」を別の図にする。

chronicleの `年-index` は記録数が変わるだけでもずれる。ID差だけを新しい出来事と数えず、年・kind・本文・対象の実在形状・原因の意味を照合する。同じchannel IDでも異なる経路なら別の物理結果として表示する。診断記録は専用台帳に置き、無作用枝の文明historyへ毎年の追加記録を入れない。

出力は `artifacts/environment34-irrigation-coupled/`。各枝の通常と同じ描画部品による原寸／4倍、必要な短い動画、年別の対話的な図、分岐原因表、各枝の独立保存、全監査と生の性能値を同梱する。人工の休止／修復、前年参照、費用上限・0人口、選択不一致等のfixtureは別形式の計算・状態機械データとし、自然保存へ制御入力を混ぜない。

## 11. 統合前の検証と性能

最初の実装は無作用C2でBを完全再現するところから始める。共通driver・incrementalな土地利用／環境処理を追加しても、既存B・C1の全保存とRNG、A2のSHA基準、物理探索の経路・予算、Safariを含む既存画面・BGM・配信の検証を保持する。

必須検証は、4条件の同じ起点、導入年0／99／100／575／任意年、既存pending起点、建設／破損／放棄／埋戻しとその翌年、C1と同じ確定prefixを使った一度の計算の一致、同年の社会・敷地・水路への接続、手動／自動選択、0年進行、全エラーの原子性、過去の画面、起点の再構成、全台帳改変拒否、本番入口での拒否、一括／分割／gzip再開と続きの完全一致とする。

無作用C2は自然5世界×1万年でBの完全な保存内容の意味が一致しなければならない。比較では診断用の非永続集計を分け、C2のheaderや専用receiptが違うことを文明差として扱わない。他の3条件は、全出力がBと一致することを要求せず、変化の出典と自己再現を検証する。

正式性能はseed 42の2000／10000年、seed 21の2000年を1回warm-up＋5回中央値で測る。無作用C2とBの同じ出力で共通runnerの追加負荷を測り、初期目標はB年次比1.10倍以内。combinedは枝ごとに2000年5秒／10000年25秒・B比2倍以内を目標とし、状態・探索・建築の仕事量が分岐した差も併記する。4つの文明を進める合計時間は別に表示し、C1の4条件の軽い単年計算と同じ総時間だと扱わない。初期導入・年次・全保存準備・cold read・観測・描画は分け、基準を超えたら値や履歴を省略せず処理を見直す。

## 12. C2の完了と採用判断

実装・全検証・自然と人工の比較資料が揃った段階で、定数据え置きで本番化を設計する／モデルを修正して再比較する／追加経済作用を延期する、を判断する。近似上限・労働の出自・既存伝承との重複、差が小さい場合や望ましくない歴史差も理由として扱う。

C2は独立試走までであり、新規世界の既定・旧世界への明示導入・本番保存の経済policy版の更新は採用判断後に行う。D3全体の区切りとD4への移行は、この判断と未採用事項を記録して決める。設計PRだけでC2・D3・Issue #34を完了としない。

## 13. 最初の実装：中立な土地driverと診断

最初の実装を、土地の共通年次driverと無作用の監査入口に区切る。`generated-land-batch-internal.ts` はバッチ内で1つのworking文明を進める。既存Bの入力検証・複製・施設policy・生態系の最終処理は保持し、公開APIには年次制御callbackや経済modifierを追加しない。内部の各phaseが戻った時点で、live stateを含まない凍結したprimitive値のreceiptを試走側へ渡す。通常Bではreceiptを生成しない。

`coupled-baseline-audit-v1.ts` はBのv6から同じBを進め、別の診断台帳にstep／自動選択の前後RNGと確定境界を記録する。これはC2の作用済みworldやC2保存ではない。ここで返すworldは無作用のBであり、C2のroot・boundary印・codecは次の作用runnerとともに実装する。既存pendingから始める場合、そのstepが導入前に消費した乱数は不明（null）とし、0とは記録しない。

現kernelのstepの乱数消費は、降雨3、伝承の種類数以内（最大8）、知識・交流2、災害判定1、災害選択最大1、選択済み出来事の乱数最大1、選択発生判定最大1、template選択最大2の合計19以下である。診断には保守的な上限64を使い、自動選択は厳密に1と照合する。逆元計算自体の許可上限は4096、バッチ全体は100万で、任意の長い乱数列の周回数を復元するAPIとは扱わない。

変更前のmain `9fe364bd5bb80127551ded67fa7163c26c75613d` を別ディレクトリでbuildし、seed 1／21／29／42／198の1万年後のv6全保存をcanonical JSONでSHA-256化した基準を `tests/fixtures/coupled-baseline-b-reference.json` に保持する。`scripts/audit-coupled-baseline.mjs` は新driverの全保存をこの変更前の基準と照合し、各年のcommitが一度だけであることとphase間のRNG連鎖も検査する。単に変更後のBと同じ共通コードを比較するだけにはしない。

初回監査では5世界すべての全保存SHAが一致した。計5万年のcommitは各年1回、自動選択は計294回、観測したstep内の最大乱数消費は17で上限64以内だった。追加の単体検証では導入年0／99／100／575、pending起点、0年進行、手動選択後の進行、分割再開、stop-at-record、診断callbackの例外時の入力不変と、既存乱数器による実測・32bit周回・範囲外拒否を確認した。CIに同じ5世界の長期監査と結果artifactの出力を追加する。

この区切りでは水路・環境はまだバッチ末尾のB replayである。**当年の環境を確定してから翌年へ渡すincremental runner、C1式の作用、C2境界と保存、4条件の独立比較、正式性能測定は未完了**であり、C2全体の完了や性能基準の達成とは数えない。次は土地利用・植生・水路sourceをcursorで更新し、各年の環境確定を接続した無作用runnerで同じ全保存基準を再度満たす。

## 14. 次の実装：無作用の年次水路・環境runner

`annual-baseline-internal.ts` は非公開の土地batchを1回だけ所有し、確定した年ごとに土地差分→既存の水路ライフサイクル→既存の環境計算を進めてから次の文明phaseへ戻す。通常Bの公開入口は引き続きバッチ末尾のreplayを使い、比較対象として残す。作用式・係数・描画・本番の経済policyは変更しない。

`annual-land-sources-internal.ts` は、文明記録・施設・橋・住宅・共同空地・各地区の建物変更をappend-only cursorで読む。住宅等の建設とfieldの状態遷移、火災の出典を保持し、土地利用は既存のカテゴリ順と各台帳順、植生は年・地区・ID順を維持する。全文から計算する既存の `landUseEvents`／`vegetationSourceEvents` は変更せず、自然5世界の各年差分を積み上げた値と確定prefixで照合するoracleとしても使う。記録済み未来が配列に存在するfixtureでも、未確定年を取り込まない。

水路のsource indexには、確定した土地revisionと原因だけを追加する。変化のない年は同じ敷地frameを再利用し、現在のconfirmedYearだけを更新する。ライフサイクルへは土地と原因の最小interfaceを渡し、古い環境headerを当年環境として参照させない。環境runnerは翌年分の差分だけを受け付け、占有・農地のpatchカウンタを更新する。過去・未来・同年の二重appendは拒否する。`stepPatch`、気候、ライフサイクル、幾何・歩行の計算は既存部品を共有する。

毎年の全世界複製・全履歴scan・全patch snapshotは作らない。導入prefixの読み込みはバッチ開始時に1回行い、環境snapshotは既存の灌漑導入年を起点にした100年checkpointと返却時のcurrentに限定する。各phaseのreceiptには環境確定年のbefore／afterを記録し、「環境を確定してから翌年へ入った」ことを検査する。pendingでは環境を進めず、手動選択は乱数0、自動選択は1を消費して、その年の環境を1回だけ確定する。

初回の長期監査ではseed 1／21／29／42／198の各1万年で、§13の変更前Bの全保存SHAがすべて一致し、計5万回の年次環境更新とRNG連鎖も一致した。追加検証には、開始年0／99／100／237／574／575／614／615／674／675、灌漑自体の途中導入99／237、旧気候と将来だけの緩やかな気候への切替、cold replay、pendingのgzip再開・手動／自動選択、0年進行、無効差分と例外時の入力不変を含む。gzip後はBの仕様に従って非永続の探索診断がリセットされるため、再開結果は全保存の内容で比較する。

`audit-annual-baseline.mjs` と `benchmark-annual-baseline.mjs` を既存のC2基盤CIへ追加する。性能はseed 42の2000／10000年と21の2000年を1回warm-up＋5回、順序を交替して測り、年次処理と保存準備を含む全体を別々に記録する。ケースごとにプロセスを分け、直前の1万年ケースのheapやJITの状態を次のseedへ持ち越さない。初回の連続プロセス計測ではseed 21が1.171倍、同じ実装の単独計測は0.984倍となったため、この分離を追加した。処理範囲・対象世界・年数を変えず、無作用runnerの年次B比1.10以内を検査する。初期地形生成とIOを計測へ混ぜず、4条件を進める費用や経済作用の性能達成とは扱わない。

分離後の初回ローカル測定では、上記3ケースの年次B比は順に0.988／1.042／1.003で、すべて基準内だった。保存準備を含む全体の中央値は約2.60／11.80／2.43秒だった。実装コミットのCIでもunit 386件（失敗・skipなし）、5世界の全保存一致、3ケースの性能基準を通過している。生の5回分の値はCI artifactの `annual-baseline-performance.json` に保存する。

このrunnerも無作用のBであり、C2の作用済みworldや専用保存ではない。次は前年の確定環境を作用式へ渡すadapterと経済の一度だけの適用、C2 root／boundary印／専用保存を接続する。C2・D3・Issue #34は引き続き未完了である。

## 15. 経済作用と試走境界の接続

この区切りでは、C2の経済作用とメモリ内の試走境界を実装する。専用の保存・reader・再開codecと、4条件の自然史の比較資料は次の区切りである。通常UI・本番経済policyを切り替えず、C2・D3・#34の完了とは扱わない。

`economy-effect-core-v1.ts` にC1の計算式を抽出し、C1 readerは従来どおり記録済み年までに制限する。C2は自分の枝の直前の確定年だけを読むadapterを持つ。水路・工事・畑のrevisionは年次indexから取得し、水分は当該patchだけを読む。毎年の全履歴scanや全patch snapshotを作用計算へ追加しない。最大追加100bp・費用上限300bp等のC1定数と演算順を維持する。

年の開始前に前年の作用を準備し、pendingでは準備値だけを保持する。選択なし、または選択確定後の `finishYear` がC2専用modeを検査し、川辺のharvestFactorへ一度だけ掛ける。その枝の地域経済・地域人口を実状態として更新し、同年の社会・施設・住宅・共同空地、続いて水路・環境へ渡す。総食料・人口への別ボーナスや追加乱数はない。575年の建設は576年から作用し、導入年以前の工事費は遡及しない。

`createCoupledReview` は検証済みv6保存から、同じorigin hashを持つ4 policyの別々の所有rootを作る。rootと内部worldは専用format、landは複製で消えない `trialBoundary` を持つ。各進行は所有するrootだけを受け付け、入力は不変に保つ。現在はメモリ内での所有証明のみで、JSONやstructuredCloneした試走を読込済みとして再開する入口は作らない。これを専用保存の実装済みと扱わない。

地域経済のreceiptには、原因となる前年の作用、実際のgain/cost、人口・干ばつ・洪水・穀物庫・実際の発行記録IDのcompactな入力tuple、収穫と余剰廃棄量を残す。毎年の全地域経済snapshotは保存しない。初期経済から全年度を再生し、最後の枝の経済・人口・各年の収穫・廃棄・発行本文を照合する。備蓄上限に達すると収穫差が次年の備蓄差として残らない場合もある。人工の低備蓄起点では、前年度の差が翌年の余剰廃棄まで持ち越されることを検証し、自然試走とは分ける。

主比較は各枝の自動選択とする。共通の明示選択は、origin hash・protocol・版付きtemplate indexと年・質問・全選択肢のcanonicalな内容bindingが一致した枝だけへ適用する。`chooseCommonCoupledReviews` は全枝を照合してから進め、不一致では進めない。自動／手動のphaseには実際の選択indexと内容bindingを記録する。導入前に済んだpendingのstepの乱数消費を0とは推定しない。

通常のsession、進行・保存factory、生成保存draft、本番の所有cache入口は、C2 root・world・landの印を明示的に拒否する。通常shapeへ包み直した値やstructuredCloneにも同じ拒否を適用し、既存Bの公開optionへ経済callbackを追加しない。これは偶発的な混入を防ぐ境界であり、人がJSONから印を削る操作を防ぐ署名ではない。

`audit-coupled-effects.mjs` を独立したCI jobへ追加する。自然5世界×1万年で無作用枝の全B値と既存全保存SHAを照合し、combined枝の全年度の地域経済と発行記録、9900年からの分割再開を照合する。これは経済作用を接続する段階の監査であり、4条件の景観比較、専用codecの改変拒否・gzip再開・容量、および保存準備を含めたcombinedの正式性能の代替ではない。

## 16. C2専用保存・reader・再開

PR #88統合後、C2独立試走の専用codecを実装する。通常保存キーやv6 readerの許可リストへは追加しない。`coupled-storage-v1.ts` はcompactなJSONと標準gzip envelopeだけを出力し、`coupled-history-v1.ts` が検証した正確な凍結rootだけに、C2専用の継続所有証明を付ける。#88のメモリ内rootはまだwire契約ではなかったため、当時の任意のJSON化を互換保存とは扱わない。

保存の実体は最新の枝のworldを一つ持つ。導入元は `coupled-origin-prefix-v1` のtemplateに、当時の可変値と台帳の長さ、人口blockの途中cursorを記録する。地形・河川・plans・初期植生・導入前の台帳は最新worldへの参照とし、同じprefixを二重格納しない。元v6の土地基礎にある過去のaccess証拠は、導入元に固有の情報として残す。導入時点の環境currentは過去checkpointから再構成する。最新currentがcheckpointと同年なら、そのsnapshotも参照で保存する。pending起点の未確定記録は年だけで切らず、保存した台帳長を使う。

元のv6を内部だけで復元・検証し、導入元hashと、導入年・初期経済・pending・RNG状態を照合する。作用後のC2を本番worldとして登録しない。共通の土地validatorを使う際もlandの印を保持し、水路・環境の検証と観測は本番所有cacheから分離した中立reader部品を使う。

経済receiptとphaseは版付きtupleにして、毎年繰り返すfield名を削る。100年ごとの経済・人口・phase位置・source cursorを保持し、最新値はworldのcurrentに持つ。探索回数等の非永続診断はwireでは0へ正規化するため、完全一致の比較対象は再書出しと以後の全保存内容である。kernel・乱数診断・選択templateの版とC1の全定数を厳密に照合する。

readerは、記録済みの水路決定・幾何・土地占有からライフサイクルと環境を再生し、その各年の確定prefixで係数と地域経済を再生する。収穫・余剰廃棄・地域人口・発行本文・原因・全checkpoint・最新経済を検証する。乱数状態の連鎖と有界消費、既存状態の先頭3出力からの干ばつ、自動選択の1出力と実際の選択index、版付き質問・選択肢・選択記録も照合する。診断は保存済みstateに対応する値を読むだけで、乱数器のnextを呼ばない。長い年次再生は制御を返す。非同期hashの前に入力全体を所有し直す。

payload全体の結合hashも付ける。これは署名ではなく、再計算可能な整合性検査である。個々の地域経済・水路・環境はhashと独立して再生するが、保存されていない全ての文明抽選・候補重みや全ての大域変数の真正性まで証明するreaderとは扱わない。検証範囲は§8・§9の契約を保つ。

単体検証には4 policyのplain/gzip往復、導入年0／99／100／575、pending起点と新しいpendingの手動／自動再開、分割継続、原本・係数・人口入力・干ばつ・経済本文・幾何・checkpoint・RNG・選択の改変拒否を含む。結合hashを再計算した改変も、独立の再生で拒否する。C2進行・気候producer・新たな灌漑探索・乱数器のnextを遮断した別プロセスでも読込と再書出しを検証する。

初回の5世界×1万年のcombined監査では、plain約9.65〜10.49MB、gzip保存用JSON約1.30〜1.38MBで、cold readと9900年からのgzip再開が一致した。16MiB／4MiBの上限を履歴省略なしで検査する。4 policyすべての自然比較、同年景観・分岐原因、保存準備まで含む正式性能は続けて検証する。
