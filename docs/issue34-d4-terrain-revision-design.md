# Issue 34 D4：恒久地形改変の設計と作業計画

2026-11-09、D4-0設計案。基準mainは `56589fd`。D3の本番計算・通常画面・新規既定／最終比較（PR #92・#93・#94）はすべて統合済み。本書では設計と工程だけを追加し、地形・年次計算・保存・新規既定は変更しない。

## 1. 目指す変化と最初の範囲

丘陵で農耕を続ける人々が、近くの斜面の一部を削って小さな段状の平場を作る。後の建築や通行は実際に変わった地面を使い、利用が終わって草木が戻っても、削った形は残る。改変前の年を見れば元の斜面を表示する。

最初の試作は **hill-sideの小規模な切り土・段状整地** とする。現在の畑の敷地26×14pxを置ける平場を評価単位にし、成立しただけで畑を追加したり収穫を増やしたりしない。後年に通常の需要・選択から実際の畑が成立すれば、その時から既存の土地利用・社会計算を通る。「段々畑が成立した」と呼ぶのは耕作も確認できる場合だけで、整地だけの状態と区別する。

地形revision、占有、水理、橋、歩行、植生、過去観測、保存の共通契約を先に作る。盛り土、採石量・運搬・労働人数、遠景の山の削り取り、河川付替え、堤防、海岸埋立、大規模配水網は初版に含めない。河川を変更する改変は§11の別設計が必要で、小さな切り土の成功を水理変更の安全性と読み替えない。

## 2. 現行実装で越える必要のある境界

| 接続点 | 現状 | D4で必要な変更 |
| --- | --- | --- |

| [terrain-record-raster-v1.ts](../src/terrain/terrain-record-raster-v1.ts) | 保存されたshapeとphysicsの一致を検証 | 初期shapeは不変、改変後のphysicsは別の版付き契約で検証 |

| [geometry-v1.ts](../src/irrigation/geometry-v1.ts)・河川／橋の検証 | 初期地形・保存水源に基づく幾何 | 改変前後の同じ年の地形で保護対象を再検証 |

`TerrainRecord.source.revision` は生成元コードの出典であり、時間で変わる地形revisionには流用しない。既存の初期地形validatorへ改変済みラスタを偽装して通さない。

## 3. 正本・revision・対象年のAPI

新しい地形履歴は、初期地形1個と、版付きの確定改変イベント列、必要なcheckpointから構成する案とする。

- `TerrainRevisionId`：初期地形のhashを起点とし、親revision・commit年・イベント内容を結び付けたSHA-256。地区IDと規則版を含め、表示上の左右反転座標は使用しない。
- `TerrainChange`：改変ID、種類、地区、cause、承認年、作用開始年、親／子revision、変更セルの前後値、再計算領域、利用状態、検証結果の根拠を保持する。
- `cause`：専用の判断IDと規則、同じ世界の確定した農耕敷地・建設／利用記録への参照、評価した年の状態を保存する。古い年代記の「山を開く」等の文章から事後的に地形を作らない。
- セル差分はcanonical座標順の重複しないrunで保存。`surface / grade / bearing / elevation`の整数範囲、前値、影響範囲を検査する。差分を適用した結果からgradeを再計算し、保存結果と照合する。丘陵の試走では既存の4近傍の標高差を用い、gradeは `min(2, 最大差)`、崖は2とする。初期版の地面範囲・端の扱いも保持し、規則IDで固定する。
- `resolveTerrainAtYear(history, year)` → `ResolvedTerrainAtYear`：基準hash、対象年、revision、地区ごとのphysics、描画に必要な改変形状を返す読み取り専用API。初期shapeと差分のどちらが正本かを曖昧にしない。

旧 `terrainRecordAt` の意味とv1 validatorは維持する。地面・橋・水路等の共通の物理読取部分には明示的なview／adapterを設け、D4のviewを旧 `ValidatedTerrainRecord` へ型castしない。最初は切替なしのviewで現行v7を完全再現してから改変を許可する。

checkpointは100年境界を候補とし、同じrevisionならラスタを重複保存しない。直近checkpointからイベントを再生する。年ごとの全ラスタ複製と、観測時の初期地形再生成を避ける。キャッシュは基準hash・revision・地区・renderer版を含み、植生や素材にはさらに年・環境・利用状態を含める。キャッシュがなくても結果は一致しなければならない。

## 4. 最初の切り土の暫定条件

以下は **独立試走の出発値**。正式policyの採用値ではなく、自然比較で成立しない結果も残して見直す。

| 項目 | 試走案 |
| --- | --- |
| 対象 | hill-sideの既知の安定陸地。水面・崖・砂州・画面外を除外 |
| 平場 | 26×14px、候補の左上は2px格子。現在の畑寸法に合わせる |
| 掘削 | 目標高は平場内の最低高。各セルの切下げは最大2相対標高単位、盛り土なし。少なくとも1セルが変わること |
| 影響範囲 | 2pxの周囲も再評価し、最大640セル。gradeと2px通行窓への影響を含む。範囲外へ影響が波及するなら拒否 |
| 水域との距離 | 全影響セルは淡水・海水から4px以上離す。表面区分・水域の形・水位・stream／portは一切変更しない |
| 利用と保護 | 現役建物・住宅・畑・共同空地・予約、橋と橋詰、水路と取水部、既存改変との重なりを拒否。既存利用の移設・立退きはしない |
| 接続 | 初期拠点と既存の入口・橋詰の到達性を維持し、新しい平場の入口にも2px通路で到達できること |
| 自然発生の候補年 | 導入後の100年境界。丘陵の確定した畑が50年以上継続利用され、pendingがないことを条件に評価 |
| 頻度の上限 | 成功後500年の間隔、1世界で最大4件。成功・保留とも判断理由を記録 |
| 候補の順序 | 合法な候補のうち総切下げ量、既存の農耕地への歩行距離、canonical座標順で決定。文明RNGを追加消費しない |

隣接する平場を連続させる段々畑、多段の擁壁、土砂の行き先や安定性はまだモデル化しない。切り土による局所的な「水がたまる／流れる」を描いたり収穫に足したりしない。現行の水理は物理流体モデルではなく、初版の保証は保存された水域・水源・合法経路を維持する範囲に限る。

候補探索に上限が必要なら、その走査順・上限・打切り理由を規則へ保存する。「安全な候補が見つからない」と「存在しない」を区別し、成立率のために保護条件を緩めない。

## 5. 年次順序と原子的な改変

導入する確定年をJとし、J年以前の地形と文明を保持する。承認年Yの工事は、**Y+1年から地形として作用**する。

1. 当年Yは、年初に確定しているrevisionだけで経済・社会・選択・建築・水路・環境を進める。選択待ちは当年未確定として止める。
2. 全ての当年処理が確定した後、同じ年末の敷地・水路・橋・予約・利用履歴から候補を作る。当年に建った施設も保護対象に含める。
3. 別の不変な候補地形へ差分を仮適用する。範囲・前値・周辺grade・占有・橋・水源・水路幾何・既存到達性・平場の接続を検証する。全ての地区の変更がない部分も保持する。
4. 地形イベント、次revision、植生への攪乱、判断記録、将来の投影に必要な値を一つのcommitとして準備する。いずれかが失敗すれば、地形差分は一切採用せず保留理由だけを残す。
5. Y年末の保存では次年の予約済みcommitを保持できる。Y年の画像は旧地形、Y+1年の経済・配置・観測は新地形とし、再開時にも一度だけ切り替える。10000年には将来作用の工事を作らない。

最初は工事を年単位の離散commitとして表現する。工事途中の数十年占有や返済・賃金を表現したとは扱わない。独立試走では追加の工事経済効果を入れず、本番採用前に機会費用の扱いを別途決める。D3の水路費用へ切り土の費用を紛れ込ませない。

改変を取り消したように見せて初期地形へ戻す操作は設けない。将来の新たな改変で形が変わる場合も、親revisionを持つ別イベントが必要になる。

## 6. 植生・放棄・景観

切り土の実変更セルに触れる植生パッチだけを、作用開始年に出典付きの攪乱として更新する。8×8pxパッチの既存モデル上の近似であることを記録し、周囲の森林までまとめて初期化しない。地面の断面と平場は新しいphysics・改変形状から描き、同年の根元と敷地に整合させる。初期地形の地表decalは実変更域でマスクし、古い斜面模様が新しい平場を上塗りしないようにする。改変前と範囲外の画素は旧rendererの契約を保つ。

整地後は `prepared`、実際の耕作が始まれば `cultivated`、利用が終われば `abandoned` として土地利用を区別する。整地だけなら既存の自然回復規則で草木が戻る。耕作終了後は利用蓄積に応じて回復するが、標高は元に戻さない。未耕作の平場を「放棄農地」と呼ばない。

遠景の山の輪郭、世界の大域気候、年内の雲・木・人の動きは地形改変の正本にしない。静止画・動く景観・植生抑制・歩行は同じ年のrevisionを参照する。過去観測と描画のために工事を進行・抽選してはならない。

## 7. 独立試走と保存・所有境界

D4-A/Bは本番と別の `terrain-change-review-v1` world／保存・rule・所有cacheを持つ案とする。通常session・v7 reader・ブラウザ保存・通常importは明示的に拒否する。外側の本番version 8や保存キーはまだ採用しない。C段階の保存設計で互換条件と併せて確定する。

入口は検証済みv7の確定年J、pendingなし、J<10000とする。origin全保存のhashと不変prefixを保持し、既存v7を編集してD4の所有rootに見せない。履歴はoriginを一度だけ保存し、その後を差分で持つ。全originを二重に埋め込んだり、容量確保のために古い文明・経済履歴を削ったりしない。

保存には初期地形hash、版、導入年、改変イベント、判断出典、親子revision、作用開始年、checkpoint、未作用commit、結合hashを含める。readerは深くdetachしてから検証し、外部の参照や浅いfreezeを信用しない。差分前値・局所physics・同年の占有／到達性・水理保護・植生と、既存経済の年次順序を再生して照合する。

読込・過去投影ではgenerator・候補探索・文明RNG next・writerを呼ばない。保存された合法性の根拠は検証するが、「その時の探索で最良だった」ことや全ての棄却候補の網羅性までreaderが証明したとは扱わない。hash再計算だけで意味検証を迂回できないことを人工改変で確認する。

## 8. 比較の作り方と受け入れ条件

基準は統合済みD3のv7。まず改変なしの共通view／runnerで、5世界の完全保存・RNG・景観を固定参照に一致させる。新旧の両方を同じ変更済みコードで生成しただけでは互換証明にしない。

その後、同じoriginから「D3のまま」と「切り土あり」を別々に進める。改変後の敷地や土地利用を基準枝へコピーせず、それぞれの実際の経済・選択・配置・水路を使う。新しい工事の直接収穫効果がなくても、後年の配置を介して歴史が変わり得る。文明・RNG・災害年の一致は強制せず、一致した項目も最初に違った項目も記録する。

自然seed 1／21／29／42／198を1万年、3地区、0／100／300／1000／2000／10000年と、各工事の承認・作用前後、最初の歴史差・都市到達前後で比較する。成立0件、保留、準備されたが耕作されない平場、成立しても見た目が小さい例を省かない。自然で成立しないときは、それを成功例として人工fixtureで置き換えず、候補条件を再検討する。

人工fixtureは、成功、平坦で変化なし、切下げ超過、水際、崖、現役・当年新設の占有、予約、橋詰、水路、既存入口の孤立、重複セル、前値不一致、未知親revision、未来checkpoint、pending／年上限、同年の競合を含める。人工入力は自然史・本番保存へ混ぜない。

必須確認：

- Y／Y+1、J／J+1、99／100境界、一括／1年刻み／分割／gzip再開、予約済みcommitの保存後再開が完全一致する。
- 改変前の全過去、旧v5/v6/v7の保存と将来計算・画素が維持される。導入済みの気候変更・renderer変更も元の版を保つ。
- 既存の建物・橋・水路・水源・到達可能な入口を壊さず、新しい平場への通路が合法である。対象外の地区・遠景を変更しない。
- 失敗・容量不足・非同期操作競合では現在のworldと旧保存キーを保持する。未知版とD4試走の通常importを拒否する。
- 改変前後の地面・占有・通路・植生・水源を切替表示でき、原寸／4倍、モバイル、静止／動画、Safari・BGMを確認する。

正式性能はseed42の2000／10000年、seed21の2000年を独立プロセス・1準備＋5回で測定する。年次と保存準備・hash・gzip込み全体は各5秒／25秒以下、D3同条件比2倍以下。改変なし共通化の年次は既存D3比1.10以下とする。比較のために既存B/C1/C2/C3の基準を緩めない。

完全保存はplain 16MiB／gzip保存用JSON 4MiB以内を目標にし、自然だけでなく最大4件・最大差分のfixtureで検査する。cold read・初回観測・素材準備と、常時描画p95≤83.3msは別計測する。PCとCPU4倍条件の生の5回値を残し、実機保証と呼ばない。容量・性能が超過すれば履歴削除や計測範囲の縮小で通さず、形式・投影・索引を見直す。

## 10. 本番化時の既存世界・経済の扱い

本番化を採用する場合でも、旧v7は元の規則で読込・保存・進行する。利用者の明示操作で確定年Jから導入し、J以前を保持する。新規世界の既定切替は最後のPRで比較資料と併せて行う。導入とブラウザ保存の成功を別に知らせ、操作途中の古い非同期結果を別世界へ採用しない。

工事費用はD4-C0の判断点である。独立試走の「費用なし」を無条件の本番採用とは扱わない。新しい費用を導入するなら、前年度の確定工事を翌年へ作用させる契約、既存v7への不作用、収穫と負担それぞれの比較が必要になる。地形変更による合法な農地増と、直接の収穫ボーナスを二重計上しない。

## 11. 河川・海岸改変を後続へ残す条件

川の付け替え等は別のD4拡張設計として、変更前後のstream／port対応、水面と水位、上下流の接続、旧水路の取水根拠、橋脚と橋詰、洪水／歩行、既存占有の退避・中止、地区間の地理的整合を一括で扱う。画面上の線を引き直すだけでは実装しない。

初期の切り土では水理を変えないため、この拡張を実装済みとも受け入れ済みとも数えない。D4の小規模改変を区切る時点で、拡張を#34に残すか独立issueへ分けるかを成果物とともに決める。本設計の統合だけでD4全体・#34をクローズしない。

## 13. D4-A1：改変なしの地形履歴view

`terrain-revision-v1.ts` は初期地形を既存の厳密境界で検証・凍結してからhashを作り、確定年を越えない読み取り専用viewを返す。地形の出典revisionとSHA-256による時間revisionを分ける。まだ改変イベントは空で、同じ初期physics・shape・水源を再利用する。観測は履歴を進めず、確定年の延長は別操作で行う。履歴・viewのコピーは所有済みとして受け付けない。

地面・建築探索・橋・水路・描画の型を、初期地形または所有する同年viewを受ける明示的な物理sourceへ拡張する。v1の初期地形validatorの契約や通常worldのterrainは変えない。景観への接続は専用のレビューadapterだけで行い、本番sessionへD4を導入しない。canonical hash処理はengine・producer・RNGから独立させる。

CIでは既存のv7固定参照・gzip再開の監査に続き、5世界・7年・3地区の105観測を比較する。専用ブラウザ検証は元の地形RGBA固定参照、12景観、同年の歩行・動く素材、観測前後のv7不変を確認する。切り土・自然候補・D4保存・本番採用はA2以降であり、A1の統合をD4完了とはしない。
