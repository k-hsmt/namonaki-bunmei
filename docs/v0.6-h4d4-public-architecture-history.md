# 名もなき文明 v0.6｜H4-D4 大型公共建築の履歴・敷地設計

**設計フェーズ／Humanレビュー前。** H4-D3（PR #25）の承認を受け、A「大きな会堂」・B「中庭型共同建築」を将来の本番に導入する条件を決める。C「土塁付き館」は外観方向だけ保持し、権力・維持制度の裏付けを別工程とする。**小規模城塞案は却下、城の導入は保留**（城壁が画面端まで続く・山地を変える景観スケールで将来再設計）。

このPRは**設計資料と実データ監査のみ**。建築の自然発生、セーブ・描画・施設台帳の本番コード変更は行わない。

## 1. 現行実装に基づく決定的な制約

| 現行箇所 | 実装の事実 | 大型公共建築への影響 |
|---|---|---|
| `settlement-history.ts` | 施設は11件の固定区画、`hall` は区画3・座標(197,121) | 都市に分類されただけで建物が増える設計は不可。大建築の合法区画を別途検証 |
| `Building` | `id,kind,x,y,builtYear,condition,reused?,recordId?` だけ | 建設時の形状・大規模敷地が固定されない。改修で姿を変える場合も明示イベントが要る |
| `store/siteAt` | `buildingChanges` から建設・損傷・修繕を過去再構成 | 新築時様式と敷地をイベントと一緒に固定し、巻戻し前に現れないこと |
| `existingGround` | 通常施設は18×7px、畑・橋は別矩形 | D3の大型屋根は土地正本に収まらない。**描画屋根の大きさで敷地衝突を代用しない** |
| `engine.ts` | 後発施設の `canBuild` は住宅とだけ衝突検査する | 新大型施設には**川・既存施設・住宅街区・未検証地形**を含む別ゲートが必要 |
| `society.ts` | `council` は寄り合いの慣習。君主・政庁・防衛の台帳なし | A/Bは共同性を根拠に検討。Cは館の権限を勝手に推測しない |
| `draw.ts` | hallの大きな屋根は実寸で約40px幅、物理区画は18px幅 | 視覚改善の採用と物理的な建設許可を分離する |
| v4旧データ | 建物の個別外観・大型敷地のフィールドなし | 旧セーブの建物を新築・改築済み扱いしない。既存外観は原則維持 |

## 2. A/Bの正式な位置付け：別個の王宮ではなく「共同施設の建築系譜」

**第一案：今の `kind:'hall'` を維持し、将来の新築だけ建築様式を確定する。**

- A `architectureStyle:'great-hall'`：大型会堂。高さのある屋根、公共的な大間口、静かな柱列。
- B `architectureStyle:'courtyard-hall'`：中庭型共同建築。屋根に囲まれた空地を中心に、人が集まる施設。
- 現在の `hall` は様式フィールド欠損時に **`legacy-hall`（現行の絵を継続）**。年・人口・都市分類から勝手にA/Bへ変形しない。
- A/Bは同一都市に両方存在する必要はない。同じ役割でも建設時の選択・敷地の条件次第で異なった姿になり得る。
- 新設施設のIDは既存 `river-bank-3` を流用しない。確定イベントIDから導出する一意ID、または予約済みの専用固定IDを使う。**IDの割当方式は実装前に一本化する**。
- 既存hallを改修する案は、別工程の明示的な `renovated` イベント・増築敷地・費用の確定ができるまで **HOLD**。建築様式の「上書き」だけでは不可。
- Cの館は `hall` の描画様式として安易に実装しない。公共性と支配権限の違いが確定してから施設種別を決める。

### 次の実装PRで追加する最小の正本候補（現段階では型の提案のみ）

```ts
type CivicStyle = 'great-hall' | 'courtyard-hall';
interface NewCivicConstruction {
  id: string;              // 旧施設と衝突しない固定ID
  kind: 'hall';
  architectureStyle: CivicStyle; // 新築時に固定
  footprint: {x:number;y:number;width:number;depth:number}; // 実占有
  builtYear: number;
  constructionRecordId: string; // 確定建設イベントへのリンク
}
```

`constructionRecordId` は変更され得る既存 `Building.recordId`（修繕等の最新イベントで上書きされる）と**別の不変な出典**。屋根の描画外接矩形はこの `footprint` とは分ける。将来の連続的な物理拡張は、追加の確定改修イベントなしに許さない。

**保存方針：** v4に任意フィールドを追加する案をまず検証し、既存の建物はフィールド無しのまま旧描画を維持。新形式だけ厳格にバリデーションする。整合不能ならスキーマ版を上げる判断を独立ゲートで行い、無断の暗黙マイグレーションはしない。

## 3. 物理敷地ゲート：今回の実測の意味

`tests/h4d4-public-building-site-audit.test.mjs` は seed42・自然進行958年の都市、河畔に実在する `hall` の座標を基準に、A/Bの**仮矩形**を検査する。

- A：44×22pxの仮敷地。B：56×30pxの仮敷地。寸法・位置は**未承認の設計仮説**であり、実際の建設予定地ではない。
- 既存hallを仮に除外して**置換したと仮定した場合のみ**、住宅街区・残りの施設・川との衝突を判定。除外自体が建物の撤去・改修を認める意味ではない。
- `isUnoccupiedGround`、`findHousingGroundConflicts`、実際の `housingAt` と `snapshotAt` を使い、判定の理由（`housingCollisionIds`、`terrainAndFacility`）を `artifacts/h4d4-site-audit/report.json` に保存。
- **`GEOMETRY_SCREEN_CLEAR_ONLY` でも建築許可ではない**。現行検査では道路・歴史的な土地権限・屋根と背景の視認性・生活空間の取り合いを保証できない。
- たとえ矩形が空いても `constructionResult=HOLD_NO_CONFIRMED_CONSTRUCTION_OR_RENOVATION` を維持。
- 実装時は新築の候補敷地を**別に**選定する。元のhallの建物ID・敷地を残したまま新施設との距離を判定する。元hallを勝手に消さない。
- 検査対象外の丘陵・入り江と、河畔で安全判定に不足する地形は **HOLD**。見栄えのための自動移設・川の埋立て・住宅撤去は許可しない。

### 3.1 実データ監査結果（seed42・958年）

CIの `H4-D4-SITE-AUDIT` と `artifacts/h4d4-site-audit/report.json` で確認：

- 河畔は自然進行の **都市（scale=3）**。集会所 `river-bank-3` は **24年建設・位置(197,121)・intact**。住宅街区7件、既存施設11件。
- **A（44×22px、矩形 x175,y103）：GEOMETRY_CONFLICT。** 住宅 `river-residential-00003`、`river-residential-00006` と衝突。
- **B（56×30px、矩形 x169,y99）：GEOMETRY_CONFLICT。** 同じ住宅2街区に加え、既存 `river-bank-2` 家屋とも衝突。
- いずれも元の `hall` の小さい物理敷地18×7から大幅に拡大する仮案であり、**現行の場所を拡張して採用することはできない**。この試算は元hallの撤去・改修を許可するものでもない。
- 検査時点と建築年が異なれば障害物の状態も変わり得る。**958年でのHOLDをすべての年代の永久不可能と同一視しない**一方、建物を歴史の途中で無断移設・消去することも認めない。

**次の設計課題：** 既存の集会所の改築ではなく、専用の合法な新設区画を探すことを第一候補にする。新設が無理なら「建てられない文明」も許容する。新しい公共建築が古い住宅を置換・区画整理するルールは今回導入せず、将来の独立した歴史イベント設計に分離する。

## 4. 建設の理由：人口だけで建てない

正式な自然進行実装に先立って、条件を検証する。

- **必要性：** `hall` や他の既存施設が実在し、集会の利用・共同維持を続ける必要がある。単に `scale===3` は不可。
- **継続性：** `council` 慣習や関係する確定記録など、共同体として運用する履歴上の裏付けを要求する。現存の `council` が無い文明に暗黙付与しない。
- **維持能力：** 食糧の安定、施設を維持する余力と、一定期間続く条件。期間・数値は今後のシミュレーション監査で決める。根拠なしに閾値を固定しない。
- **土地：** 候補の敷地が空いていることを確認し、後発住宅・施設の建設も同じ占有ゲートに従わせる。
- **独立性：** 必要条件が欠ければHOLD。都市の見栄えを優先してイベントを発行しない。建てない都市や町にも独自の歴史がある。
- **建設時点：** `constructionRecordId` が確定してからその年の履歴を追加する。出来事だけ／建物だけが残る中途半端な更新を禁止。

## 5. 画面に現れるまでの系譜

```
確定済み共同慣習・資源の継続
  → 新築・土地占有の候補ゲート（HOLD理由を残す）
  → 施設建設イベント（ID, year, style, footprint, constructionRecordId）
  → buildingChanges / siteAt / snapshotAt
  → composeScene の施設投影
  → drawScene（確定様式・固定描画）
  → 保存・読込・過去巻戻しの画素一致
```

- `hall` が傷んでも姿は連続する。廃墟化・修繕・再利用で同じ建設年・敷地・建築様式を保持。
- 既存 `hall` の年別レコード、H3の住宅履歴、街路・前庭の地面表現と建物表示の整合性を確認。
- `snapshotAt` が含めるのはその年に実在した施設だけ。旧セーブの未記録部分に新施設を遡及生成しない。

## 6. 実装の次の最小PR（提案・まだ開始しない）

**H4-D4-A：正本と敷地ゲートのみ。** 新築様式・実占有の保存と検査を追加するが、**自然建設は無効**。旧セーブを壊さず、既存hallの描画は維持。合法・違法候補の単体テストと保存／過去再生の回帰を要求。

**H4-D4-B：歴史に基づく建設候補。** 利用と維持能力の根拠、建設イベントとのリンク、HOLD理由を組み込む。自然進行への接続は別Humanレビューを通した場合のみ。

**H4-D4-C：施設の描画と現実の都市評価。** A/Bの原寸320×180比較、屋根密度・中庭の余白・施設の遮蔽・住宅と河川の占有を検査。seed7/42/82の1,000〜2,000年の自然履歴を確認。城・館は含まない。

## 7. Humanレビューのゲート

1. A/Bを**新設時のhall系譜**として扱い、既存hallの無断改修はしない方式でよいか。
2. 新しい施設IDと `constructionRecordId` を建設時に固定する方針でよいか。
3. A/Bの物理敷地を別途確定し、衝突時は原則HOLDでよいか。
4. 合法敷地が十分見つからない場合は、美観優先の無断移設ではなく配置計画の再設計へ戻ることを認めるか。
5. 城は地形・背景を変える大規模景観の別工程として保留し、Cの館も権力・維持の歴史モデルができるまで自然建設をしない。
