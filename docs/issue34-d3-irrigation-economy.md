# Issue 34 D3-C：灌漑の収穫と工事負担の比較設計

PR #78の景観をユーザーが受け入れ、main `bf4c6af`へ統合した。D3-Bは完了。本書はD3-Cの最初の設計（C0）で、収穫への作用と工事・維持の負担を独立比較し、本番採用・修正・延期を判断する手順を定める。v6の進行・保存・新規既定は、この文書の統合では変更しない。

## 1. 既存の計算と今回の問い

`src/story/engine.ts` の `step` は短期降雨・人口・食料指標・出来事・選択を進める。水路管理の伝承 `waterworks` はすでに食料変動・収容力へ作用し、灌漑の出来事や選択にも食料指標への効果がある。

その後、確定年の `finishYear` が `src/story/regional-economy.ts` の `updateRegionalEconomy` を呼び、地域別の収穫・需要・備蓄・交易・食糧不足・移住を計算する。施設・住宅等の確定とD3-Bの水路・環境積算はさらに後になる。現在の地域別収穫は概ね次の形で、画面の畑面積と実際の農地面積の換算はない。

`harvest = floor(min(地域人口, 地域の土地上限) × 地域の基礎収量 × 当年のharvestFactor)`

今回の問いは「位置を持つ水路が実際に稼働している場合の追加効果と負担を、地域別収穫に限定して加える価値があるか」。既存の伝承・灌漑イベントの効果を全て新たな水路の成果と数えず、同じ基準に対する追加分だけを比較する。`state.food` に別のボーナスを重ねたり、pxをヘクタール・人数へ直結させたりしない。

## 2. 最初は固定した歴史の単年比較（C1）

最初の実装は、**D3-Bの同じ確定入力に対する単年の地域経済比較**とする。無作用・収穫増のみ・負担のみ・両方の4条件を同じ年・同じ入力で計算する。

| 条件 | 収穫の追加分 | 工事・維持による機会費用 | 役割 |
| --- | --- | --- | --- |
| baseline | 0 | 0 | Bの地域経済を完全再現 |
| yield-only | あり | 0 | 供水の追加分を分離 |
| cost-only | 0 | あり | 無償の工事というBの仮定を分離 |
| combined | あり | あり | 差引の効果を確認 |

各条件はその年のBの開始時点の経済・人口を複製して計算し、次の年はまたBの入力へ戻す。条件ごとの備蓄や移住を翌年へ持ち越さない。年間収穫差を合計することはできるが、備蓄差の単純合計を「蓄積した富」と呼ばず、人口・都市到達年の長期差も主張しない。4つの自然史や、完全な将来予測として表示しない。

将来の人口・選択・災害まで変える比較はC2で別に行う。C1だけで採用が妥当と判断できなければ、値の修正または経済接続の延期を選べる。効果が小さいという結果を、本番の定数を大きくする理由にしない。

### 2.1 正確な入力を採取する場所

既存v6の最終保存には、地域経済の全ての年の**計算直前**の入力が入っているわけではない。観測の年末人口にはすでにその年の移住が反映され、経済のcoverageは直近5件、交易履歴は20件のみ。現在の干ばつ値から昔の収穫条件を補完しない。

C1のproducerは新しいBの試走を進めながら、`finishYear`の地域経済の直前・直後を読み取り専用の観測hookで採取する。直前の人口配列（未所在人口を含む）、地域経済、harvestFactorの根拠となる短期干ばつ値、遮断・穀物庫条件、直後の経済と人口、発行された地域記録のIDを捕捉する。

hookへ渡す値は所有する複製を深く凍結し、戻り値を年次処理へ反映しない。hookの有無で文明state・RNG・施設・住宅・水路・環境・完全なv6保存が一致することを先に検証する。選択待ちの年は採取せず、選択確定後の`finishYear`で一度だけ採取する。過去の保存を読むだけでこのhookを動かしたり、入力を新たに抽選したりしない。

通常のv6起動・観測・保存にはhookを設定しない。最初の自然比較はseed 1／21／29／42／198の新規世界から10000年まで、同じBの自動選択で採取する。既存世界を起点にする場合は確定年Jから先だけを採取し、それ以前の不明な入力を捏造しない。

## 3. 一年遅れの作用と導入境界

C1の効果年をYとすると、供水・畑・土地・植生・水路イベントは、すべて**確定したY−1年**を参照する。Y年の地域経済入力だけをY年のhookから得る。この順序なら、まだ建築も水路も確定していないY年の結果を、同じ年の収穫へ先取りしない。

- 575年に建設した水路は、576年の収穫と工事負担から作用する。
- 615年に破損した場合は、616年から追加収穫と日常管理の対象外となる。
- 同じ年に建設して埋め戻された場合は翌年の供水利益は0で、実際の各工事の負担だけを数える。
- 作用導入年J以前の工事費は遡及しない。新たなイベント費用は原因年がJより後のものだけを対象にし、稼働利益と日常管理はY=J+1から既存の系統も対象にできる。

これは「前年度の供水・生産基盤が翌年度に寄与する」という試走の仮定で、当年の破損と経済効果の消失には一年のずれがある。即時の作用を採用する場合は、単に係数を変えず年内順序から再設計する。C1のグラフには原因年と作用年を両方表示する。

## 4. 試走用の追加収穫

追加収穫は川辺の、前年に稼働中で畑がintactだった系統だけに与える。丘陵・入り江・未導入・対象畑なし・休止・破損・放棄・埋戻し後は0。

1. D3-Bの配水と同じ安定陸地・水頭・4近傍接続・他敷地の除外を使い、対象畑の内部で実際につながるセル数Uと、安定陸地セル数Nを得る。水路自体や畑の周囲2pxを収穫面積に含めない。
2. 畑内の各安定セルが属するpatchの水分を、局所の追加加湿を入れない同じ前年stateから `moistureAt(humidity, waterBuffers[patch], soil)` で求め、その面積加重平均をMとする。水分・土壌の単位は既存モデルの指数で、降水量ではない。過去に灌漑が与えた土壌の効果も入ったstateなので、これを「灌漑が一度もなかった世界」とは呼ばない。
3. `dryNeed = clamp(−M / 40, 0, 1)`、`fieldShare = 1 / max(1, 川辺の前年のintactな畑数)`とする。
4. `gainBp = floor(100 × (U/N) × dryNeed × fieldShare)`。N=0や不明な水分では利益0と理由を記録する。bpは10000分の1で、地域の収穫に対する最大追加分は1%。

1区画を地域全体の農地だとみなさず、畑の等価な持分で按分したうえで最大1%に制限する。畑数と面積の換算は便宜的な仮定で、実測の収量ではない。

wetセルの抽出をBの効果計算と共有する場合は、純粋な読み取りhelperを切り出す。Bのpatchへの水分換算・建設・寿命・経路順序を変更せず、A2の完全保存基準とA3/Bの全値一致を保持する。既存の最大水分24を、そのまま24%の収穫増へ読み替えない。

## 5. 試走用の工事・維持負担

初回の負担は、収穫から一部の労力を振り向けたという**生産の機会費用**として同じharvestFactorへ反映する。実際に支払った食料・通貨、人員の人数、労働者が確保できるかを表すモデルではない。`reserve`から別途引いたり、食料指標を重ねて下げたりしない。

前年の経路長をL（最大64）として、各原因付きイベントを一度だけ数える。

| 負担 | 試走の基準値 | 対象 |
| --- | --- | --- |
| 建設 | `ceil(200 × L/64)` bp | built |
| 点検 | `ceil(50 × L/64)` bp | maintained |
| 修復 | `ceil(100 × L/64)` bp | repaired |
| 埋戻し | `ceil(50 × L/64)` bp | backfilled（時計・後発建築の双方） |
| 日常管理 | `ceil(5 × L/64)` bp／年 | 前年activeまたはidle |

休止・再開・破損・放棄という状態変化そのものには、新しい工事費を作らない。日常管理は大きな点検の代用ではなく、Bの40／80／20年の時計を延長しない。damaged／abandoned／retiredには日常管理を課さない。したがってidleでは収穫増0・日常管理のみになる。

`requestedCostBp`は各費用の合計、`costBp = min(300, requestedCostBp)`とし、初回は地域収穫の最大3%までの機会費用を比較する。上限で切られた量も必ず別に記録する。これは支払えなかった債務を帳消しにする仕組みではなく、初回近似の適用限界である。自然試走で上限超過が出る場合は、この案をそのまま本番採用せず、負担モデルを修正する。

人口・生産が0の地域では収穫差も0で、労働力の調達や未払いを解決したとは扱わない。そのような年の工事は独立に件数を示し、実際の工事可否や債務を扱う本番採用案が必要ならC2の要件に加える。

## 6. 地域経済への渡し方

各条件は既存の当年係数Fから次を計算し、既存の収穫のfloorを一度だけ適用する。

`F' = F × (1 + (gainBp − costBp) / 10000)`

対象外の2地区はFをそのまま使う。係数以外の入力、交易の上限・遮断・需要・穀物庫条件・地域の並びは4条件で同じにする。基準の伝承、全体の食料指標、乱数、災害、選択は変更しない。

例：L=64、畑1区画、全域に接続、dryNeed=1ならgainは100bp。建設の翌年は200bp＋日常管理5bpで、combinedの純係数は−105bp。その後の通常の稼働年は＋95bp。湿潤でdryNeed=0なら日常管理だけが残る。利益と負担の双方を確認できるが、この例を自然世界の結果として掲載しない。

C1の地域経済のrecord callbackは文明の`entry`を呼ばない。baselineは採取した同じID列で記録を再現し、経済state・人口配列・記録がBと完全一致することを確認する。他条件で新たに必要になる記録は明示したreview専用IDとし、本番の年代記・施設原因へ混入させない。

## 7. 保存・読込・比較資料

C1は `irrigation-economy-review-v1 / schemaVersion: 1 / status: review-only` の独立形式にする。元のB世界は1つだけ格納し、出典ハッシュ、導入年、試走ruleと全定数、採取した年次入力、4条件の計算結果を結び付ける。本番v6のreader・保存先・rendererの許可リストへは追加しない。

年次入力は人口配列・干ばつ値・条件flags・発行記録の参照等をcompactなtupleとして保存し、毎年4つの全世界や地域経済全体を複製しない。初期の地域経済からbaselineを再生すれば次年のBの開始経済を得られるため、各年のreserveやcoverage配列を全て重複保存する必要はない。必要なcheckpointは100年ごととcurrentに限定し、浮動小数の備蓄・coverageを勝手に丸めない。JSON16MiB／gzip目安4MiBを監査し、超過を隠すために履歴を削らない。

readerは元のv6を検証し、年・地点・導入境界・幾何と原因参照、入力の範囲、baselineの再生、4条件の整数係数と地域経済の計算結果・checkpointを照合する。新しい地形・水路探索・気候目標・選択の生成は不要。出典ハッシュは取り違えの検出であり、採取記録の全ての文明抽選過程を署名で認証するものではない。

`artifacts/environment34-irrigation-economy/` に次を出す。

- 自然5世界を除外せず、成立／不成立、状態別年数、供水率、乾燥度、各費用、丸めで差が0になる年、上限超過・人口0の工事を集計。
- 4条件の年別の収穫・費用による減少・差引、備蓄・供給率・交易・その年だけの移住の潜在差。増産が備蓄上限で捨てられる場合も示す。
- 効果0の期間を含む1万年全体、稼働期間だけ、工事の翌年、乾燥／湿潤の期間を併記。差が見える年だけに絞らない。
- 合法な取水なし、配水率0／一部／全域、湿潤、破損・修復・休止・復旧・後発埋戻し、JとJ+1、0人口、複数作業と上限の人工fixture。自然の歴史とは区別する。
- 元のBの風景には作用範囲と原因年／効果年を注記できるが、C1で建物や人口が変化した新しい景観は描かない。

## 8. C2で双方向の歴史を比較する場合

C1を見て社会計算への作用を進める場合のみ、C2の独立した年次runnerを実装する。前年度の確定水路から当年の係数を作り、`finishYear`の地域経済に渡し、当年の社会・建築を確定した後、水路と環境をその年まで積算する。翌年はその結果を使う。今のBのように文明を複数年進めてから環境を一括積算する方式へ、係数だけ後付けしない。

食料事情の差が交易・移住・社会・敷地・水路の成立へ戻るため、Bの未来の水路台帳や建築をC2へ固定しない。Bと同じ種・初期状態から開始しても、eligibleな出来事・選択の出現・乱数の消費回数が変わり、災害年もずれる可能性がある。「追加の乱数呼出し0」と「乱数列・災害年の完全一致」は別の性質として報告する。

初回の共通選択は、両方に同じ分岐がある場合だけ、保存した決定IDと選択肢IDで適用する。片方にしかない分岐を同じ年へ押し込まない。C1の固定入力による差と、C2の自然に分岐した歴史差を別の図にする。最初の経済差・年代記差・選択差・RNG差を原因と年付きで記録する。

C2には専用の試走world識別子と保存契約を設け、内部の文明stateを通常のv6世界やWorldSessionとして公開しない。年次hook・選択待ち・読込の検証範囲、旧v6の将来進行を保持する本番の経済policy版は、C2の実装前に具体化する。独立比較での検証と採用判断なしに、経済を変更した世界をv6として書き出さない。

## 9. 実装順序と完了条件

1. **C0（本書）**：単年比較、入力採取、一年遅れ、試走定数、保存と比較範囲を定める。本番の採用判断やC全体の完了ではない。
2. **C1**：読み取り専用hookと4条件の独立比較を実装。Bの完全保存・RNG・選択と災害・景観がhookの有無で一致し、baselineの全年度の地域経済と人口が一致する。単年計算、境界、改変拒否、分割・保存再開、自然5世界×1万年、容量・性能と利益／負担の双方を検証して結果を提出する。
3. **判断**：利益がほぼ0・既存効果との重複・仮定の弱さ・負担上限・性能等も含め、C2へ進む／値を修正してC1を再比較／経済接続を延期、を明記する。常に利益が出るように調整しない。
4. **C2へ進む場合**：専用runnerと保存契約の設計、双方向試走、歴史差と互換性の検証を経て採用を判断する。新規既定や旧世界の明示導入の本番実装は、その判断後の作業とする。

C1の性能は、採取を含むBの年次計算と、4条件・保存準備を含む総時間を分け、1回warm-up＋5回中央値を出す。seed 42の2000／10000年・seed 21の2000年を用い、採取による年次時間はB比1.10倍以内、全体は2000年5秒／10000年25秒・同等範囲のB比2倍以内を初期目標とする。採取前後の生の値と全5回を残し、基準を超えたら処理を見直す。4条件の単年計算を動画のFPSとは呼ばない。

本番採用を延期する判断もD3-Cの結果になり得るが、未実装の食料・人口への作用はそのまま記録して後続へ残す。D3の区切りとD4へ進む判断は、Cの比較と採用／延期の記録を揃えて行う。Issue #34全体を設計PRだけで閉じない。

## C1実装記録

地域経済の観測hookを `src/story/economy-observer.ts` に定義し、生成世界の明示した試走オプションにだけ接続した。確定年の計算前後・条件・記録・収穫／輸入／交易／上限超過分を所有する複製で渡し、入れ子の値まで読み取り専用にする。通常UIの呼出しは変更しない。地域経済の計算式とD3-Bのwetセルを読み取りhelperとして共有し、元の結果の完全一致を検証する。

`src/irrigation/economy-*-v1.ts` にproducer・整数係数・reader・独立保存を実装した。元のB世界は1つ、年次入力は人口4要素・干ばつ・遮断／穀物庫flags・災害と経済記録の参照のtupleとする。4条件の年間出力は読取時に再計算できるため毎年の全世界や全経済stateを保存せず、100年checkpointとcurrentにbaselineと累積の収穫差だけを記録する。備蓄差を累積資産として保存しない。

元世界ハッシュに加え、導入年・初期経済・入力tupleの結合ハッシュを検証する。これは事故や取り違えを検出する整合性検査で、再ハッシュ可能な署名なしの資料から全ての文明抽選の真正性を証明するものではない。基準の記録本文・年・人口・洪水と穀物庫の出典、全年度の地域経済と保存済み集計を再生して照合し、過去の人口・経済を現在値で補完しない。読込にproducer・観測hook・新しい探索や気候生成は不要で、本番キーには書かない。

`benchmark-irrigation-economy.mjs` は採取前後の年次と4条件込みの全体を1回warm-up＋5回で計測する。`audit-irrigation-economy.mjs` は自然5世界×1万年、完全なB保存・baseline・gzipと9900年からの再開、容量と全年度を検証する。`review-irrigation-economy.mjs` は同じ歴史に対する食糧量そのものと単年差の対話的な図、全期間集計、12件の人工fixtureを出す。`check-irrigation-economy-page.mjs` で実際のChrome描画と操作を検証する。C1は景観や長期人口を変えた試走ではない。

出力先は本書の `artifacts/environment34-irrigation-economy/`。正式な数値・最新CIと、C2へ進む／修正／延期の推奨は実装PRとIssueに記載する。本実装だけで経済作用の本番採用やD3全体の完了とはしない。
