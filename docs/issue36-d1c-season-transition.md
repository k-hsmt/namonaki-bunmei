# Issue #36 D1c｜年が進むときの季節の切り替え（Humanレビュー用）

- 設計：[issue36-season-design.md](issue36-season-design.md) §7（D0）。D1a・D1b：[issue36-d1a-season-gallery.md](issue36-d1a-season-gallery.md)
- 状態：**試作。本編には接続しない**（年次同期・動画・設定への接続はD3）。
- 生成：`npm run build && node scripts/preview-season-d1c.mjs` → `artifacts/season36-d1c/`（report.json・動画36本、約8分）

## 1. 試作の方法

- **年の並び**：温帯林（seed 6）と亜寒帯林（seed 18）を、本編と同じ進め方（`advanceWorldSessionAsync`：1回で次の記録まで最大36年。選択待ちは自動選択と同じくランダムに選ぶ）で進めた確定年の並び（各120年分）。季節の位相（年 mod 4）は進むたびに不規則に変わる。
- **再生**：各年を4位相すべてで事前に描き（最終世界の過去観測。本編の表示と同じ）、各速度で8秒間、実時間で再生して録画した。実際の描画は1年あたり中央値94〜107ms（最大171〜212ms）かかるので、とても速い（75ms）では本編はもともと毎回描けない。
- **遷移**：新しい年の建物・地形・植物のまま、**前に表示していた位相の絵から新しい位相の絵へ**重ね合わせる。前の年の画面とは重ねない（消えた建物が残る等の捏造をしない：D0 §7）。年の内容（建物・植物の成長）は即座に新しい年になる。
- **間引き**：速い・とても速いで、画面の更新を700ms／1400msに1回にし、最新の確定年だけを表示する。溜めない。停止時は最後の確定年を即座に表示する。
- **明滅の指標**：80×45に縮小した画面の明るさ（0〜255）の、フレーム間の差の平均。0.5を超えたフレームを「切り替わり」と数える。

## 3. 読み取れること（事実）

- 季節がそのまま切り替わると、1回の明るさの変化は最大40前後（雪や紅葉の有無）。遷移を入れると1フレームあたりの最大は2〜6に下がる。
- 間引きは切り替わりの**回数**を減らすが、1回の**強さ**は下がらない（亜寒帯林では平均19〜21のまま）。
- 間引き＋遷移では、強さも下がる。ただし亜寒帯林で最大13〜22が残る。間引いた間に何年も進むため、年の内容（植物の成長・建物）がまとめて変わるため（遷移は季節だけを滑らかにする）。
- 「とても速い」の現状（毎回描き直す）は、明滅の合計が他の10倍以上。

## 4. Humanレビューで決めてほしいこと

1. 通常速度（ゆっくり・ふつう）の遷移の長さ：なし／150／250／350ms。
2. 速い・とても速いの扱い：間引きの間隔（700／1400ms）と、遷移を併用するか。
3. 停止直後に最後の確定年をすぐ表示する動き（各動画の最後）。

## 5. Humanレビュー結果と25年周期の試し（2026-11-13）

**レビュー結果**：遷移はあった方がよい。速い・とても速いは1400msごとの更新に遷移を併用する。停止直後に最後の確定年をすぐ表示する動きはよい。

**周期の見直し（D0 §2の変更候補）**：毎年の季節の切り替え（年 mod 4）は慌ただしい、との指摘。本編の1回の進行は平均4〜5年（中央値3年）で、毎年切り替えると約9割の進行で季節が変わる。候補を比べた結果、**B案：季節1つを25年（100年で四季が一巡）を試す**ことになった。

- `SEASON_PHASE_YEARS=25`、位相 = floor(確定年 / 25) mod 4（試行値。D0の時間の決め方は、試行の結果を見て書き換える）。
- 録画は16秒。方式はレビューで決まったもの（ゆっくり・ふつう：遷移250ms、速い・とても速い：1400msごとに更新＋遷移350ms）と、比較用の遷移なし／毎回描き直す。

| 1秒あたりの明滅の合計 | 毎年切り替え（前回、8秒） | 25年ごと（今回、16秒） |
|---|---|---|
| ふつう・遷移なし（温帯林／亜寒帯林） | 11.2／15.3 | 0.2／5.2 |
| ふつう・遷移250ms | 10.2／15.5 | 0／5.0 |
| とても速い・毎回描き直す | 209／274 | 44／38 |
| とても速い・1400ms＋遷移350ms | ― | 13.4／11.9 |

とても速いの1400ms＋遷移では、最大値28〜31が残る。1.4秒の間に約90年進み、植物の成長や建物がまとめて変わるため（遷移は季節の見た目だけを滑らかにする）。

**検討で挙がった懸念（未解決）**：季節が長く続くと、#34の長期気候（100年ごとの乾湿・寒暖）と見分けにくくなる可能性がある。25年なら1つの季節は#34の区切りより短い。

**決定（2026-11-13）**：25年で進める。D0 §2を書き換えた（`SEASON_PHASE_YEARS=25` は試行値から確定値へ）。
