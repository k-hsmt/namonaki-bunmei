# 名もなき文明 v0.6｜H4-D4-A 大型公共建築の正本と土地占有ゲート

**状態：Draft / Humanレビュー待ち。** H4-D4（PR #26）の設計を、自然建設を有効化せずに実装する。

## 何ができるようになったか

既存の施設種別 `kind:'hall'` に、**新築時にだけ固定される** `civic` 情報を任意で持たせられる。

```ts
civic?: {
  architectureStyle: 'great-hall' | 'courtyard-hall';
  footprint: { x:number; y:number; width:number; depth:number };
  constructionRecordId: string;
}
```

- A 大きな会堂とB 中庭型共同建築を識別する。城・館の建設様式は未対応。
- `footprint` は実際の地表占有（屋根の描画領域ではない）。`existingGround()` が新築の拡張敷地を返すため、将来の住宅の衝突検査でも施設が占有した土地を避けられる。
- 旧施設の `civic` がない場合は現行の18×7pxなどの敷地／現行の描画のまま。見た目を分類・人口から推測して改修しない。
- `constructionRecordId` は施設の修繕 `recordId` に上書きされない、**建設時の不変な出典**。施設IDは新規 `civic-...` とし、旧hallのIDを流用しない。

## 明示的な新築への経路（自然進行へは未接続）

1. `reviewCivicConstruction` は既存の確定施設・住宅街区・川を検査。河畔以外は必ず `unsupported-terrain` でHOLD。
2. 同関数は**新築イベントの存在**（同じID・年・`kind:'building-built'`）も検査。未確定・重複ID・既存の施設/住宅・河川衝突は理由付きでHOLD。
3. `appendConfirmedCivicConstruction` は**既に確定された建設イベントを受け取った場合だけ**、新規hallを `buildingChanges` と現在の `site.view.buildings` へ純粋に追記する。入力を変更しない、過去年への追記を拒否する。
4. この関数は`engine.ts`から呼ばれておらず、**ゲームの自然進行では一件も新築しない**。共同体の慣習・維持の成立条件は後続H4-D4-Bの審査対象。

`clear` は**土地と出典に関する技術的な通過**にすぎない。史実を追加してよいというHumanの一括承認ではない。実装の接続先と確定イベント発行は後続レビューに残す。

## 保存・時間旅行の保護

- `siteAt()` は新フィールドを保持して履歴を再構築し、`civic.footprint` を深くコピーして外部の書換えから保護。
- `snapshotAt()` は確定済み `civic` を施設と一緒に引き渡す。ただし `drawScene` の新しい大型建築用の描き方は未実装。
- `validateHousingSave()` で、**新しいcivicフィールドが存在する場合のみ**様式・敷地範囲・施設kind・新規ID・建設年・原イベント・履歴の不変属性を検査。不正なものは保存前と読込時に拒否。
- 既存v4の`civic`欠損を「大型建築済み」として補完しない。v2/v3の移行ルールも変更しない。
- 既存の`hall`の`recordId`は修繕時に更新されるが、新築の`constructionRecordId`は別。合法な将来の修繕でも敷地・様式・建設年を変更させない。

- A/Bだけを受理し、城・不正な様式/範囲/新築の出典を拒否。
- 河畔の川、廃墟を含む住宅、既存家屋、既存集会所を侵さない。
- 丘陵・入り江をHOLD。重複ID、記録のない新設、過去への後付けもHOLD。
- 明示新築では、同一ID・建設年・敷地・様式を維持し、旧施設と過去の観測を変更しない。
- 新築を明示的に含めたv4保存のJSON往復と、様式・敷地・原イベント・既存施設記録の改ざん拒否。
- 新機能を持たない旧v4セーブの往復は元の結果を維持。
- 既存のブラウザ回帰とH3 2,000/10,000年長期監査も継続。
