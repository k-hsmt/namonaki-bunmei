## 1. 観測体験と非目的

- 「風景に見える遺構を調べる → 確定した建設・状態履歴・年代記を読む → その年の風景を観測 → 風景同士を比べる」をひとつながりの操作にする。
- 対象が「なぜ」変わったかは確定したcause ID・年代記が**直接対応**する場合だけ示す。人口減少と廃墟の同時期発生を因果として自動説明しない。
- 320×180pxの**風景そのもの**を主役にする。通常モードでクリック可能マーク・名前・輪郭を常時重ねず、調査パネルはCanvas外に置く。
- 新しい「発掘」「遺物発見」「文化財指定」「隠れた水路の再発見」「住民の記憶」などの**文明史イベントは追加しない**。「記録を読む」はプレイヤーのUI操作に過ぎない。
- #29の5指標や歴史グラフを再実装しない。既存の過去観測入口を再利用する。
- #37の自然回帰を見やすくするために植物を間引く／ずらす、廃墟を前景に再描画する、地面に未確定の遺構を描くことは禁止。

## 2. 現行コードに存在する正本と境界

| 観測対象 | 確定情報の入口 | 読取時の制約 |

| 住宅街区 | `src/story/housing-history.ts`の`HousingHistory.events`、`housingAt()`、`residentialBlocks` | 屋根の`partId`は**描画単位**であり一戸の家ではない。履歴は`blockId`で束ねる。`status:unknown/partial`は無記録を「存在しない」と断言しない |
| 廃墟 | 元の施設／街区ID、`src/ruin/ruin-history-v1.ts`、#37の風化・回帰投影 | 廃墟に新しい別IDを振らない。放棄年と廃墟化年を混同せず、残存物と風化は確定史から描画 |
| 橋 | `src/story/generated-bridge-history-review.ts`の`bridgeId`・`builtYear`・`sourceRecordId`、`buildingChanges` | 橋桁の形状とその年の損傷／修復を区別。壊れた橋を通行可能と表現しない |

## 3. D0対象範囲と「存在」の語彙

本Issueの初版は**5系統**（施設、住宅街区、廃墟、橋、水路）を対象とする。廃墟は元の施設／街区の**状態**であり、独立した所有者やIDではない。

**観測年yに対して区別する状態**：
1. `visible`：yに存在し、実描画の**一部が視認可能**で、識別可能な対象IDを持つ。
2. `recorded-hidden`：yに対象・状態の確定記録はあるが、完全な植物遮蔽・描画上の不可視・埋戻し等によって**現在の風景から選べない**。記録の一覧でのみアクセス可能。
3. `not-yet-built`：建設がyより後であることが**確定**している（比較など明示的な前後の文脈で利用）。
4. `unknown`：歴史の導入前など、対象の存在／起点を断定する情報がない。
5. `unsupported`：保存されている情報を対象の可視形状・個体IDに安全に対応づけられない。

`recorded-hidden`は必ずしも物理的に残存することを意味しない。とくに**埋戻し水路**は「かつて存在した記録」であって、地表に見える構造物・確定した遺構があることと同義ではない。これを「発見された遺跡」と名づけない。

初期の対象外：個々の樹木の同一個体・樹齢、抽象的な景観描画だけの道、履歴IDのない地面の模様、イベントと結び付かない架空の古木・石積み、未記録の旧文明の復元。将来、バイオーム／土地の変遷を扱うなら、個体史と群落史を別Issueで設計する。

## 4. 履歴対象の正規化：既存の保存正本を変えない

実装候補の**UI専用**の参照型：

```ts
type HistoricalTargetRef =
  | { readonly kind: 'facility'; readonly id: string }
  | { readonly kind: 'housing-block'; readonly blockId: string }
  | { readonly kind: 'bridge'; readonly id: string }
  | { readonly kind: 'waterway'; readonly systemId: string };

interface HistoricalSubject {
  readonly ref: HistoricalTargetRef;
  readonly siteId: 'river-bank' | 'hill-side' | 'coast-inlet';
  readonly observedYear: number;
  readonly visibility: 'visible'|'recorded-hidden'|'not-yet-built'|'unknown'|'unsupported';
  readonly title: string;
  readonly currentCondition: string | null;
  readonly history: readonly HistoricalChange[];
}
interface HistoricalChange {
  readonly year: number;
  readonly sourceKind: 'housing-event'|'building-change'|'bridge-record'|'waterway-event';
  readonly sourceId: string;
  readonly label: string;
  readonly linkedChronicleId?: string;
}
```

これは**概念的な出力**であり、`currentCondition`の厳密な判別型や`sourceId`を構成するキー、別建築世代の参照はD1実装時に各正本の実型へ合わせる。新しい`save.schemaVersion`、新規年次イベント、乱数・`state`更新を導入しない。

- 同じ`facility.id`に複数の建築出生がある場合は「**施設の系譜**」と「**その年に描かれる建築世代**」を分ける。建て直した建物を建設以来同じ物理建築と記載しない。
- `HousingHistory.events`は`(year,seq)`順、`after`をその年の確定状態として読む。`causeRecordId`がある場合のみ既存年代記へのリンクを検証して表示。
- 施設の`buildingChanges`は各確定状態を読めるが、イベントIDがすべての変更に付くと仮定しない。`buildingId`、`recordId`などと**実際に一致**する記録だけ年代記へリンクする。
- 橋は`sourceRecordId`と確定した状態記録を照合。橋の出生がない／ID不一致は対象から除外するか不整合として扱い、近傍の橋へ接続しない。
- 水路は`systemId`、`ChannelEvent.id/year/seq/kind`を参照。`ChannelCause`には年代記のほか土地利用・方針時計等があり、**すべてを年代記と呼ばない**。`backfilled`後は現在の見える水路とみなさない。
- **時点yの普通の履歴パネル**には`year<=y`の確定変化だけを表示する。`y`より後の出来事を「この年の歴史」として列挙しない。明示的な二時点比較は別の文脈で扱う。
- 同一年に複数変更がある場合は正本の`seq`・確定した順序を使用。同一年に状態が複数回変わったと推測しない。
- 現在の保存内の歴史を**読む**だけ。インデックスを作る場合は観測UI側の一時キャッシュとし、現行の保存値・履歴に書き戻さない。

## 5. 「調べるモード」：二つの入口（Human決定B＋B）

### 5.1 通常の観測
- 初期OFF。Canvasに対象ID・枠線・ピン・ラベル・輪郭を常設しない。#29のバー・グラフ・既存年代記の操作は従来どおり。
- 「調べる」を押すとON。OFFに戻すと選択マスク／候補／調査パネルを閉じ、風景は通常の描画へ戻る。
- 調査操作は**読み取り専用**。調べるモードのON/OFFだけで文明の進行速度やRNGを変更しない。履歴年への**明示的な移動**では#29と同様、自動進行を停止する。

### 5.2 風景から発見する
- **現在表示されている観測年・地区の実際の可視画素**から対象を選択。選べる対象は確定したIDとその時点の描画形状を照合できるもののみ。
- ON時、ポインタ・フォーカス・選択対象だけを控えめに強調。全施設を派手な枠で常時マーキングしない。タッチで小さすぎる対象には近傍候補／名称の選び直しを補助として提供する。
- 見えない建物に**透明なクリック領域**を与えない。覆った植物・建物を取り除かない。

### 5.3 この土地の記録から調べる
- 同じ調べるモード内に、地区の**既存確定記録に存在する**対象一覧への入口を用意。視認可能な建物のほか、覆われた廃墟・埋戻された水路なども閲覧できる。
- 「現地に見える」「記録はあるが現在は見えない」「記録が不十分」を明確な文言で分ける。**記録にない対象を一覧に足さない**。
- 一覧の存在は、文明がその遺構を「発掘・発見した」という新しい確定史を意味しない。
- 過去観測中の通常一覧は**その年まで**に確定した対象／イベントのみを使う。後年の対象を閲覧するには、明示的に比較側の年を移動する／別年を観測する。
- 小画面・キーボード／支援技術でも一覧から選択可能。風景上のピクセルヒットテストが唯一の入口にならない。

## 6. 320×180pxのヒットテストと遮蔽

D2の実装第一候補は、既存描画の所有者IDに結びつけた**オフスクリーンのピクセル選択マスク**。ゲームの保存正本ではない。

1. 対象の`ref`・幾何・建築世代と、現在の確定年の`SceneComposition`／建築画家／橋・水路の投影を照合。
2. 実画像と同じ変換・`mirrorX`・描画順・クリップ・前後レイヤーを適用。**選択可能と判定するのは、前景による遮蔽を経ても対象の可視画素が残る場所のみ**。
3. 画面上のCSSサイズ／devicePixelRatioから**元画像の整数ピクセル座標**を求め、クリック・タッチはマスクで対応する`HistoricalTargetRef`を引く。
4. 画素が一つも視認できない対象は`recorded-hidden`へ分類し、風景ヒットテストからは選べない。一覧側のみで閲覧する。
5. 動く風景では対象とマスクの時相がずれないよう、**調査中は静止した同一観測フレームに揃える**案を優先し、動物や揺れる木との瞬間的な当たり判定を避ける（演出の停止はUI操作に限り、文明年次処理を停止する意味ではない）。
6. 3地点、左右反転、草木／風化・廃墟化後の描画、施設・住宅部品、橋、水路、前景植物による遮蔽を含めてテスト。色から逆算して施設を認識するヒューリスティックは禁止。
7. 1pxの対象をタッチしやすくするための候補領域拡大は可能だが、重複・非表示の建物に勝手に割当てない。重なりは明示的な**候補の選択UI**で解消。

**実装停止線**：現行描画器が正確な可視所有者マスクを供給できない種類は、矩形で見かけ上の選択を「実装済み」としない。先にD1の**記録一覧**を実装し、D2で対象種ごとに実際の画素との突合を完了してから風景選択を開放する。比較用・レビュー用のマスクを本編の可視風景に重ねて保存しない。

## 7. 調査パネルと年代記

Canvasの**外側**に選択対象の履歴パネルを1件表示。

- 表示：対象の種類・名称・地区・観測年の状態、確定した起点、建築世代（確認可能なとき）、時系列の確定変化、実際に一致する年代記、当時の風景への操作。
- 「建設」「修復」「廃墟化」「休止」「埋戻し」等は元のイベント`kind`を基準にラベル化し、**不明な理由や推定年**を発生させない。
- 住宅街区の屋根部分に対するタップは`blockId`の街区情報を表示。「この屋根の住人の歴史」「1部品＝1家屋」等は表示しない。
- 既知の建設年より前は**未建設**、年代／開始が判定不能な情報は**記録なし**、存在したが現在見えない場合は**記録はあるが見えない**と区別。
- 年代記に一致する`RecordEntry.id`がなければ、単に「住宅／施設／水路の状態記録」であり、年代記のタイトル・理由を作らない。
- 過去の年へ移動した時は、その時点に存在する対象と履歴を再検証。まだ存在しない場合は「この年にはまだ建てられていません」。それ以上の未来の変化をその年の履歴パネルへ混ぜない。
- 新たな世界を生成／ロード／リセットした場合、過去の対象ID・調査内容・比較画像を破棄。地区切替時はその地区に対象がない場合、選択を解除。

## 8. 比較画面（Human決定B）と年の選択（Human決定B）

### 8.1 2枚の風景・同一の世界と地区

- PCは**左右2枚**、スマホは**上下2枚**。それぞれ同じ世界・同じ地区の**別々の確定年**を通常と同じ320×180pxの静止レンダリングから取得する。
- 比較元`referenceYear`は**比較開始時の観測年**に固定。ライブ中なら最新の確定年、過去観測中ならその過去年。自動更新・勝手な現在移動はしない。
- 比較先`comparisonYear`は確定した建設・増築・修復・放棄・廃墟化・水路の維持・埋戻しなど、対象の**実際に記録された年**を優先して選べる。
- さらに**任意の確定整数年**（世界暦0年〜`lastObservedYear(state)`）を直接入力・スライダー・±1年で指定可能。10,000年のスライダーだけに依存しない。イベント年の**前の年**は0年より前でなければ提示できる。
- 履歴対象のイベントが少なくても、**任意年比較**は可能。存在しない「最盛期」を機械的に選出しない。
- 明示的な2時点比較では、比較元より後の**すでに確定した年**を比較先に選ぶことは許す。ただし、その結果を比較元年の通常履歴として注入しない。表示に「比較元」「比較先」の年を明記し、「現在／過去」ラベルを強制しない。
- 各画像の存在・不在・状態ラベルは、その画像**自身の観測年**から導出。建設前、破損、世代交代、埋戻し、森林の遮蔽をその年の事実どおり表す。
- 比較中は2つの静止景観でよい。季節や植生を比較しやすさのために同一化しない。#36、#37、#38、#47の**その年の実描画**を再利用。
- 画像の上下／左右に情報を置き、元の風景を切り抜き・拡大加工して誤認させない。選択中の対象に印が必要なら**明示的にONできる別の注記層**として扱い、保存された風景画素には影響させない。**実際には見えない遺構をその場所に描くことはしない**。

### 8.2 観測年と比較年の独立した状態

```ts
interface HistoricalComparison {
  readonly worldIdentity: string; // UI内のセッション識別子。セーブへ追加しない
  readonly siteId: 'river-bank'|'hill-side'|'coast-inlet';
  readonly referenceYear: number;
  readonly comparisonYear: number;
  readonly target: HistoricalTargetRef|null;
}
```

- 上記は**UI一時状態**。世界保存に追加しない。`worldIdentity`は画面内のロード・生成毎に区別する概念で、永続化された`seed`だけを世界の同一性証明に使わない。
- **比較先の変更**は比較画像だけを更新。メインCanvas・#29グラフの表示窓・年代記・`viewedYear`は変更しない。
- **「この年を観測」**を明示的に選ぶときだけ、既存の`observeYear()`相当の共通入口を呼び、自動進行を止め、グラフ・年代記・Canvas・ステータスの観測年を一致させる。
- **比較を閉じる**と元の観測年と表示を維持する。調査モードを閉じた場合は比較も閉じる。
- 世界の再生成／ロードで比較画像と対象を破棄。比較中に文明が進行した場合も、2枚の確定年を**明示的な固定スナップショット**として維持するか、調査画面で進行を止めるかをD4のE2Eで決める（黙って基準年を更新しない）。
- 画像描画で`advanceWorldSession*`／`chooseWorldSession*`等の年次writerを呼ばない。UIには暫定イベントや未確定の`state.year`を年選択肢として出さない。

## 9. 性能と実装の責務

- `HistoricalTargetRef`と確定履歴の読み取りは**純粋関数**。同じworld・site・year・targetなら表示テキストとイベントが一致。
- 10,000年の履歴を毎フレーム全件走査しない。インデックスは世界オブジェクトID／確定境界をキーに遅延生成し、必要に応じてキャッシュ。保存・世界の正本を変更しない。
- ヒットテスト用マスクは観測年・地区・可視レイヤーの変更で再作成し、静止画と所有者IDを**同じ時相**にする。描画ごとに高コストな独立3D／物理探索を行わない。
- 比較画像は観測年ごとに必要な時だけ生成。前後年のレンダリングのために世界の年次処理を二度実行しない。
- 性能数値の合格閾値はD1〜D4の本物の世界（9世界／3地区／複数の年・密な植生）で測定してHumanレビューで定める。閾値が未設定の段階で「性能合格」と宣言しない。

### D1の必須テスト例

- [ ] 同じ施設IDで建築世代を変えた場合、出生年とその年の様式を正しく区別する
- [ ] 住宅街区の`partId`が異なっても同じ`blockId`へリンクし、未記録の住人史は生成しない
- [ ] 橋の`sourceRecordId`が正しい`RecordEntry`に一致。損傷時に通行可能を表示しない
- [ ] 水路の`systemId`ごとに`built/paused/abandoned/backfilled`を参照し、`ChannelCause`を偽の年代記に変換しない
- [ ] 未導入・履歴欠損・未建設・記録済み非表示を区別し、未来情報を普通の観測パネルに混ぜない
- [ ] 読み取り前後の世界save hash・文明RNG・確定記録が一致する

### D2〜D5の必須テスト例

- [ ] 木の前景に完全に覆われた廃墟は**風景から選べず**「この土地の記録」からだけ読める
- [ ] 左右反転とCSS拡大・縮小、屋根の重なり・水路と橋の重なりで同じ実画素の対象を選ぶ
- [ ] タッチで小さな物体を選び直せる。キーボード／支援技術では一覧から調べられる
- [ ] 比較先変更で通常の`viewedYear`／#29のグラフ状態を変更しない。明示的に「この年を観測」の時だけ変更
- [ ] 世界暦0年や上限年、分岐待ち年、同一年比較、建設年の前日相当（前年）、その年に存在しない対象に対応
- [ ] 通常描画と比較用レンダリングの**同一world・site・year**のRGBAが一致。季節・風化・植物・動物は一致すべき年の条件を参照
- [ ] 複数seed×3地区×長期の履歴・実画像比較により、保存→読込→過去→現在で世界史・地形・植生・建築・水路・文明RNGが不変
- [ ] 調べるモードOFFで従来の観測画面・通常描画を変更しない
- [ ] モバイルで比較画像を縦に並べても視認性と操作領域が保たれ、元の320×180pxのCanvas比率が変わらない

## 11. D0完成時の結論と残る実装選択

**確定すること**：風景からの発見と、記録を辿る調査は別の入口。後者には隠れた施設や埋戻し水路の**記録**が存在し得るが、それを現在の地表に描いて発見を捏造しない。2画面の静止比較では確定年の本物の風景をそのまま並べ、調査対象の世代・状態と年代記を一致させる。

**Human判断の追加を要さずD1〜D4で比較・具体化する技術詳細**：マスクの実装方法／閾値、動く景観の静止方式、履歴一覧の密度、表示スタイル、比較中の進行の取り扱い、描画キャッシュ、性能閾値。もし可視画素を正しく追跡できないならD2を中断し、対象種ごとに再設計・Humanレビューへ戻す。

**本PRの変更は本設計文書1ファイルのみ**。D1の履歴取得APIから実装し、Humanのレビュー・マージを経て段階的に進める。#39のクローズ、既存の確定史の書き換え、マージは行わない。
