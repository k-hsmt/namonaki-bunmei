# 集落が周辺へ広がる配置（terrain-placement-v2）

初期の家への距離を強く最小化していたため、川岸などの狭い一角に建物が詰まり、画面下端で屋根が重なっていた。新しく生む文明では、余白を残しながら既存の集落の周辺へ広がる配置を使う。

## 配置の変更

- 最初の家は、水への近さと家・畑・通路の成立を維持しつつ、画面下端や左右端に偏らない場所を優先する。
- 確定済みの家・住宅のうち、周囲の占有が少ない入口を次の成長の起点にする。未建設の予約敷地を成長の起点にはしない。選んだ起点が行き止まりなどで使えない場合は、次の確定済みの起点も順に試す。
- 通常の建物は、他の敷地から横6pxまたは縦10pxの間隔を取る。畑は3px、大型civicは横8pxまたは縦10px。さらに近隣の占有密度を評価し、必要な最小間隔へ詰めることだけを目的にしない。
- 起点からの歩行距離に14〜32pxの好適範囲を設ける。住宅が増えた後は4街区ごとに34〜56pxを好むことで周辺への枝分かれを促す。80pxを超える孤立した飛び地は候補にしない。これは敷地の直線距離ではなく、建設後の歩行可能な経路で評価する。
- 初期拠点への距離評価は48pxで頭打ちにする。実際の施設建設時には、計画時の候補を無条件に使わず、その年の占有状況で再評価する。

建物の需要・人口条件・建設間隔・維持や衰退・乱数の使い方は従来どおり。地形のgrade・標高差・通路幅・候補格子・橋の安全条件も変えない。建設位置が変わるため、敷地不足や橋との干渉を通じて、建設時期・歴史に間接的な差は生じ得る。

最短経路を使う候補探索は、全候補を調べる参照探索と同じ最小スコアを選ぶ。好適距離の下限による非単調な項は、枝刈り用の下界に加えない。凍結済みの地形で、占有・予約・橋・起点・要求が同じ場合に限り、前回の敷地なし判定を再利用する。未確定年や不明な履歴では再利用せず、参照探索も必ず計算する。

## 保存と既存世界

新規作成だけを `terrain-placement-v2` にする。保存契約v5のpolicy IDを保存し、読み込み時にもその方式を復元する。`terrain-placement-v1` と legacy-fixed の保存は以前の方式で継続し、建物を移動したり、過去を再生成したりしない。改善を試すには「この種で生まれ直す」または「新しい文明を生む」を使う。

旧D5の監査と性能比較は明示的にv1を指定し、当時の固定結果・承認記録を保持する。新配置の検証結果を旧D5の数値へ上書きしない。

## 確認方法

```sh
npm test
PLAYWRIGHT_BROWSERS_PATH=/tmp/namonaki-browsers npm run test:browser
node scripts/audit-organic-growth.mjs
node scripts/benchmark-organic-growth.mjs
PLAYWRIGHT_BROWSERS_PATH=/tmp/namonaki-browsers node scripts/review-organic-growth.mjs
```

`artifacts/terrain31-organic/index.html` は seed 10・42・3、3地区、100・300・1000年の新旧54景観を並べる。描画のために人口や建物を追加しない。seed 10の川辺・100年では、畑を除く建物6棟の占有範囲が58×26pxから80×61pxへ拡大した。建物を増やして広がりを演出した結果ではない。

`audit.json` は12世界の自然進行（seed 1は10000年、残りは2000年）、gzip保存往復、読み込み後60年の続きの一致、過去12情景の不変性、全既存v1ハッシュの維持を記録する。所要時間は単発の参考値で、旧D5の正式な中央値計測とは区別する。

CIの `organic-growth` がこの監査と比較画像を毎回生成し、`terrain31-organic-growth` artifactに保存する。ユニットテストでは好適距離・枝分かれの厳密探索一致、余白、自然進行での広がり、保存後の方式維持と継続一致を検証する。

`performance.json` は seed 1 の2000年・10000年と、行き止まり探索が多い seed 7・10 の2000年を各方式でウォームアップ1回＋計測5回実行する。初期化・描画・ハッシュ・保存を除外し、新配置の中央値が5秒／25秒以内、かつ同一ランナー上のv1の2倍以内（分母は最低1秒）であることを確認する。旧D5全16ケースの再承認を意味するものではない。
