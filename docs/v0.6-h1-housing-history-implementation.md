## 1. 実装範囲

- `src/story/housing-history.ts`：住宅街区の型と確定履歴の再構築 `housingAt(history,year,siteId)`。年・同一年の順序、街区ID・敷地・建設年・様式の不変性、住戸数の非負性、状態遷移を検証。
- `src/scene/housing-ground.ts`：物理的な住宅敷地について、同一年に成立済みの個別施設、川、既存住宅街区との衝突を検査。**屋根や樹冠の描画上の重なりは衝突とみなさない**。
- `src/scene/composition.ts`：住宅街区を描画用 `residentialBlocks` に投影する。屋根部品の `partId`、奥行き `far/middle/near`、表示する住戸数 `representedUnits` を導出。
- `src/scene/draw.ts`：**任意の住宅履歴が渡されたときのみ**遠景・中景・前景の簡易スプライトを描画。既存3引数の描画呼出しには変更がない。4枚の固定画像を切り替える実装ではない。

## 2. 正本と描画導出の対応

```text
HousingHistory.events
  └─ housingAt(year) : その年の実在住宅街区・住戸数・状態
      └─ composeScene(snapshot, housingHistory)
          ├─ structures : 従来の確定施設台帳のみ
          ├─ residentialBlocks : 記録済み住宅街区のみ
          └─ roofParts : 住宅街区の決定的な描画部品
              └─ drawScene(...,housingHistory) -> Canvas 320×180
```

`housingCount` は履歴上の住戸数。`roofPartCount` は描画用の屋根部品数。`slotCapacity` は敷地・奥行き・スプライト段階から求める部品数上限。**三者は同一ではない。** `representedUnits` を合算すると、各街区の `housingCount` と一致する。1つの屋根部品が複数住戸を表してよいが、実在しない施設や住戸は生成しない。

住宅街区の物理座標と、スプライト描画座標を分離。建設年、ID、敷地、様式は不変で、規模変更によって住宅の位置を再配置しない。住宅ストックが増えて表示部品数が増える場合にも、それまでの部品インデックスと原点を維持する。部品に割り当てた住戸の表現上の重みは増築で変化し得る。

`condition` と `use` は独立した状態。廃墟化イベント `ruined` の後状態は必ず `ruined + vacant`。廃墟からの再利用は `repaired` の後に `reused` を別イベントとして記録し、`year/seq` で順序を確定する。

## 6. CONDITIONAL GOレビュー対応：状態遷移の厳密化

### 6-1. イベントごとに変更を許可する属性

| イベント | 変更可能な属性 | 追加条件 |
|---|---|---|
| `built` | 新街区の全初期値 | 建設年＝イベント年、健全・利用中、修繕年なし |
| `expanded` | `housingCount` の増加のみ | 敷地・様式・状態を維持 |
| `underused` | `use` のみ | `occupied → underused` |
| `vacated` | `use` のみ | `occupied/underused → vacant` |
| `damaged` | `condition` のみ | `sound → damaged` |
| `ruined` | `condition` と `use` | **`damaged → ruined` に限る。原子的に `use=vacant`** |
| `repaired` | `condition` と `lastRenovatedYear` | `damaged/ruined → sound`、修繕年＝イベント年。廃墟後は未使用のまま |
| `reused` | `use` のみ | 健全・未使用の街区を `occupied/underused` へ移す |

すべてのイベントで `blockId/siteId/footprint/builtYear/styleId/styleSeed` は不変。イベントによって許可されていない `housingCount/condition/use/lastRenovatedYear` の変更を拒否する。`lastRenovatedYear` は街区の建設年より前、およびイベントの確定年より後を禁止する。同じ年の修繕・再利用には `seq` で順序を付ける。

**直接廃墟化の条件：** H1で `sound → ruined` は禁止し、損傷の履歴が記録された `damaged` からのみ、別の明示イベントで廃墟化できる。人口減少や規模名の変化はそのイベントに該当しない。将来の災害による即時倒壊は、損傷→廃墟化の同年連続イベントなど、因果関係を明示した別設計で扱う。

## 7. 地形検証の適用範囲とH3の停止条件

現在の `src/scene/housing-ground.ts` は **河畔（`siteIndex === 0`）の河川輪郭だけ**をポリゴン検証している。住宅街区同士と現在存在する個別施設との占有矩形チェックは共通だが、**丘陵・入り江の斜面・水面・道路・不可建設区域を検証する仕組みは未実装**。

**H3開始時の必須条件：** 丘陵（siteIndex=1）と入り江（siteIndex=2）の地形敷地検証を実装・fixtureで検証するまで、自然進行による住宅街区の建設イベント生成を禁止する。未対応地点は必ず **HOLD** とし、建設可能と仮定して進めない。現行H1には自然進行の住宅建設処理そのものがない。

さらに既存の施設建設処理は、後から既存住宅街区に衝突した場合のHOLDが未接続。H3において住宅・施設いずれの建設も確定前に土地占有を検査し、位置の移動や削除はしない。
