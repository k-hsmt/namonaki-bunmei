# v0.6 Milestone A — 320×180 landscape prototype (Human review requested)

Status: **REVIEW / NOT APPROVED**. Do not start milestones B/C, merge or deploy.

## Asset provenance and scope
The supplied `namonaki_pixel_prototype.zip` was inspected, including the actual `render.py`, README, and settlement/city PNGs. A locally generated extension adds independent village and town fixtures on the exact same base terrain and fixed camera. The full reproducible prototype (Python renderer, README, tests, ten PNG outputs) is delivered as a conversation artifact alongside this review; **these PNGs are not actual simulation observations**.

The four fixtures are intended as a **layout language** rather than four images to swap in the production renderer.

## Comparison criteria (no on-image labels)
- Settlement: sparse huts, narrow paths, most land remains natural.
- Village: compact domestic cluster, communal clearing, interconnected paths and larger cultivation.
- Town: market clearing and stalls, distinguishable workshops and storage, water-edge loading zones and established roads.
- City: layered roof blocks, several streets, paved land and concentrated waterfront; terrain and river outline stay recognizable.

Screenshots: native 320×180 and NEAREST 1280×720 for each stage; composite native 640×360 and NEAREST 2560×1440.

## Verification done on prototype
- Recreated all four fixtures from source.
- Image dimensions and exact nearest-neighbor pixel expansion verified.
- Eight per-stage files distinct; repeated runs generated byte-for-byte identical images.
- Existing TypeScript simulation / save / main site: **not changed**.
- No browser or 1000-year simulation claim is made for this isolated prototype.

## Milestone B proposal — only after visual acceptance
1. Pure `SceneComposition` from confirmed historical observation, with a distinct factual-vs-decorative boundary.
2. Assign immutable sprite appearance at construction/renovation, not on a scale classification transition.
3. Track land-use/block evolution with explicit events or deterministic legacy fallback; do not insert buildings into confirmed historic saves.
4. Display public buildings, bridges, warehouses, quay facilities **only** when authoritative history supports them.
5. Keep existing `drawScene` API and old-save boundary; add Node + Playwright tests before replacing the runtime painter.

## Remaining visual concerns
The style is deliberately simpler than the accepted high-res concept. Roof forms and foreground/midground depth may still feel insufficient at 1x. Human assessment, not unique PNG hashes, determines A acceptance.
