## 1. 目的とHuman確定判断

『名もなき文明』で、建物が放棄された後の数十〜数百年を、歴史に裏付けられた景観として観察できるようにする。廃墟が朽ち、苔や蔦が壁を覆い、草や木が徐々に周辺へ戻る。一方、建築の痕跡が完全には消えないこともある。**自然に隠れたことは、建物が確定履歴から消えたことではない。**

| 判断 | Human決定 |
| --- | --- |
| 基本モデル | **B**：建築の風化は描画投影、自然回帰は既存の植生・土地履歴に接続 |
| 侵入範囲 | **B**：敷地外縁と、廃墟内部の**確認済みの露出地面**に限定 |
| 回復開始 | **B**：住宅の`vacated`で外縁、`ruined`で内部へ段階的に拡大 |
| 苔・蔦 | **B**：確定気候・既存植生に連動した**表面描画**。独立した植物個体の保存史は作らない |
| 遺構の可視性 | **B**：自然な遮蔽を許容。可視性を保証するために植物を移動／間引きしない |

### 対象
- 住宅街区・既存の施設の廃墟、建築時の様式と素材、確定した放棄・廃墟・修繕・再利用の履歴。
- 8×8px植生パッチ、局所生育領域、草・低木・若木・成熟樹の段階的な回復。
- 建物表面の苔・蔦、既存の7バイオーム・3地区の気候差。現行の季節表現との合成。
- 原寸320×180pxの静止・動く景観、過去観測、保存往復、長期進行での整合性。

### 初版対象外
- 風化を原因とする**物理的な建物の倒壊・消滅**、敷地／施設IDの削除、土地権利・通行／建築可能性の自動変更。
- 苔・蔦の独立した生物種・個体・保存イベントや、経済・人口・災害頻度への効果。
- 未確定の道路・水路の維持停止を推測しての植生解放。**確定した**農地・公共空地は既存モデルを用いる。道路の歴史的な退廃と物理機能変化は別設計。
- 「遺構の発見」「文化的な保存／解釈」「建材流用」「完全復元」「用途転換」の新しい確定イベント。既存の修繕・再利用の描画整合は扱う。
- 現在の開発フェーズにない過去の記録を補完する互換アダプタ。

## 2. 正本と投影の境界

**正本**：
1. 建築物のID・敷地・建設年・様式と世代・状態（`intact/damaged/ruined`など）・修繕・再利用の確定イベント。
2. 建築上の占有（廃墟でも`housing-ground.ts`の既存敷地占有を保持）、地形・水理・施設の確定履歴。
3. 既存の植生群落・攪乱履歴（`vegetation/history-v1.ts`、`flora-growth-v1.ts`）、世界と地点の気候履歴。
4. 季節の位相・積雪の表示は#36が所有する。

**導出する表示**：
- `RuinAppearance`：放棄と廃墟化からの経過時間、当時の建材、長期気候、確定した修繕を参照する風化強度／欠損輪郭。
- `ReclamationAccess`：どの地面がいつから植物を置けるかの**局所アクセス**。建築上の土地占有とは別。
- `SurfaceCover`：残存する壁・柱・基礎表面への苔／蔦の被覆。
- 表示上の欠損や前景植物による遮蔽は、建物の消滅・建築可能性・森林の物理的なルール変更を意味しない。

初版では、確定イベントから局所アクセスを再構築する**版付き・決定的な投影**を第一候補とする。必要な正本情報が欠ける場合は保守的に**未解放**とし、未来／他の建築の履歴から埋めない。

## 3. 建築と放棄の時間軸

### 住宅
現行`housing-history.ts`に`built / underused / vacated / damaged / ruined / repaired / reused`がある。**状態`condition`と利用`use`は異なる軸**であり、`ruined`では`vacant`を要求する。

| 確定イベント | 局所植生アクセス | 風化の扱い |
| --- | --- | --- |
| `built` | 住宅敷地は保護 | 建築出生様式を使用 |
| `underused` | 敷地保護のまま | 明確な放棄起点を創作しない |
| `vacated` | 外縁の適格な地面のみ解放 | 放棄・表面被覆の起点を得る |
| `ruined` | 外縁を維持、**確認済み露出内部**を新たに解放 | 廃墟としての経過年数を別に開始 |
| `repaired` | 内部を再保護、外縁は`vacant`なら条件付きで維持 | 修繕の正本に従い、該当世代の風化を再評価 |
| `reused` | 利用範囲を再保護し、必要な植生の攪乱を反映 | 建築の正本と再利用状態を反映 |
| 再`vacated` | 新しい解放期間を開始 | 旧期間と混ぜず再計算 |

`damaged`単独では建物全体の放棄や土地解放を推測しない。建築上の修繕・再利用が別年に確定する現行ルールを守る。`vacated`の直後に成熟樹を瞬時に生やさない。**放棄年数**と**廃墟化後の年数**は別の時計として表示に使用する。

### 一般施設
`settlement-history.ts`には住宅の`vacated`と同等の状態はなく、`building-abandoned`時に`ruined`となる場合がある。**存在しない施設の空き家期間を捏造しない**。施設は、確認済みの`building-abandoned`と占有・描画情報が揃った時点から外縁と露出内部の候補を評価する。修繕・再利用も既存の確定建物履歴を参照。`recordId`・建築出生情報・敷地が追跡不能な対象は、勝手に局所解放しない。

## 4. 二種類の土地占有を混同しない

- **ConstructionOccupancy**：既存の土地利用と物理的な建築・橋・河川・水路・公共空地などの衝突判定。住宅は廃墟でも敷地全体を保持。`housing-ground.ts`、施設配置・道路アクセスの契約を変更しない。
- **VegetationAccess**：植物の根元が**実際に置ける場所**の細粒度表示。外縁と露出した内部のみに限定。土地占有や建設権限を変更しない。
- **RuinSurfaceGeometry**：建材ごとの残存壁・屋根・柱・基礎の形状。苔・蔦と#36積雪の適用候補を与える。

### 根元を置ける条件（全条件必須）
1. 確定されたその年の陸地・生育可能面。川・海・運河・斜面の非支持面ではない。
2. 対象IDと住宅・施設状態から、当該領域の解放が**確定**している。
3. 描画上の透明色ではなく、正本の構造と地表に裏付けられた**露出地面**である。
4. 壁・柱・基礎・居住中の他施設・橋・水路等の予約／占有と根元必要領域が衝突しない。
5. 既存の植物群落候補、局所気候・地表材・成長上限に適合する。
6. 画面左右の鏡像時、根元・マスク・建築部材の座標が同じ地形座標から一貫して変換される。

未対応または不明な構造上の場所は**保護（植物なし）**を既定とする。樹冠や蔦が前面から建物を隠すことは許すが、幹・根元の構造貫通は許さない。可視性を補償するための自動剪定・植物移動はしない。

### 候補マスク（D0概念）
```ts
type ReclamationZone = 'perimeter' | 'exposed-interior';
type GroundMask = Uint8Array; // 320 x 180、地形の正規座標
interface ReclamationRegion {
  readonly ownerId: string;
  readonly siteId: 'river-bank' | 'hill-side' | 'coast-inlet';
  readonly zone: ReclamationZone;
  readonly openedYear: number;
  readonly sourceRecordId: string; // または検証可能な住宅イベントの一意キー
  readonly mask: GroundMask; // 導出、保存しない
}
```

この型は概念例。ピクセル配列をすべて毎年保存するのではなく、確定イベント・構造形状から導き、場面内にキャッシュする。全ての見えない床を露出地面とみなさず、根元候補の安全な輪郭だけ採用する。

## 5. 8×8植生パッチとの接続（重要）

現在の`vegetation/history-v1.ts`は`clear / release / fire`の確定攪乱イベントと8×8pxパッチを用いる。`vegetationAt`は重なったパッチ全体の成長開始年を変更しうる。そこで**廃墟の小さな開口を解放するために既存パッチ全体へ単純な`release`を追加しない**。

- 既存パッチ：植物群落・生育適性・周辺環境の正本として扱い、屋外で既に成長中の植物の年齢を維持。
- 局所解放：建物イベントと位置の確定証拠に対応した`openedYear`を用い、露出地面の**局所的な遷移年齢**を導く。
- 局所植生段階：`openedYear`以降の経過時間と既存の種別・気候許容・地表の成立条件を用いる。既存パッチが建築占有によって抑制されていても、局所解放領域は適切に成長し得る。
- 同時に同じパッチの**建物外の成熟木**を巻き戻さない。既存群落の樹種や姿を無制約にコピーせず、成長の0→草→低木→若木→成熟木の段階を飛び越えない。
- 追加する局所植物の配置・個体表現も、世界seed／地点／オーナーID／解放イベントから決定的に生成し、文明用RNGは一度も消費しない。
- 再利用／修繕により地面の保護が再開したら、対象局所植生を**その確定年にのみ**除去／攪乱し、再放棄では新しい`openedYear`を使用。過去の植物を削除しない。

D1では「既存`release`の部分領域拡張」と「イベントを参照する独立局所アクセス投影」を比較する。**推奨は後者**。ただし、最終実装のデータ所有と保存versionは実測・回帰検証後に決める。独自の無根拠な植生史を追加しない。

## 6. 建材・建築世代と風化の描画

現在の`architecture/scene-v1.ts`の`drawRuin()`は建築世代の部品を一定割合欠損した姿に変換する。D0では、これを**既存状態`ruined`の描画の起点**とし、放棄・廃墟後の年月・材質・気候から段階的に変化させる。

| 壁・構造材料 | 優先する視覚差 | 残存傾向の試作 |
| --- | --- | --- |
| 木造（丸太・板） | 色褪せ、変色、傷み、部分的な欠け | 梁や柱の断片 |
| 土・版築・編枝土壁 | 角の摩耗、表面の退色、ひび | 地形色に馴染む低い壁 |
| 石積み・整形石材 | 目地の凹凸、苔、石の一部欠け | 石壁や基礎の輪郭 |
| 木石混構造 | 木造部と石部の異なる劣化 | 石基礎に木材の断片 |

屋根素材は茅・木板・石板・瓦・漆喰等を**現行建築出生の正本**から参照する。見た目の屋根欠損は、#36の「実際に残る屋根へだけ雪を積もらせる」描画へ渡す。初版では風化が進んでも`condition`や`footprint`は変更しない。

描画用の概念値：
```ts
interface RuinAppearance {
  readonly weathering: number;
  readonly roofLoss: number;
  readonly wallLoss: number;
  readonly traceVisibility: number; // 表示の結果、可視率の最低保証ではない
}
```

数値と閾値をD0で確定しない。***歳月だけで建物の完全消滅を確定しない***。巨大な石造物が長く残る世界も、自然に深く覆われる世界も許す。外観は静止・動く景観に同じ決定的な規則を用いる。

修繕では建設年や過去の世代を上書きしない。修繕／改築・再建の確定履歴が与える世代を選び、確認できない部分補修の位置を捏造しない。必要に応じて建築描画単位で新しい風化起点を定義し、誤った「全建物が新築されたような巻戻り」を避ける。

## 7. 苔・蔦の「表面被覆」は既存環境から導出

苔と蔦は建物の表面に描く**独立した表示カテゴリ**であって、植生の確定個体・経済的な資源とはしない。

- **苔**：湿潤度、気温、日陰相当の幾何／素材差、周辺苔・下層植生の生育適性、放棄後の露出期間に応じて点・面状に付着。石目地・湿った木材・基礎周辺を優先。
- **蔦／蔓**：地面に成立し得る根元、近隣の既存植物群落の適性、放棄後の時間、到達可能な**残存壁・柱**が揃うときのみ、下方から上方へ伸長する模様を描く。現行13植物系統に蔦専用の生物個体はないため、種として新規生成・保存はしない。
- **気候**：観測年の一時的な湿潤化で何百年分もの苔を瞬時に発生させない。#34の過去の確定環境チェックポイントや区間集約などから、放棄期間の持続条件を求める案をD1で比較。
- **部材形状**：その年に実在する壁・基礎・屋根・支柱のマスク上のみ描画。透明画素、既に欠けた壁、消滅した屋根へは被覆を発生させない。表面被覆と根元設置可能地面のマスクは**同一物ではない**。
- **時間**：放棄後に露出していた表面と、廃墟化して初めて露出した表面を区別。新しい補修の正本に従って該当部材の表面被覆を更新し、未来の修繕が過去の苔を消すことを禁じる。

概念型：
```ts
interface RuinSurfaceGeometry {
  readonly wallSurface: Uint8Array;
  readonly roofSurface: Uint8Array;
  readonly foundationSurface: Uint8Array;
  readonly exposedGround: Uint8Array; // 別途保守的に証明された領域
}
interface SurfaceCover {
  readonly mossCoverage: number;
  readonly vineCoverage: number;
}
```
正式な型・被覆強度・マスク粒度・キャッシュ単位はD1で決定。表面の緑量を全バイオーム一律に増幅しない。

## 8. 季節#36と既存描画順序

- 建物の**建築様式→風化した残存形状→苔・蔦の表面描画→季節の積雪**という、**建物内部**の合成責務を守る。
- 地表植物は既存`flora-draw.ts`の「建物背後の植物／構造物／建物前面の植物」分割を維持。単一の全画面レイヤーの前後入替えはしない。
- #36の積雪は残存屋根と植物の実際の形状のみを使い、欠損した壁・屋根を雪で再構築しない。季節が変わっても風化時間・苔の長期被覆は巻き戻さない。
- 植物の根元と幹が建物の壁・基礎を貫通しないこと。前景の樹冠や蔦が遺構を**自然に遮蔽することは許容**し、可視ピクセル数の最低保証や人工的な剪定を作らない。
- 建物ID・敷地・構造部材の正本が当時の状態を維持していれば、最終画面にほとんど遺構が見えなくても有効。歴史UI側の表示内容は別Issueとする。

既存の`sceneOccupiedPlots()`の占有除外を一律に削除すると、廃墟敷地全面に根元が入り得るため禁止。施工可能土地の衝突判定は常に従来どおり。**廃墟に苔があるから新築できる、あるいは森で隠れたから占有が無くなる**といった因果関係を作らない。

## 9. 履歴・保存・過去観測・決定性

- 入力は**確定観測年**・地区・世界seed・建築世代・確定建物イベント・確定植生と環境履歴・地形。未確定年／未来の災害・修繕・気候変化を読むことは禁止。
- 既存住宅・施設・植生イベントから派生できる局所解放は、重複して独立保存せず**決定的な版付き規則**で導くことを第一候補とする。根拠となる住宅イベントの`year/seq/blockId`や施設`recordId`を監査可能にする。
- 現行モデルが持たない廃墟内側の物理的な開口が証明できない場合は**未解放**として扱い、透明画素を根拠にしない。D1で適格な範囲の小ささを可視化しHuman確認する。
- 保存仕様を変更する実装では`AGENTS.md`に従い、現在の内部整合・再現性をテストする。不要な旧保存互換を増やさないが、壊れた保存を黙って自動補完／削除しない。
- 一括・分割進行、描画ON/OFF、同じseed・選択・確定履歴、保存→読込→再進行で**文明RNG・建築・地形・植生の確定史が変わらない**こと。
- 任意の年を観測した後に現在へ戻しても値が移らない。未来を観測してから過去を表示しても過去の廃墟景観は不変。
- 表示用のハッシュ名前空間は文明RNGから独立。風化・苔・蔦・局所回復は、観測・表示を呼んだ回数に依存しない。
- 長期気候の評価は確定チェックポイント／区間集約の活用を検討し、数千年×建物数×全画素の逐年再計算を避ける。最終キャッシュ仕様はD1性能測定で選ぶ。

## 10. D1の比較試作と合否

### 実画像の試作

1. **経過年数**：同じ建物・同じ地形で放棄直後／50／200／500年の表示を独立比較。強制比較は**開発用入力**としてラベル付けし、実際の保存済みの歴史とは区別する。
2. **建材**：木／土／石／混合と屋根材、修繕や世代交代を含む。原寸320×180px・nearest-neighbor拡大で形状の判別を確認。
3. **バイオーム**：7つの初期気候帯×3地区を候補とし、特に温帯林・熱帯雨林・砂漠・亜寒帯林で苔・蔦・自然回帰の程度を比較。全環境で森を強制発生させない。
4. **状態遷移**：住宅の使用中→低利用→空き家→廃墟→修繕（空き家）→再利用→再放棄、一般施設の建築→放棄→修繕／再利用。建物なし／形状不明は保護のまま。
5. **空間**：8×8pxパッチをまたぐ敷地、2px以下の隙間、壁・基礎・柱・水域、鏡像3地区、建物背後／手前。内部根元の衝突と周辺植物の不必要な巻戻りを検査。
