## 2. D2で作るもの・作らないもの

**作るもの**
1. `WorldArchitecturalGrammar`：世界に共通する建築の好み（年0に一度だけ確定）。
2. `RegionalArchitecturalTradition`：3地区それぞれの初期の伝統。世界の文法と、その地区の年0の土地条件への適応から確定する。
3. `BuildingBirthStyle`：建物が建った年に、その年の地区の伝統と敷地の条件から、形・構造・素材・開口・装飾を確定して固定する。
4. 上記を保存・読込・検証する版付きの記録、およびそれを描く新しい描画版。

**作らないもの（後の段階）**
- 伝統の変化・地区間の伝播・独自発明（D3）。D2の伝統は年0のまま変わらない。
- 技術能力の成立。D2では在来構造 S01〜S07 だけを選べる。高度技術 A1〜A3・X1〜X3・W7 は選ばない（D3）。
- 老朽化・建替え・敷地の再利用（D4）。既存の損傷・廃墟の状態は従来の表現のまま描く（§6.3）。
- 配置・街路の構成（D5）。建物の位置・敷地・建設年・棟数はD2で一切変えない。
- 橋・水辺施設の意匠（D1で未着手）。城・館（保留）。

**D2単独の限界**：D2だけでは伝統が年0から変わらないため、遊ぶと「初期に決まった文化が永久に続く」ように見える。これはD0 §4.1が禁じる状態に見た目上は近い。そのため、通常画面の新規世界の既定はD2の時点では切り替えず、D3の文化の変化と同時に切り替える（§9-2、Human判断済み）。

## 3. 文化の構成

### 3.1 世界の文法と地区の伝統の分担

D0のA02「同一文明の3地区で、共通性と地形適応の差が同時にある」を満たすため、軸を二つに分ける。

| 区分 | 軸 | 決め方 |
|---|---|---|
| 世界で共通（文明の面影） | 屋根の系統、軒の出、勾配、装飾の系統 | 世界の文法で確定。3地区とも同じ値から出発する |
| 地区で適応 | 壁・支持構造、壁素材、屋根素材、基礎、窓、入口、配色（P01〜P05） | 世界の文法が持つ重みに、地区の土地条件で補正をかけて確定 |

配色は地区ごとに決める（§9-4 のHuman判断）。配色の重みは、その地区で選ばれた壁素材・屋根素材と矛盾しないよう補正する（例：厚い土壁なら黄土・赤褐系P02、整形石なら石灰・青灰系P03の重みを上げる）。ただし配色の違いは、A01・A02の「形の違い」には数えない。

地区の適応が文法の共通軸を上書きすることは原則しない。ただし、組み合わせとして成立しない場合（例：茅葺き＋平屋根）は §3.3 の制約で別の候補に置き換え、その理由を記録に残す。

### 3.2 語彙（D1の採用分）

| 軸 | ID | D2で選べるもの |
|---|---|---|
| 屋根の系統 | R01〜R06、R08 | 全て |
| 軒の出 | 通常・深い（D1カタログ名R07） | 全て。屋根の系統とは別の軸 |
| 勾配 | 低・中・高 | 全て |
| 構造 | S01〜S07 | 全て（X1〜X3は選ばない） |
| 壁素材 | 10種 | 在来の8種（金属支持・複合外皮は選ばない） |
| 屋根素材 | 7種 | 在来の5種（金属板・透過材は選ばない） |
| 基礎 | F1〜F6 | F1〜F5（大規模基礎F6は選ばない） |
| 窓 | W1〜W6 | 全て（W7は選ばない） |
| 入口 | E1〜E7 | 全て |
| 装飾 | O1〜O8 | 全て。D1の所見どおり、小さい建物では描かない装飾がある |
| 配色 | P01〜P05 | 全て。P06（褪色）は状態であり文化として選ばない |

**R07の正規形**：D1の `normalizeSpec` は `roof==='R07'` を `roof='R01', deepEaves=true` に置き換えていた。D2では保存・抽選・描画のすべてで `roofFamily ∈ {R01〜R06, R08}` と `eaves ∈ {normal, deep}` に分けて持ち、`R07` という値は保存しない。R07はD1カタログ上の表示名としてだけ残す。これで「深い軒の寄棟（R03＋deep）」も表現できる。読込時に `roofFamily: 'R07'` が現れたら拒否する。抽選・描画・保存の検証で正規化の結果が一致することをテストする。

D1の代表文化 C1〜C6 は**比較のための固定値**であり、D2で6つのプリセットから選ぶ実装にはしない（D0 §3.5）。文法は各軸の重みとして持ち、結果として C1〜C6 に近い文化も、それ以外の組み合わせも生じ得る。

### 3.3 成立しない組み合わせ

D1試作の拒否規則（高床に階段のない入口、茅葺きの平屋根、在来構造への金属・ガラス、土壁を高床支柱に載せる 等）を `architecture-constraints-v1` として本番の制約表に移す。D1ではこれは「仮の規則」だったため、移す時点で一覧を本書の付録として固定し、Humanレビューの対象にする。

### 3.4 用途への投影

D1の用途横断マトリクス（7用途）を、本番の建物記録に次のように対応させる。

| 本番の記録 | D1の用途 |
|---|---|
| 住宅街区 `styleId: low` | 独立住宅 |
| 住宅街区 `styleId: terraced` | 連棟住宅 |
| 住宅街区 `styleId: courtyard` | 中庭街区 |
| 施設 `house` | 独立住宅 |
| 施設 `granary`／`workshop`／`market` | 穀物庫／仕事場／市場 |
| 施設 `hall`（civicなし） | 会堂 |
| 施設 `hall`（civicあり） | 会堂。ただし形式（great-hall/courtyard-hall）と寸法はcivicを優先 |

**civicは別の建物ではない**：現行の `CivicBuilding` は `Building & {kind:'hall'; civic:CivicFoundation}` であり（`src/story/civic-architecture.ts`）、`SiteView.buildings` に入る施設のhallそのものである。そのため、建設時様式の正本は**施設と住宅の2分類だけ**とし、civicは施設の様式記録に付く参照属性（形式と建設出典ID）として扱う（§5.2）。同じhallに施設とcivicの2件の記録ができることはない。

同じ文化の中でも用途ごとに輪郭が異なること（D1で確認済み）を本番でも保つ。

**D1との違い（設計上の空白）**：D1試作では、用途ごとの違いを代表文化ごとの**手書きの上書き**（例：C3の会堂だけ整形石、仕事場だけ大開口E7）で作っていた（`architecture-prototype.mjs` の `C(...)` の第3引数）。D2では文化が生成されるため、これを「用途ごとの補正規則」に置き換える必要がある。案として、用途ごとに軸の重みを補正する表（例：市場は大開口E7・深い軒の重みを上げる、穀物庫は高床F5・石の土台F2の重みを上げ窓を減らす、会堂は整形石・複数階・装飾の重みを上げる）を `architecture-use-rules-v1` として固定する。この表はD1では検証していないため、D2-aで代表文化C1〜C6の手書きの上書きを規則から再現できるかを確認する。

### 3.4.1 住宅街区の増築

`ResidentialBlock` の `housingCount` は `expanded` イベントで後年増える。`src/scene/composition.ts` は、その年の `housingCount` から屋根部品 `roofParts`（`partId = blockId + ':' + i`）を投影している。並びは固定敷地と `styleSeed` だけで決まり、規模が変わっても並び替わらない（同ファイルの注記）。

街区に記録を1件だけ持たせると、後年の増築で現れた屋根まで当初の建設年の様式になる。D2では伝統が変わらないので目立たないが、D3で文化が変わると歴史と外観が食い違う。そこでD2から、**住戸の追加ごとに様式を記録する**。

- `built` イベントで、部品番号 `[0, housingCount)` に対して1件。
- `expanded` イベントごとに、増えた部品番号 `[旧housingCount, 新housingCount)` に対して1件。その年の伝統と地形を使う。
- 既にある部品の様式は、後の増築でも変えない。

D3で伝統が変わっても過去の部品の様式が変わらないことを、D2の時点から検査に入れる（§8 A10）。

### 3.5 同じ文化の中の個体差

同じ伝統で建つ建物でも、勾配・軒の出・窓の数・装飾の有無などは個体ごとに少し変える。変える範囲は伝統が許す候補の中だけとし、伝統にない系統は選ばない。

D1では個体差の比較画像は作っていない（利用者の判断で不要とした）。そのため、個体差が原寸で「別の文化」に見えてしまわないかは、D2の実世界画像で初めて確認することになる。

## 4. 地域への適応

### 4.1 入力にする値（記録にあるものだけ）

| 入力 | 由来 | 何の重みに効くか（例） |
|---|---|---|
| 敷地の傾斜 | 地形セルの `grade` | 段状基礎F4、石の土台F2、高床S07 |
| 水際・氾濫面との距離 | 地形セルの `surface`、形状の freshwater/sea | 高床S07、木杭F3 |
| 地点の変種 | `variants`（river/hills/coast） | 地区ごとの素材の傾向 |
| 年0の樹林の量 | 植生の初期パッチと段階 | 木造系（S01・S02、丸太・製材板）と、土・石系の比率 |
| 岩がちな面 | 形状の cliff／slope | 石材系（S04・S05） |

重みを変えるだけで、決定にはしない。例えば川辺だから必ず高床になる、という規則は作らない。

### 4.2 使わない値

鉱床、材の輸送、技術水準、交易の量。いずれも現行の記録に建築の出典として使える形で存在しない（D0 §3.3・§4.4）。

### 4.3 地区の伝統を決める時点

年0の確定した土地だけを使う。後年の整地（v8）や植生の変化で伝統を作り直すことはしない（それはD3の「適応による変化」として扱う）。

ただし、個々の建物の基礎・高床などの**敷地への適応**は、§5.3 のとおり**建設年の**地形を使う。整地後の平場に建つ建物が段状基礎を選ばないことはあり得る。

## 5. 記録・乱数・保存

### 5.1 文明の乱数を使わない

文法・伝統・建設時の様式は、すべて文明の乱数とは別の、決定的なハッシュの系列から作る。

- 文法：`hash('architecture-grammar-v1', worldSeed)`
- 伝統：`hash('architecture-tradition-v1', worldSeed, siteId)`
- 建設時の様式：`hash('architecture-birth-v1', worldSeed, buildingRef, 出典イベント)`（住宅は部品範囲も含む）

これにより、同じseedのv8世界と比べて、社会・経済・選択・災害・地形・植生・建物の位置と年は**完全に一致**する。差は建築の記録と描画だけになる。この一致は自動テストで確認する（§8 A27）。

### 5.2 記録の形（案）

```text
architecture: {
  policy: { id: 'architecture-policy-v1', vocab: 'architecture-vocab-v1',
            constraints: 'architecture-constraints-v1', useRules: 'architecture-use-rules-v1',
            envelope: 'architecture-envelope-v1', introducedYear: 0 },
  grammar: { seed, weights{軸→候補→重み}, shared{roofFamily, eaves, pitch, ornament} },
  traditions: [ { siteId, year: 0, choices{軸→候補}, adaptation{入力値, 補正} } ×3 ],
  births: [ { ref: { kind:'facility', siteId, id, civic?{style, constructionRecordId} }
                 | { kind:'housing', siteId, blockId, parts{from, to} },
              source: { kind:'built'|'expanded', year, seq?, recordId? },
              traditionRef, use,
              features{roofFamily, eaves, pitch, structure, wall, roofMaterial,
              foundation, window, entrance, ornaments[], palette, storeys},
              envelope{left, right, top},
              substitutions[] } ]
}
```

**記録の件数の不変条件**（読込で検証する）

- 確定した施設1件（年0の初期のhouseを含む）に、施設の記録が**ちょうど1件**。field・bridgeには0件。
- civicを持つhallの記録は `civic` 属性を持ち、その `constructionRecordId` はcivicの建設出典（`building-built`）と一致する。civicのないhallは `civic` 属性を持たない。
- 住宅街区の `built` と `expanded` の各イベントに、住宅の記録が**ちょうど1件**。部品範囲は重ならず、`[0, その年のhousingCount)` を隙間なく覆う。
- 記録の `source.year` は、施設なら確定した建設年（`placements` の `builtYear`）、住宅ならイベントの年と一致する。年0の初期の建物は、`createSettlementHistory` が `store(site, year)` で `buildingChanges` に記録している（`src/story/settlement-history.ts`、v2レビュー後に確認）。そのため施設の照合は、**そのIDが `buildingChanges` に初めて現れた年**を優先し、生成世界の `placements` の `builtYear` と一致することも確かめる。`buildingChanges` は状態の変化のたびにも追記されるため、照合に使うのは初出の行だけとする。civicの `building-built` 記録との突き合わせはこれとは別に行う。

**再計算による検証の契約**

建設時の様式は、ハッシュから再計算できる値でも**保存する**（D0 §8.1「表示時に生成しない」）。読込時は全件を再計算して一致を確かめ、一致しなければ保存全体を拒否する。v8では地形が年によって変わる（`resolveTerrainAtYear(world.terrainHistory, year)`）。そのため最新の地形で再計算すると、正しい過去の記録が不一致になる。これを避けるため、様式を決める関数と検証する関数には次の入力**だけ**を明示的に渡す。

1. 年0に確定した文法と、その地区の伝統（保存された値。読込時は年0の入力から再計算して一致を確認）。
2. **建設年の確定地形**。v8の親世界の所有とハッシュの検証を通った後に、`resolveTerrainAtYear` で建設年の地形を得る。植生は様式の決定には使わない（伝統の決定に年0の植生を使うだけ）。
3. 用途・敷地・出典イベント（記録の `ref` と `source`）。
4. 同じ地区で、その年までに確定した他の記録の `envelope`（§6.2の上空の判定）。
5. `policy` の各版（vocab・constraints・use-rules・envelope）。

これ以外（観測年、最新の地形、描画の状態、文明の乱数）は入力にしない。テストする場合は次のとおり。

- 整地の前後で建つ建物：作用年の前は元の地形、後は整地後の地形で決まる。
- 保存して再開、分割進行、一括進行で同じ結果になる。
- 改竄した記録（様式、部品範囲、出典年、envelope）を拒否する。

読込時の全件の再計算に1万年分の保存でどれだけ時間がかかるかを、A30で実測する。
- `substitutions` には、§3.3の制約で候補を置き換えた場合の元の候補と理由を残す。
- 技術の参照（`technologyRef`）はD2では常に空。D3で追加する。

### 5.3 年次の処理順

「v8の後に処理する」と「同時に確定する」の意味を、次の更新境界として定める。v8の確定済みの記録は書き換えず、v9全体として一度に公開・保存する。

1. 現在のv9の所有rootから、内包するv8の世界を取り出し、既存のv8の進行（非同期、`stopAtNewRecord` を含む）で**次のv8を不変の候補として得る**。この時点ではv9は何も変わらない。建築の記録はv8の進行に入力しない（一方向）。
2. 前の確定年の翌年から、候補の確定年までの各年について、正本の差分から新しい建設を列挙する。
   - 施設：その年に初めて現れた `placements`（`builtYear` がその年）。civicの有無もここで確認する。
   - 住宅：`housing.events` の `kind: built` と `kind: expanded`。
   - 同じ年の複数の建設は、地区→種別（施設→住宅）→ID→seqの順に処理する。前の記録の `envelope` が後の記録の入力になるため、順序は固定する。
3. 列挙した全件について記録を作り、§5.2の件数の不変条件と再計算による検証を通す。
4. v8の候補と新しい記録を包む**新しいv9の所有rootを1回で作る**。
5. 1〜4のどこかで失敗した場合は、例外にして前のv9の所有rootをそのまま保つ。v8の候補だけが進んだ状態や、記録の一部だけがある状態は、公開も保存もしない。

選択肢で進行が途中で止まった場合も、確定した年までだけを列挙する。未確定の年の建設を先に記録しない。

年0の初期の建物（初期のhouse等）は、v9の世界を作る時点で同じ手順の年0の分として記録する。

テストする場合は次のとおり。

- 年0の初期のhouseに記録がある。
- 一括進行と分割進行の結果が一致する。
- 選択肢で途中停止した後に再開しても一致する。
- 同じ年に複数の施設が建っても、順序と記録が一致する。
- 記録の欠落、重複、余分な記録がある保存を拒否する。
- 途中で失敗したとき、前のrootが変わらない。

### 5.4 保存形式（案）

既存の版の追加方法（v6〜v8）にそろえる。

| 項目 | 案 |
|---|---|
| 所有root | `architecture-production-world-v1`。v8の世界を内包する |
| 保存外形 | `format: namonaki-world-save`、`version: 9`、`schemaVersion: 1` |
| 保存キー | `namonaki-story-v9`。読込の探索順は v9→v8→v7→… |
| 描画版 | `generated-scene-v8` |
| 旧版 | v5〜v8 の読込・進行・描画・保存は変更しない |

**既存世界への途中導入はD2では行わない**（D0 §8.3の既定どおり新規世界のみ）。v8の世界を読み込んでも建築文化は付かず、従来の外観のまま進む。途中導入を可能にするなら、「J年より前は不明」とする境界の設計が別に必要になる。

### 5.5 容量

建設時の様式1件あたりの大きさと、1万年×3地区で建つ建物の件数の上限を、D2-b（§7）の時点で実測する。現行の上限（非圧縮16MiB、gzip保存4MiB）を超える恐れがあれば、軸の値を整数コードの組にする等の圧縮をその時点で設計する。件数の上限は今回のコード調査では確認していない。

## 6. 描画

### 6.1 語彙の移設

D1試作（`scripts/lib/architecture-prototype.mjs`）の描画を、採用した語彙だけ `src/architecture/` にTypeScriptで移す。

- 移した後、D1ギャラリーを再生成して**画素が一致する**ことを確認する（D1で受け入れた見た目を本番に移す際に崩さないため）。
- 描画の実装が二重にならないよう、ギャラリーの生成は移した後の `src/` の実装を使う形に切り替え、試作側の描画は削除する案とする（§9-5）。

### 6.2 本番の建物への当てはめ

D1は平らな仮の舞台に、決まった寸法で描いていた。本番では次の制約に合わせる。

- **確定した建物を描画の都合で移したり消したりしない**。敷地・位置・建設年はD2で一切変えない。
- **地面の判定と上空の判定を分ける**。
  - 地面：壁・基礎は確定した敷地の範囲に収める。現行の `drawGeneratedSceneReview` は施設の地面側を `withinFootprint` で敷地に切り抜いており、これを保つ。地面の衝突は既存の土地の検証の責任で、建築の記録では扱わない。
  - 上空：屋根・軒・高さが占める範囲（`envelope`：敷地からの左右の張り出しと高さ）を、建設時の様式の一部として決めて記録する。同じ地区で既に記録された他の建物の `envelope` と、同じ奥行きの帯で重なってはいけない。橋の床と水面の上にも張り出さない。前後に並ぶ建物の重なり（手前が奥を隠す）は、現行と同じく許す。
- **張り出せない場合の決まった代替**（`architecture-envelope-v1`）。建設時に次の順で試し、最初に収まった形を採用する。採用した段階を `substitutions` に理由 `envelope` として残す。
  1. 文化どおりの形。
  2. 深い軒を通常の軒にする。
  3. 勾配を1段下げる。
  4. 屋根の系統を、伝統が許す候補のうち張り出しの小さいもの（片流れR04・平屋根R05など）にする。
  5. 張り出し0・最低の勾配にする。

  5でも収まることは一般には自明ではない（同じ奥行きの帯で先にある記録の上空と重なる場合や、特殊な敷地の場合）。**5でも制約に収まらない場合は fail-closed とし、HOLD にする**。このとき、その年の進行は失敗として扱い、前のv9の所有rootを保つ（§5.3の5）。さらに縮めること、描画を省くこと、敷地を変えることはしない。D2の段階は通常画面に公開しないため、HOLDは試走と監査の中だけで起きる。HOLDの件数が0にならない限り、通常画面への公開（D2-d）はしない。

  代替した後は §3.3 の制約を改めて当てる（例：深い軒をやめた場合、深い軒の下の入口E3は成立しないので、伝統が許す別の入口に置き換え、これも `substitutions` に残す）。

  5まで下がった記録と、HOLDになった件数・場所は、実際の世界の比較画像（D2-c）の監査に残して報告する。多すぎる場合は描画の規則を見直す。後から建つ建物は先にある記録に合わせ、先にある記録を変えることはない。
- 原寸の試験（D2-c）には、住宅街区どうしが隣り合う場合、civicのhallの隣、水際・橋の隣を含める。
- 建物の高さの上限は、既存の同じ種別の建物と比べて大きく変えない。D1の規則では複数階は整形石・混合構造（S05・S06）に限られていた。D2ではこれに加えて、2階建てを会堂だけに許す案とする。
- 住宅街区は、既存の `drawResidentialRoofs` と同じく1棟ずつの並び（`variant`）を保ち、各棟に文化の屋根・壁・基礎を当てる。

### 6.3 損傷・廃墟

既存の施設・住宅には損傷・廃墟の状態がすでに記録される。D2の時点では、損傷は既存の表現（欠け・色）を文化の外観に重ね、廃墟は既存の文化に依存しない廃墟の輪郭で描く。文化ごとの廃墟の表現はD4で設計する。

### 6.4 描画は読み取り専用

描画・過去の観測・地点の切替・アニメーションから、建築の記録や乱数を変えない（D0 A28）。未来の年の様式を先に描かない。

## 10. 未確認・推測を含む点

- 地域適応の入力（§4.1）は、型の定義から存在を確認しただけで、地区ごとに実際どれだけ値が違うかは測っていない。値が地区間でほとんど変わらない場合、A02の「地形適応の差」が弱くなる。D2-aで200seedの集計をして確認する。

- 容量（§5.5）と1万年での建物件数の上限は未確認。
