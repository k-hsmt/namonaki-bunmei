# 名もなき文明 v0.6｜H4-D3 象徴的建築の比較と歴史モデルへの導入判断

**状態：DESIGN ONLY / Humanレビュー待ち。** 本PRは新規施設・屋根・都市形成条件・保存形式・デプロイ対象の本番描画を変更しない。画像はすべてテスト専用の架空案であり、自然進行の史実ではない。

## Humanレビュー結果（2026-11-06・優先する判断）

**A 大きな集会所・会堂：方向性承認。** 特に集会所の造形は好評。ただし320×180の都市全景では中規模の建物に見えるため、都市の象徴性を担わせるには建物と公共空間の**相対的な大きさ**を改めて評価する。

**B 中庭を囲む共同建築：方向性承認。** 共同性と静けさを表す大型建築候補として正式設計へ進めてよい。既存 `hall` の無条件変形・後付け改修はしない。独立施設としての建設や改修は、履歴根拠・物理敷地のレビュー後に限る。

**C 土塁・木柵の館：造形方向性は承認、自然建設は未承認。** 採用候補から除外しないが、社会的役割（共同管理施設なのか、特定の権限を持つ館なのか）と成立条件を先に定義する。現在の寄り合いを君主制の証拠とはみなさない。

**D 小規模な城塞：今回の案は不採用。城の導入全体を保留。** 建物サイズの城塞ではなく、城壁が画面の端まで続き、背景の山を切り崩して城がそびえ立つほどの**風景・地形スケール**が望ましい。後日の独立工程で、カメラの視野・背景レイヤー・山の改変史・城壁の連続性・専用土地占有・成立する政治／防衛の歴史から根本的に設計する。既存の65px幅ほどの城塞試作を拡大して流用しない。今回の比較画像のDは**却下された旧案の記録**としてのみ保持する。

**意思決定の境界：** A/B/Cの「外観・コンセプトが良い」は、全都市への一律配置や、新施設を自然建設させる承認を意味しない。次の独立実装はA/Bの施設履歴・描画・敷地の具体設計から始め、Cは役割と条件を固める。Dの実装・プロトタイプ再制作は当面行わない。

## 今回の問い

集落・村・町・都市の違いを見やすくするため、街の核となる象徴的な建築を採用すべきか。その場合、どのような建物が、素朴で静かで長い時間を感じる架空文明にふさわしいか。

答えは「都市になったから城が建つ」ではない。政治・交易・共同作業・防衛の履歴が実際に成立したときにだけ、その痕跡として建物を残せるようにする。

## 現行コードの事実と不足

- `src/story/settlement-history.ts` の既存kindは `house / field / hall / workshop / market / bridge / granary`。配置は固定11区画。建物の `id,kind,x,y,builtYear,condition,recordId` の履歴があり、`buildingChanges` から過去を再構築する。
- `src/story/society.ts` に `council`（寄り合い）の習慣はあるが、**政治権力・支配者・軍事的な必要性・城塞の建設許可**を表す独立台帳はない。寄り合いがあることを「城主がいる」と読み替えてはならない。
- `src/scene/model.ts` の `SiteObject.kind` と `src/scene/draw.ts` の描画種別には `manor,fortress,palace` がなく、過去保存データにも存在しない。
- `src/scene/housing-ground.ts` の `existingGround` は橋と畑以外では18×7の小さな固定矩形。現在の集会所などの**描画屋根の幅**と地表占有の正本は一致しない。新たに館や城塞を設置するには拡張敷地・河川・既存施設・住宅の再検証が必要。絵の上で置けても合法な土地利用を意味しない。
- 旧v2/v3からv4の移行、年次の再生、既存IDの保存を守る必要がある。新施設を過去に遡って補完しない。
- H3-D（丘陵・入り江の建築地表・道路の正本化）は未完了であり、今回の仮画像を建設可能地点の根拠にしない。

## 正式導入が承認された場合に**別PR**で必要となる設計

### 1. 建設時の情報を固定する

- 建物ID、建設年、地形・敷地、建築系譜・様式、用途の根拠となる確定イベントIDを持たせる。
- 既存の `hall` を将来の建設時だけ `courtyard` 様式にするのか、新たな `civic-courtyard` 施設を設けるのかを先に決める。
- **同じ建物の姿が規模分類で変わらない**こと。現在ある集会所を別の外観に改修するなら、明示的な改修イベントと `effectiveYear` が必要。
- 未記録期間の旧セーブから建築様式を推測して埋めない。

### 2. 物理的な建設許可

- 現行の18×7の施設敷地矩形を、象徴建築にそのまま流用しない。
- 原寸での屋根シルエット・敷地の外接矩形を別々に定義し、物理敷地は河川・住宅街区・既存施設・道路・公共空間の占有と整合させる。
- 未検証地形や既存施設との衝突時は建設をHOLDし、無断移設・住宅削除・川の埋立てを行わない。
- ゲート結果・見送り理由を監査可能にする。

### 3. 社会的な成立条件

- A/B：集会、分担、公共的な維持能力、交易・人口の安定など、既存の社会履歴から意味が連続する条件を調べる。**人口閾値だけで必ず建てない**。
- C：一定の継続的な権限・制度、資材と人員、既存の館の維持履歴などが必要。現行の `council` を君主制として扱わない。
- D：洪水・火災などの災害を防衛戦争として扱わない。外敵・衝突等の独立史実が存在しないうちは自動建設しない。

### 4. 史実・旧セーブ・時間旅行の保護

- 建設イベント→施設台帳→ `siteAt` → `snapshotAt` → Canvasという系譜をテストする。
- 建物ができる前、損傷・廃墟化・再利用後の見え方を確認。既存の役割を失っても物理的な建築はその場に残す。
- 同一seed、選択、過去観測、v2/v3/v4保存と再開で履歴・画素を再現する。建築を追加する際の保存形式変更が本当に必要か最小差分で調査する。

## Humanレビューで判断したこと・今後の確認

- **A/B/Cの外観方向は容認。Dの小規模城塞は却下、城導入は保留。** A/Bを優先して実装可能性を設計し、Cの社会的役割は別途確定する。
- 320×180の原寸を主に見て、世界観、風景の静けさ、街の中心性、屋根の認識しやすさを確認する。
- 史実の街の規模・用途と建築の役割が噛み合っているかを評価する。
- これらの候補があっても、住宅密度や道路が乏しければ都市らしさは不足しうる。その場合は象徴建築の追加だけで完成と判断しない。
