# v0.6 Milestone B / H3-A — 河畔の自然住宅建設と施設HOLD

**状態：Draft PR #17／Humanレビュー待ち。Milestone B全体は未完了。**

## 背景と今回の範囲

H1（住宅履歴）およびH2（保存・読込・Canvasへの投影）はmain統合済み。今回のH3-Aでは、年次確定時に住宅街区の建設イベントを発行する最初の経路を設け、後発施設との物理敷地衝突を防ぐ。

- v4住宅履歴を持つ新規／移行済みゲームにのみ適用。旧v2/v3の自然進行を変更しない。
- 年次確定時、既存施設の候補を決定した直後の土地利用を調査し、河畔住宅の建設を提案。
- `built` の固定イベント年、街区ID、敷地座標、住戸数、建築様式と原因記録IDを保存する。
- 川、既存住宅、**当年までに建設済みの施設**が同じ地表を占めたら建てない。屋根・樹冠の視覚的重なりは土地衝突としない。
- 後から固定位置に施設を建てようとして既存住宅の敷地を使う場合は施設だけHOLD。別候補地へ自動移動せず、廃墟を含む住宅を消さない。衝突で施設建設を見送った年も、共同体の変化など他の確定観測は保持する。
- 未来施設のために土地を過去から予約しない。**すでに成立済みの住宅を優先し、後発施設がHOLDする**。

## 適用地点

| 地点 | H3-Aの自然建設 |
|---|---|
| 河畔（river-bank） | 安全な候補が存在し、建設条件を満たす場合だけ許可 |
| 丘陵（hill-side） | 地形検証未実装：常にHOLD |
| 入り江（coast-inlet） | 地形検証未実装：常にHOLD |

共通の既存施設衝突は `facilityHousingConflicts`、住宅・施設・河川衝突は `findHousingGroundConflicts` を利用。現在の敷地モデルは固定座標上の矩形＋河川ポリゴンであり、まだ道路・港・斜面の占有台帳はない。実装対象地点を広げる前に地形を正本として検証する。

## 住宅の建設判断（H3-A暫定規則）

- 河畔の人口900以上、60年周期の確定年のみ建設候補を検討（初年度除外）。
- 同じseed・年・住宅履歴・施設履歴なら候補と結果は同じ。建設用に乱数状態を消費しない。
- 候補の物理敷地は18×8px。表示の屋根外形・部品数はH1の既存導出を利用。
- 遠景・中景・前景に広がる複数の地表候補を走査し、最初に条件を満たした場所を採用。街区の正本は `housingCount` と建設イベントにあり、屋根数は正本ではない。
- 候補がない場合は **HOLD（建設イベントなし）**。街区の総数上限は設けない。ただし現時点では有限の候補グリッドを用いるため、候補枯渇で建設が止まり得る。これを「都市の正式な街区数上限」と扱わない。
- 既存人口計算は変更せず、住宅ストックを人口の推定値として逆算しない。住戸数は描画・履歴の試作用に独立に決定する。
- 建設原因は通常の記録台帳にIDで保持する。旧移行境界より前に住宅建設イベントを追加しない。

**制約：** 今回の人口閾値・60年周期・候補グリッドは検証可能なH3-Aパイロットの仮規則であり、自然進行の本格的なゲームバランスとして承認されていない。街区数と都市景観の品質を保証するものではない。

## H3-B以降で分けて実装する事項

1. 住宅 `underused/vacated/damaged/ruined/repaired/reused/expanded` の発生条件と原因記録。H1の許容状態遷移だけを用い、規模縮小から廃墟を即時生成しない。人口減少・既存施設の低利用と住宅利用状況を混同しない。
2. 施設建設HOLDの長期監査・UI表示、開発候補座標の選定、地形が未検証の丘陵・入り江への適用、道路・河岸との関係。
3. 旧セーブ再開・選択待ち・10,000年の容量・描画視認性を含む長時間回帰。現状では旧形式の自然進行を変更しないためのゲートを保っている。
4. ミルストーンA相当の都市シルエット評価はH4へ分離。住宅街区を勝手に増設してシルエットの不足を補わない。

## 検証観点

- 新規v4の同一seed・同一選択で同じ住宅イベント／人口・施設／描画が再現する。
- JSON往復後も、後年の住宅建設イベントと固定敷地・建設年を再生成しないで再利用する。
- 住宅建設前の年は画面にその住宅を描画しない。
- 施設建設の固定候補地が既存住宅と衝突する場合は施設だけHOLD。廃墟でも地表を占有する。
- HOLD時も共同体・人口・他の観測を欠落させない。
- 未対応地形の建設はHOLDし、同じ土地を複数施設や住宅に割り当てない。
- `npm test` と `npm run test:browser` を独立Draft PRで確認してからHumanレビューを依頼する。
