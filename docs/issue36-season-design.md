**初版の対象**：7バイオーム・3地区・植物13系統・地表材・遠景・実在する屋根と樹木への積雪。静止画と12fps上限の動く景観の一致、過去観測・保存再開。
**対象外**：食料・人口・経済・災害・土地改変・植物の年次生育値への季節効果、月や日、半球、降水量・積雪深の実測、凍結による通行変化、雪害、新しい施設や行事、季節を手動変更する本番UI。雨雪の降下粒子アニメーションはD1結果を見て別判断。

## 2. 時間の意味と確定境界

初版では `seasonPhase = confirmedYear mod 4`（0：芽吹き相当、1：繁茂相当、2：衰退／紅葉相当、3：休眠相当）を版付きの**観測位相**とする。年0は位相0とする。これは**1年に1季節しか存在しないという自然史ではない**。毎年の代表的な景観を4年周期でサンプリングする表示上の抽象化である。現実の「四季が4年で一巡する」ことを主張しない。

- 表示の年は確定済みの `lastObservedYear` または過去観測の年。選択待ちの未確定年を表示に使わない。
- 同じ年の川辺・丘陵・入り江では位相を共有するが、地域の局所環境で見え方は異なる。
- ゲームが停止すれば位相も停止する。風による木の揺れ・水面・人の歩行は既存の秒時計で動いてよい。
- 進行が36年など複数年をまとめて確定させた場合、中間年の季節を表示したことにしない。最終確定年の位相を表示する。
- 過去観測ではその年の地形・建物・長期気候・植生のみで投影し、現在の情報を混入させない。
- **Human回答：UI上で抽象化の説明はしない。** 4年間で一巡する代表景観という意味は設計・テスト文書にのみ記す。月・日・実在する年内季節のシミュレーションと誤認させる機能は追加しない。季節名を画面へ出す必要はD1で改めて確認し、表示する場合も説明文・新しい操作は増やさない。

## 3. 表示計算の正本と責務

入力は現行世界の確定状態（seed、年、地区、terrain、実在する建物・屋根、`WorldClimateBaseline`、当年の長期気候偏差・局所環境、`FloraPatchView`）。描画のために新しい植物・屋根・地形を生成しない。

概念的な計算境界：

```ts
type SeasonPhase = 0 | 1 | 2 | 3;
interface SeasonalView {
  ruleId: 'season-presentation-v1';
  phase: SeasonPhase;
  // それぞれ表示上の指標。単位・範囲はD1で校正。
  temperatureAccent: number;
  moistureAccent: number;
  snowPotential: number;
}
function seasonalViewAt(confirmedYear: number, climate: WorldClimateBaseline, deviation: Readonly<{temperature:number;humidity:number}>): SeasonalView;
```

上記は**概念型**であり、本実装のAPIと定数をD0段階で固定しない。`WorldClimateBaseline` の `annualTemperatureRangeIndex`、`rainfallConcentrationIndex`、`effectiveTemperature`、`effectiveMoisture` と、#34の当年相対偏差を使う。相対指標は°C・mmではない。季節の表現に使う偏差を、#34の環境stateへ書き戻さない。

強制4位相は**開発用比較の表示入力**としてのみ許す。現行世界の保存、文明RNG、年次状態へ格納・作用させない。決定的な局所模様には地形ハッシュ等の専用名前空間を使い、文明用RNGを一度も消費しない。

## 4. バイオーム・植物の応答

共通の4位相を、地域の気候と植物系統へ投影する。7分類すべてを日本型の四季にしない。季節変化の強さは年較差・降水集中・現在の寒暖乾湿に従うため、4位相が似た外観となる世界も許容する。

| バイオーム | 優先したい季節差 |
| --- | --- |
| 温帯林 | 落葉樹の芽吹き・深緑・紅葉・枝の露出。常緑木は残す |
| 亜寒帯林 | 長い寒冷期・針葉樹の雪、短い生育期 |
| ツンドラ | 低木・草本・苔の短い生育期、地面の雪と露出 |
| 熱帯雨林 | 主に降水集中・湿った地面・葉量の小さな差。機械的な紅葉はしない |
| 草原 | 草の緑化・黄変・休眠、疎林木はその種に応じる |
| ステップ | 限られた緑化期と乾草・裸地、寒暖差に応じた冷え込み |
| 砂漠 | 基本は疎らで乾いた景観。降水が少なければ季節差も少ない |

植物13系統（落葉・常緑・針葉・熱帯・疎林・河畔の各樹木、乾燥・寒冷・一般低木、草本・林床・湿地・苔類）の現実的な応答を別表としてD1で作成する。落葉樹の休眠は**葉を隠して枝を表示**するが、樹齢・`FloraStage`・根・パッチ占有を変えない。休眠は枯死でも生育後退でもない。#34の長期寒冷による葉の衰退と二重適用しない。

既存`flora-scene-v1`の植物根元・疎密・配置・A/B描画混合・成長段階を再利用する。季節表現は両方の植物描画器に適用。存在しない樹冠を季節で追加しない。紅葉等は種・その年の条件から導き、全画面一律の彩度変更としない。

## 5. 地表・積雪と形状

現在の6地表材（砂、岩、裸土、落葉、湿地表、寒冷地表）は正本のまま。季節の落葉・雪・湿潤色・乾草は描画レイヤーとして重ね、地表材IDや土壌負債を書き換えない。季節積雪は実地形の陸地を対象にした視覚マスクで、川・海・建物・歩行可能領域を変更しない。

積雪は共通の表示上の雪ポテンシャルを参照しつつ、**各物体の形状に応じて**描く。

1. **地表**：安定陸地と地表材・斜面から雪面を生成。薄い積雪では土・岩・草が残る。建物・橋・共同空地・水路等への重なりは、実際の占有と描画順を尊重し、場当たり的な全面塗りをしない。
2. **屋根**：住宅屋根部品・施設の実際の描画形状から積雪可能面を提供する。色検出や建物全体の矩形に雪を貼る方法は不可。破損・廃墟・建替えをその年の正本から読む。屋根がなければ屋根雪は描かない。共通の`roof snow surface`インターフェース案はD1の形状検証後に確定。
3. **樹木**：針葉樹は枝・葉群の上辺、落葉樹は露出した枝など、季節適用後の実際のスプライトに沿って雪を置く。幹・根元位置は不変。樹冠の1px揺れに雪も追随する。樹木が無い場所には枝雪を描かない。

**既存の遠景の雪線（#34）を保持し、季節雪と二重描画しない。** 遠景の形状は既存の山ポリゴンのまま。地表・屋根・枝の雪は気候条件を満たす場合に限る。積雪と路面の通行性・氷結・災害の因果関係は初版に存在しない。

## 6. 描画順序と季節演出の接続点

現在の主な責務：`src/flora/flora-scene-v1.ts`（植物の実体画素）、`src/scene/flora-draw.ts`（地表材と植物の前後分割）、`src/scene/draw-generated-review.ts`（地形、建物、施設）、`src/architecture/scene-v1.ts`（建築様式）、`src/scene/motion-frame.ts`／`motion-player.ts`（静止・動的画面とキャッシュ）。

順序の原則：
- 正本地形・水面 → バイオーム色と地表材 → 季節の地表表現。
- 建物背後の植物とその枝雪 → 人物・活動 → 実際の建物と屋根雪 → 建物手前の植物とその枝雪。
- 実際のコード上の橋・水路・施設の合成順序は保ち、簡略な新規レイヤー順に無理に置き換えない。
- 植物の前後判定は**季節変化後の不透明画素**と既存の`structureGroundLines`を使用。落葉後に存在しない葉が建物を隠すことを禁止。
- 屋根雪は建物自身のレンダリングと一体に合成し、手前の植物による遮蔽を維持。形状情報の提供は現行`GeneratedStructurePainter`の責務を拡張する案。描画色を見て屋根を推測しない。

本番画面で季節を操作する入力は作らない。静止画も動画も同じ`SeasonalView`と共通の物体描画ルールで生成する。静止画で雪があるのに動く景観ではない、という状態を拒否する。

## 7. 短く穏やかな年次遷移（Human B案）

**年次が確定した時点で、内部の季節・世界表示は直ちに新年の値となる。** 演出は描画専用・短時間・キャンセル可能で、文明stepを遅延させない。遷移時間の初期比較は例として150／250／350ms。最終値はD1の実機観測で選ぶ（固定済みの仕様ではない）。

**新年の地形・建物・植物正本を固定したまま**、旧位相の季節表現から新位相の季節表現へ遷移させる。同じ年の異なる表示条件だけを重ねる。前年度の完成フレームと新年度の完成フレームを単純にクロスフェードすると、消えた建物が一瞬残る、建物が二重に見える等の歴史の捏造が起こるため禁止。可能なら季節依存の色・葉・雪だけをアルファ／段階的置換し、地形・建物の正本画素は新年に固定する。

- 通常速度では短い遷移。**高速・連続進行では中間演出を省略**し、最新確定年に対応する完成景観を優先する。遷移をキューに溜めない。
- **高速進行時のちらつき防止（Human重点）**：年次確定のたびにキャンバスを強制更新せず、描画要求を1件に集約して観測画面の更新頻度を制限する（間隔・方式はD1実測で決定）。更新間に確定した年を全部描かず、最新の確定年の**完全なシーン**のみ表示する。表示中のシーンの年と年ラベルは同期させ、実際より先の景観を表示しない。
- 更新間隔を制限しても季節による強い色差のフラッシュが残る場合は、D1で高速中の季節描画の抑制度合い（更新をさらに間引く／一時停止まで完成シーンの表示を保つ等）を比較しHumanレビューへ出す。**画面を暗転させる・独立した季節時計を動かす・過渡状態を保存する**ことでは対処しない。
- 高速進行を止めた時点で、保留中の描画要求を破棄・更新し、**最後に確定した年の完成景観**へ速やかに整合させる。明滅回避より確定史の正確さを優先する境界とする。
- 新たな年次確定、観測地点変更、過去観測、保存読込、ブラウザ非表示で遷移を破棄し、目標年の完成画像へ直ちに整合させる。
- 過去観測・再読込・静止画モードでは、過去から現在への演出を再生せず指定年の完成画像を示す。
- `prefers-reduced-motion`、既存の動画停止設定、非表示タブ停止を尊重し、必要なら遷移なしの即時更新とする。
- フレーム時刻・描画回数・速度選択は文明の履歴、RNG、積雪・葉の**最終形**を変えない。
- 季節位相と、結果へ影響する気候指標・局所描画パラメータをキャッシュキーへ含める。季節が変わるだけなら年次物理・ルート探索を不要に再計算しない。描画キャッシュは更新内容を実測し設計する。

## 8. セーブ・版・互換

季節は現行年と既存気候履歴からの導出値であり、**年ごとの季節履歴や壁時計・遷移途中の値は保存しない**。演出の秒数や再生途中の状態も保存しない。季節の表示規則は`season-presentation-v1`等の版付き契約として現行世界に結びつける（格納場所は本番接続時に決定）。

現行の通常世界は`namonaki-world-save` v10・schemaVersion 2（気候と植物の記録）。新しい景観規則を導入するときは、現行保存の内部整合性と再現性を守り、必要なら**現行保存契約を明示的に更新**する。旧v9や古いv10 schemaへの互換アダプタを増設する義務はない（`AGENTS.md`）。既存世界の過去を無断で補完せず、読めない場合は明示して保存値を勝手に削除しない。

D0文書だけで保存version、schema、デフォルト世界を変更してはならない。

## 9. D1比較と合否基準

1. **基本比較**：7バイオーム×3地区×4位相＝84景観（最低限）。同一seed・同一年・同一物理世界に開発用の位相だけを重ね、原寸320×180と拡大nearest-neighborを両方出す。7種の代表seedのほか複数seedの自然生成差も試す。
2. **時代比較**：0／100／1,000／10,000年等、同一地区で成熟木・新築・廃墟・地形改変が異なる年を使い、各年の自然位相と強制4位相を比較。表示試走と自然史を区別。
3. **積雪境界**：屋根形状ごと（住宅・大建築・破損・廃墟）および常緑／落葉樹、河畔・丘陵・入り江、鏡像地区。雪の漏れ、欠けた屋根への描画、前後関係、雪線の二重化を点検。
4. **進行・UI**：年0/1/2/3/4、99/100、通常／高速、未確定選択、停止、地点変更、過去観測、再開、reduced-motion、動画停止、非表示復帰。**高速再生を画面録画で比較**し、色差の大きい4位相を繰り返す条件、短時間に複数年確定する条件、停止直後に年・年ラベル・景観が同期する条件を検証。1確定年ごとに画面全体が交互に明滅しないよう更新頻度と合成方法を検証し、評価はPCとiPhoneを含む実機で行う。UIに4年周期の説明文は出さない。
5. **非干渉・決定性**：同じseed・選択で季節OFF対ONの文明state・RNG・施設・地形・経済・植生の年次履歴・保存再開が同一。最終画像は同じ年・位相・設定で同一。途中描画時刻は保存と歴史へ影響しない。
6. **性能**：静止画準備・描画、動的準備・12fps、遷移開始・取消を個別に計測。既存の描画性能監査の閾値を守り、屋根mask作成や植物画素分割を毎フレーム全件再計算しない。閾値・機種は既存監査に合わせて記録。

Humanの視覚評価では「季節が明瞭」「バイオームごとの自然さ」「素朴さと静けさ」「建物や植物の履歴が分かる」を個別に判定する。**見た目が弱い場合、無根拠な全画面フィルタで補わず、植物系統・葉量・地表・積雪配置を見直す。**

## 10. 実装工程の案と今回の停止線

| 段階 | 成果物 | 禁止する早期変更 |
