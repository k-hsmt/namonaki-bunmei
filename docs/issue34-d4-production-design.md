# Issue 34 D4-C0：丘陵の小規模整地を本番化する契約

## 採用案と根拠

D4-Bの5世界・各1万年では14件の合法な整地が成立し、1万年時点で11件は建築利用、3件は未耕作の平場だった。耕作例はなく、収穫・人口・選択・RNG・災害・水路は全世界一致する一方、3世界で配置、2世界で出来事に間接的な差が出た。[比較結果](issue34-d4-terrain-comparison.md)を根拠に、初版を**丘陵の小規模な切り土・平場の準備**として本番化する案とする。「段々畑を増やす機能」とは説明しない。

独立比較と同じ条件を固定する。26×14px、2px格子、最大切下げ2相対単位、1pxの段状apronと2pxの影響域、640セルの安全予算、水際4px、既存占有・予約・到達性の保護。継続50年以上の確定した丘陵の畑を出典に100年境界で判断し、500年の間隔・最大4件、改変前に畑として不成立／改変後に成立する候補だけを選ぶ。承認Y年は元の地形、Y+1年から新しい地形と実際の植生攪乱を使う。工事成立で畑を自動追加しない。

切り土の本番規則名は `terrain-cut-v1`。A3の `terrain-cut-review-v2` と幾何・判断順序・年次効果は同じで、A2の旧v1の幾何へ戻さない。規則IDだけに依存した分岐を整理し、旧review-v1、review-v2、本番v1をそれぞれ固定して再検証する。

これは本番接続の設計・実装案であり、Bの景観判定や最終の通常画面の受け入れを代行するものではない。統合の最終判断は利用者の景観確認・PRレビューに残す。河川・海岸・盛り土・大工事、#34全体のクローズは対象外。

## 初版の経済負担を明示する

初版は**追加の掘削費用・直接収穫ボーナスとも0**とする。`small-cut-no-direct-economic-effect-v1` として保存し、readerがこの固定値を検証する。D3の水路の収穫／維持負担は引き続き完全に持ち越す。

相対標高×セル数は労働時間・土砂体積・生産規模を表しておらず、それを任意のbpに換算する根拠がない。14件で農地が自動的に増えていないこと、最大4件・500年間隔の小規模な準備であることを採用範囲とする。工事が経済的に無料だと実証したものではなく、労働の機会費用をまだ表現しないモデルである。森林等の攪乱と、その後の実際の敷地・通行・土地利用の変化は省かない。

追加費用や収穫効果を入れる次版では、専用規則と新しい導入境界・比較を必要とし、既存v8の将来へ無断で適用しない。D3の水路費用へ切り土の費用を紛れ込ませず、合法な敷地増と直接収穫加算を二重計上しない。

## 本番worldと保存形式

| 項目 | 本番契約 |
| --- | --- |
| 所有root | `terrain-production-world-v1`、`status: production`。試走rootとは別のWeakSet／packet cache |
| 土地の永続境界 | `terrainPolicyBoundary: terrain-development-v1`。旧B・C2・C3入口が無断で除去しない |
| 進行・保存台帳 | `terrainDevelopment`。試走の `terrainChanges` は本番rootに置かない |
| 共通保存外形 | `format: namonaki-world-save`、`version: 8`、`schemaVersion: 1` |
| 描画契約 | `generated-scene-v7`。同年の実地形・記録済み植生・歩行を使う |
| 履歴wire | `terrain-history-v1`、確定イベント・基準hash・確定年・作用前commitを保持 |
| 起点prefix | 本番専用の `terrain-production-origin-prefix-v1`／`terrain-production-origin-ref-v1` |
| current参照 | 本番専用の `terrain-production-environment-checkpoint-ref-v1` |
| 保存キー | `namonaki-story-v8` |
| 経済規則 | D3 combinedを継承し、`small-cut-no-direct-economic-effect-v1` を別に固定 |

v8は完全な世界1個を保存する。初期地形はそのまま保持し、解決済みラスタを旧v1 validatorへ偽装しない。過去のv7起点は初期地形・append-only台帳の不変prefixを現在の本体へ参照し、小さいscalarと起点hashだけを保持する。D3の元のv6起点と、D3導入以来の全経済証拠も保持する。全originの二重保存、過去の年代記・経済・環境履歴の削除はしない。

初期地形や内部の不変な地形履歴は中立な結果データとして共有できる。共有してよいのは純粋な幾何・年次計算・native意味検証・同年の投影処理であり、試走のworld／public runner／public codecを呼んで本番へ昇格させない。正本worldとpublic factory、wire、ownership、保存先の境界は別にする。

専用試走のformat、renderer、永続境界、origin dialectを本番readerで受け付けない。本番らしい外側にしただけのadapterやcloneも、所有cache・永続境界・起点証拠・完全な意味検証を迂回できない。これは全文明抽選の真正性を証明する仕組みではなく、既存C3と同じ記録検証の限界を持つ。

## 既存世界と新規世界

本番導入の入口は所有済みv7の確定年J、pendingなし、J<10000。v7を読み込んだだけでは導入しない。v5／v6も元の計算・保存を維持し、既存の水路／経済導入を飛ばしてv8にしない。

`introduceTerrainProduction` はJ年の完全v7を確定・hash化してから、新しい不変rootを作る。J以前の地形・敷地・植生・経済・選択・RNG・画像を保持する。最初の工事判断はJより未来の100年境界で行い、J年に直ちに工事を承認しない。pending／10000年では導入できない。保存済みの未作用commitは再開後にも一度だけ作用する。

新規既定は最後のC2で `createNewTerrainWorld` へ切り替え、年0から導入する。`createNewWorld`／`createNewIrrigatedWorld`／`createNewEconomicWorld` は各世代の比較・旧保存用factoryとして意味を保つ。スタートごとのランダムseedは1操作につき一度選び、非同期処理の再試行で別seedへ変えない。

導入そのものが過去を変えないことと、導入後に利用者が明示的に選ぶ既存の景観／気候upgradeを区別する。元の景観版・気候導入年を保持し、気候の新しい切替はD4導入Jより未来の100年境界に限定する。景観の明示upgradeは従来と同じ表示上の契約を保ち、経済・地形を変更しない。

## 年次進行と非同期のUI

本番v8にも一つの非公開な年次batchを使い、工事のhash確定を待ってから次の年へ進む。経済・選択・建築・水路・環境の年次順序と、旧v5/v6/v7の同期進行は変更しない。

通常sessionにv8の所有rootを加え、`advanceWorldSessionAsync`／`chooseWorldSessionAsync` を設ける。旧世界は既存の同期処理へそのまま委譲する。従来の同期APIへv8を誤って渡した場合は明示的に拒否し、初期地形の旧Bへ落とさない。

UIは進行・選択・導入・新規生成・保存・importの間にbusyと操作番号を保持する。awaitの後に元のworldと操作番号を照合し、古い結果を別世界へ適用しない。自動進行と自動選択も同じ入口を使う。BGMの利用者ジェスチャーによる初期化はその場で行い、世界のawaitの後へ移さない。

「丘陵の整地を導入」は確定したv7だけに表示し、過去を保って未来の地面・植生・配置が変わることを説明する。追加収穫と追加工事負担を加えないことも導入の説明で区別する。導入完了とブラウザ保存成功を混同しない。観測年の工事件数・準備／耕作／耕作終了／別用途の利用は正本から表示し、未成立の畑を作らない。

## 保存・読込・失敗時の保持

共通async reader／gzip envelopeは版8だけを新たにdispatchし、外側と内側のversion／modeを照合する。同期validatorで受け付けるv8はnative検証済みpacketだけ。初期地形、差分前後値、親子hash、作用年、同年の占有・到達性・出生時の敷地、植生出典、v7起点、元のv6以来のD3全経済／phase／環境を検証してから所有する。

native読込・再書出しで、新しい地形／水路候補の探索、年次writer、world／気候producer、RNG nextを呼ばない。指定された保存工事の局所再検証は行う。保存された探索の全棄却候補・最良性を網羅証明したとは扱わない。

検索順はv8→v7→v6→v5→旧キー。最初に存在する保存が破損していれば停止し、古い世界へ黙って戻さない。unknown版・混合envelope・試走保存も拒否する。v8を導入・保存しても旧v7キーは保持する。importは検証と表示確認だけではキーを上書きせず、利用者が保存して成功した後にだけ古い優先キーとの競合を解消する。特にv7等の明示importを保存する場合、成功前に既存v8を削除しない。

容量不足・native検証失敗・非同期競合では現在のrootと旧キーを保持する。完全なJSONの書出しを可能にし、一部の履歴を削って保存成功に見せない。plain16MiB、gzip保存用JSON4MiB、最大4件と差分予算の容量確認を継続する。古い形式の上限やfallbackの意味は変えない。

## 実装と受け入れ

C1は本番の正本・年次・reader／codecと共通保存dispatchまで。通常の新規既定と自動migrationはまだ変更しない。中立な内部処理を抽出し、試走と本番の入口・所有を分ける。C2で通常session／UI・新規既定・保存競合処理を接続する。

必須確認は次の通り。

- Bで固定した5世界の意味世界・経済tuple・phase・工事内容に本番が一致する。規則名と連鎖hashの差だけを許し、幾何・cause・年・実変更セルを省かない。
- 旧v5/v6/v7の固定参照と将来、途中J導入の全過去・3地区の画素が不変。D3の経済導入年がD4導入年と異なる例、pending／10000年、Y/Y+1、J/J+1、99/100、手動／自動／分割／gzip再開が一致する。
- native本番・試走それぞれでproducer・progress・候補探索・RNGを遮断した読込／再書出しが成功する。hash再計算後のセル・出典・規則・checkpoint変更は拒否する。cloneや本番風adapterをpublic writerが所有済みと扱わない。
- v8／v7共存、破損優先キーの停止、import後の明示保存、quota失敗と完全export、非同期の古い結果の不採用をブラウザで確認する。
- 通常画面で過去年・整地の件数と利用・新規seed・動く景観・Safari／BGMを確認し、通常v7とv8の最終比較・動画を提出する。
- 年次とhash／gzip込み5秒／25秒、D3比2倍、中立比1.10、plain16MiB／gzip4MiB、PC／CPU4倍の46条件の描画p95≤83.3msを維持する。初回native読込・観測・素材準備の重さは別に残す。

全互換・性能・保存・通常画面の検証結果と景観の受け入れを揃えて、D4の小規模整地を統合する。D4-Bだけの完了をD4全体の完了とはしない。
