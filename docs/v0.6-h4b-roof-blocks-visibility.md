# v0.6 H4-B｜歴史上の住宅街区を一体的に見せ、施設の視認性を守る

**状態：Draft / Humanレビュー待ち。H4-Aの固定履歴比較画像をBefore基準とする。**

## 変更範囲

`src/scene/draw.ts` の表示処理だけを変更する。住宅・施設のID、建設年、住宅数、地表の敷地、人口、年次イベント、保存形式、乱数状態を変更しない。

1. **街区の連続性：** `SceneComposition.residentialBlocks` に記録された住宅の `footprint` の**内側のみ**に地面の輪郭、一本の内側通路、軒先をつなぐ色面を描画。状態 `occupied/underused/vacant/ruined` による材質差はあるが、存在しない新しい建物・道・公共施設を追加しない。
2. **施設の読みやすさ：** 従来は `far住宅→middle住宅→施設→near住宅` で、前景住宅が市場・工房などに重なり得た。新順序は `far住宅→middle住宅→near住宅→確定施設→橋`。物理敷地が重ならなくても屋根の投影が施設の脚・輪郭を隠す問題を減らす。
3. **歴史の連続性：** 屋根部品の位置・様式は `housingAt` と `composeScene` が確定したもののみ。表示上の規模が変わっただけで住宅が生えたり消えたりする処理は追加しない。未記録の旧セーブには住宅床面を描かない。

## 検証

- `tests/browser/h4b-facility-visibility.test.mjs`：**物理敷地が衝突しないが屋根だけが市場の脚に重なる**固定fixtureを作成。住宅履歴あり／なしの市場の脚をピクセル比較し、既存施設の輪郭が保持されることを確認。
- H4-Aの四段階固定fixtureを同じカメラ・seedで再生成し、`artifacts/h4a-visual` に「After」比較画像・出典JSONを保存。BeforeはPR #20の `visual-a-comparison` artifact と比較する。
- 規模分類だけが変わった場合、`residentialBlocks` の座標・屋根数・代表住戸数が変わらないことを検証。
- 既存H1/H2/H3ブラウザ回帰、過去視点・セーブ再開・旧セーブ互換性、10,000年監査をCIで継続。

## Human受入基準

- 320×180の原寸で、集落→村→町→都市の各風景に違いが感じられるか。固定画像にラベルは重ねない。
- 建物が孤立して点在するだけでなく、住宅の集まりとして読めるか。
- 市場・集会所・仕事場・橋が住宅の屋根によって識別不能にならないか。
- 同じ街区が規模変更で唐突に様式変更しないか。
- 景色が美しくなっても、歴史にない建物や架空の道路が足されていないか。

**限界と次工程：** 今回の通路は街区内の表示であり、地点全体をつなぐ道路網をシミュレーション上の歴史として記録するものではない。道路・広場の接続や画素単位の表現品質、人間による四段階識別率の最終確認はH4-Cで行う。H3-Dの丘陵・入り江自然建設はHOLD維持。Milestone B未完了。
