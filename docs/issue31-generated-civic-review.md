# Issue #31 D3-B大型公共建築段階

前提：#55の住宅3地点対応。状態：**大型公共建築の独立自然進行・台帳検証まで。本編とv5保存は未有効化。D3-B全体は未完了**。

## 接続と確定順

`generated-civic-review.ts`は、既存通常施設を確定した後、同年の住宅建設より前に各地点のcivicを判定する。
独立APIのformatは`generated-civic-review`とし、通常施設のみ・住宅のみ・旧固定経路へ黙ってdispatchしない。
人口計算・食料・災害・経済・RNGの計算を変更しない。

社会条件は既存`proposeCivicConstruction`に合わせる：40年周期、人口4,500以上、coverage≥.94、shortageYears=0、交易3年以上。
既存の健全な通常hallが24年以上前に建設され、同じ起源のcouncilが24年前・現在・途中の全practiceChangesで有効なことを要求する。
同じ地区にcivicが既にあれば新築せず、古いhallを置換・拡張しない。成立しない場合は理由をHOLD診断へ記録する。

様式は既存のgreat-hall／courtyard-hallのみ。seedによる既存の選択計算を維持し、敷地は44×22／56×30。
地形の平坦条件・水面・全占有・Q5の試走予約・幅2pxの通行・既存入口切断を共通ゲートで検査する。
スコアに既存hall入口への距離と、最寄り確定住宅入口への距離をそれぞれ加える。
下限探索と全候補参照探索が同じ大敷地・入口・スコア・経路を返す反例テストを追加した。

全ゲートを通過した場合だけ、年代記・現在view・buildingChanges・外側placementsへ一緒に追記する。
IDは既存川辺形式を保った`civic-SITE-YEAR-STYLE`。敷地・様式・建設出典は初回建設時に固定する。
後年の通常施設と住宅はcivic敷地も実占有として避け、損傷・修繕・廃墟化で位置を動かさない。
過去年への追記や、元のhallへcivic属性を後付けする操作は認めない。

## 旧保存との境界

`validateCivicBuilding`は明示site引数を省略すると従来の川辺限定のまま。
`validateCivicLedger`も既定は`legacy-fixed`で、既存v4読込は変更しない。
新しい独立APIだけが`generated-review-only`を明示し、地区別のID・初回状態・建設年・出典記録・全遷移・現在viewとの一致を検査する。
過去のcivic情報や建設年を旧保存へ推測補完しない。

新築直後と、進行／選択から返る直前に台帳を検査する。返却時の上限はlastObservedYearで、選択待ちの未確定年と区別する。
損傷・修繕の後でも、敷地・様式・初回出典が履歴途中で変われば拒否する。
これは新規v5保存の未知JSON全体validatorを完成させた意味ではない。正式な保存・読込・UIはD4-Bに残る。
