## 実装した範囲

| 系統 | 形状の違い | 土地の違い |
| --- | --- | --- |
| H01 片側の長い丘 | 片側の高地から長い裾へ下がる | 反対側に連続する低地 |
| H02 二つの丸い丘 | 離れた二つの高まりと鞍部 | 丘の間と裾を通る |
| H03 広い谷底 | 両側の丘が中央の広い谷を挟む | 谷沿いにまとまった平地 |
| H04 緩い台地 | 広い上面と手前の斜面 | 上面・裾の二層 |
| H05 連なる低丘 | 三つの小さな起伏 | 低い丘の間に平地 |
| H06 斜めの尾根 | 奥右から手前左へ続く尾根と鞍部 | 尾根を横断する間隙 |
| H07 河岸段丘 | 二段の平坦面と斜面帯 | 上段・下段・裾の建設帯 |
| H08 岩のある狭い谷 | 岩壁が挟む折れた低地 | 岩壁は非建設、中央が候補 |

形状・標高profile・ピクセル中心ラスタ・相対標高・4近傍の標高差から求めるgrade・岩盤ラベルを生成する。
描画の地表は同じラスタを使う。景観の色は広い標高帯で塗り、丸めでgradeが交互になる縞模様は描かない。
物理診断画像は平坦／緩斜面／急斜面／岩盤を明示する。草の模様は物理判定を変えない。

hashはD0付録A.6の長さ付きUTF-8/FNV-1a/mixを採用し、golden vectorで固定した。
通常選択はseedから8系統を選び、系統内でも位置・高さ等を変える。
比較画像は同じseedで系統だけを明示指定する。自然選択と混同しないよう出典JSONに両方を記録する。

## 初期敷地と通行の検査

18×7家屋と26×14畑について、整数境界・画面内・安定地盤・grade≤1・敷地内標高差≤2を検査する。
通行は2×2窓原点を1pxずつ4近傍移動するグラフのみ。幅1pxの首・角接触は不通、幅2pxの接続は通る。
仮の家屋・畑を置いた後も、両入口が同じ画面端rootへ届くことを確認する。

`probeHillInitialPlots` はD1で「少なくとも一組が入る」ことを調べる存在検査である。
2px格子と近傍の5つの相対位置を試す限定的な探索で、D3の面積降順核・経路スコア最適化・予約比較・施設配置を代用しない。
見つからないときはnullを返し、別系統への差替えや無限再試行をしない。比較用の座標は建設履歴に保存しない。
画像にも家屋を史実として描き足さない。Q5の予約方針、Q6の本番定数は未確定のまま。

- `terrain31_hills_seeds.png`：8系統×seed7/42/82、原寸24場面。
- 各場面の320×180、最近傍4倍1280×720、物理マスクの原寸・4倍。
- `audit.json`：自然選択seed1..1,000の分布・初期敷地存在・失敗。失敗を隠さない。

`REVIEW_SOURCE_SHA` を指定すると出典に記録する。未指定は `local-unidentified`。
CIはこのスクリプトを実行してPNGと監査をartifactへ残す。

## 検証と残るレビュー

ローカル確認：Node109件、既存Playwright24件成功。追加の24場面では物理マスク全地表セルの一致と、JSON往復後PNG一致を検査する。
自然選択1,000seedで初期敷地検査の失敗0。出現数はH01..H08順に128/126/118/124/142/112/113/137。
文明の100年進行へ試作生成・判定を挟んでも、全状態・乱数・履歴が一致することを確認した。

遠景山は共通の参照背景。山6系統・入り江8系統・3地区の流域整合はD1-Cで扱う。
中景の丘の輪郭は比較用投影で、地表物理と同じ座標そのものではない。本番ではD2の保存renderへ移す。
丘の主形状は比較できるが、角張った裾や台地上面の奥行き、低コントラストでどこまで起伏が読めるかはHumanレビュー対象。
建物を置いた街並み、全施設の到達可能性、長期の住宅成立数、ゲーム保存・過去観測の新地形対応は未検証。
24場面のJSON往復は試作形状の確認であり、v5保存や10,000年の新地形統合検証ではない。
