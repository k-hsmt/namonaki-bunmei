# Issue #31 D3-C準備 — 保存水路IDと架橋除外域

状態：**水路所属メタデータの独立実装のみ。橋の建設・通行・履歴・Canvas接続は未完了**。
前提は#57までの3地点の土地利用試走。既存D2地形record・旧セーブ・本編の保存形式を書き換えない。

`river-reaches-review.ts`はD2の検証済み保存地形に結び付く追加descriptorを作る。
各reachは保存済み淡水polygonのID・半開の行範囲・既存のstreamIdを持つ。
川のセルだけから支流名を推測せず、保存済みpolygonと上流／下流ポートの包含関係から既存IDを対応させる。
合流は上流のtributary-a/bと下流main、分流は上流mainと下流mouth-a/bに分ける。
単一の主流に属する中州・網状流の各河道には、その主流IDを付ける。中州の陸地を水面に戻さない。

行ごとの連続水面区間数が変わる位置を分岐・合流として保存し、橋の範囲が上下8pxへ触れる場合は除外する。
中州の両端も水面が分かれる／合わさる位置として扱う。橋を必ず建てるため除外帯を狭める操作はしない。

readerは保存結果の形状・RLEと既存地理グラフだけを検査し、seedから世界を生成しない。
未知フィールド・未知版・出典不一致・未知polygon/stream ID・行範囲の重複や欠損・曖昧なセル所属・ポートIDの不一致・架橋除外位置の改変を拒否する。
地形record自身の結果は変更しない。各淡水セルが一意に既存stream IDへ属し、全淡水セルを覆うことを全セルで照合する。
返すdescriptorはdeep-frozen。セル索引はメモリ上だけで、保存しない。

`captureRiverReaches`は新規生成側のproducer用であり、保存世界を読むときに欠損descriptorを補う関数ではない。
旧v2/v3/v4やlegacy-fixedへ適用する経路はない。正式な生成世界の保存形式はD4で統合する。

```sh
npm run build
node tests/river-reaches-review.test.mjs
```

不正範囲・架空ID・除外位置改変を拒否し、固定地形fixtureとdescriptorを生成器を呼ばずに読む回帰を追加した。
所有セルの固定ハッシュは明示的なlittle-endian int16で作り、実行CPUのバイト順へ依存しない。
