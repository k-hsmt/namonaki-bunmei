# Issue #31｜川辺の地形多様化：最初の独立試作

## 優先順位と今回の範囲

2026-11-06の利用者判断により、共同空地は現状で一区切りとし、滞在表現・入口まわりの
追加改善は優先しない。既存Issueの順序、**#31 世界生成 → #32 植生の自然遷移 → #33 風景アニメーション**へ戻る。
空地の存在感が控えめであることを、次の開発へ進む妨げにしない。

本PRは#31の最小試作として、**川辺の川筋・川幅・中州をseedから変える独立モジュール**を追加する。
実ゲームへの地形適用、保存形式変更、既存建物の移設はまだ行わない。ゲームを起動しただけでは新地形にならない。
巨大ワールド・気候帯・丘陵と入り江の生成・植生・動物・土地改変は後続のIssue／工程で扱う。

## 動くもの

- `generateRiverPrototype(seed)`：細い蛇行、幅広い曲流、中州を挟む流路の3系統。
  同じ系統でもseedで曲がりと位置が変わる。固定の3枚の絵を切り替える方式ではない。
- 初期河川を水域ポリゴンと中州ポリゴンで表す。中州を水域から除外した同じマスクを描画と土地判定で使う。
- `reviewPrototypePlot`：原寸ピクセル中心で敷地内の水面を調べる。水面と画面外はHOLD。
  斜面・地盤・通路・他建築の履歴はまだ扱わないので、`land` は「この試作では水没していない」の意味に限定する。
- `legacyRiverReference`：既存河川の物理マスクの独立コピー。全地表ピクセルで現行の土地ゲートとの一致を検証。
- `preview-river-terrain.mjs`：旧形状参照＋3seedの原寸・4倍・固定施設予約地の診断画像と出典を出力する。
  **PROTOTYPE_NOT_HISTORY** と明記し、自然進行で成立した景色・建築とは扱わない。

### 初回の比較

| 地形 | seed | 水面画素数 | 水没しない通常予約地 | 水面に重なる通常予約地 |
| --- | ---: | ---: | ---: | --- |
| 現行形状の参照 | 0（参照用） | 3,296 | 10 | なし |
| 中州のある流路 | 7 | 4,570 | 9 | 工房 `river-bank-9` |
| 幅広い曲流 | 42 | 4,399 | 8 | 工房 `river-bank-5`・`river-bank-9` |
| 細い蛇行 | 82 | 1,789 | 10 | なし |

固定予約地は11区画のうち、橋を除いた10区画を集計。橋はすべて別設計が必要としてHOLDする。
橋の予定矩形が水面に重なるかどうかだけで、適切な架橋と判定しない。
診断画像の枠は**予約地の参照位置**であり、建設済み施設を描いたものではない。

この結果から、川筋を変えるだけで現在の固定区画方式に衝突することが確認できた。
本番接続では、新しい世界の初期施設・橋・住宅候補を地形に合わせる設計が必要になる。
既存セーブの地形を再生成して建物を動かす対応はしない。

## 未実装と次の接続

1. 新規ゲームに対する初期地形の固定保存と、旧v2/v3/v4の従来地形を保持する境界。
2. 描画・住宅・公共施設・橋が保存された同一の地形を参照する接続。固定施設予約地の扱いもここで決める。
3. 地形に合う初期配置と自然建設の小さな通し試走。川の上に家を建てたり、旧施設を勝手に移したりしない。

試作形状は5断面による粗い輪郭であり、自然らしさの完成評価ではない。
最初は形状の違いと衝突箇所を確認し、保存・建設への接続を優先する。
この段階で河岸の数ピクセルの細部を繰り返し調整して、他のIssueを止めない。

## 実行と検証

```sh
npm ci
npm test
npx playwright install chromium
node scripts/preview-river-terrain.mjs
```

既存ブラウザ回帰と同じく `CHROMIUM_PATH` を指定できる。
出力は `artifacts/terrain31-prototype/`。原寸・4倍、予約地診断、比較一覧、`provenance.json` を含む。
CIでは対象HEADも記録する。

- seedの再現性、同系統内の変化、JSON往復、不正seed拒否。
- 現行河川マスクとの全地表画素一致、中州が河道内にあること、水面での敷地HOLD。
- ブラウザで描いた水色ピクセルと土地判定のマスク一致、再描画のPNG一致。
- 新モジュールは実ゲームのエンジン・描画・保存へ未接続。既存のNode／ブラウザ／長期保存回帰を継続。

Issue #31全体の完了ではなく、最初の形状生成と衝突診断の試作である。Draftでレビューし、マージは利用者が判断する。
