# v0.6 H4-D4-B/C｜大型共同建築の自然進行と景観

**実装対象：B（自然建設と履歴）＋C（確定建築のCanvas描画と検証）。**
**対象外：Cの館／城／政庁／新たな防衛モデル／丘陵と入り江。**

## 1. 建設する理由（D4-B）

- 新規v4で、住宅履歴が年0から**完全追跡**されていること。旧v2/v3から移行した部分追跡のセーブに、未確認の古い空き地を補完しない。
- 河畔に確定した通常の `hall` が現存すること。これを「改築」したり削除したりせず**独立した大型の共同施設を新築**する。
- 河畔で有効な `council`（寄り合い）が**24年以上**記録上継続していること（現在および24年前の同じ起源）。単なる都市規模と人口では発生しない。
- 建設余力として、人口4,500人以上、食糧充足度0.94以上、継続的不足0年、交易継続3年以上。仮の実験閾値でありゲームバランスを保証するものではない。
- 40年ごとの候補判定。満たさない場合は `HOLD`、人口や規模の変化だけで新築しない。新しい共同施設は1地点1棟を上限とする（独立の物理敷地と制度モデルが未整備なので意図的な暫定上限）。
- 建築様式は `seed` から決定的に選択し、新築時に固定。 `great-hall`（44×22px）または `courtyard-hall`（56×30px）。
- 新築可能な候補地点は固定の探索用リスト。川・既存施設・住宅街区との物理衝突はD4-Aのゲートで検査する。適切な候補がゼロなら `HOLD no-safe-plot`。**街区の無断移設・既存集会所の巨大化・川の埋立てはしない**。
- 後発の住宅と固定施設も、確定した大型共同施設の地表占有を回避する。

## 2. 確定イベントと時間旅行

`finishYear` の社会慣習・地域施設の確定後、住宅候補に先行して `proposeCivicConstruction()` を評価。条件が成立した場合のみ、その年の次に採番されるイベントIDを建築の `constructionRecordId` にする。

同じ `id` と年に対する `building-built` イベントと `buildingChanges` を、候補検証済みの台帳上で一括確定する。歴史イベントだけ、または施設だけを勝手に作らない。描画から乱数を消費しない。

- 建物ID・様式・建築時年・地表敷地・建設イベント由来を維持。
- 被災・廃墟化・修繕・再利用では状態だけ変わり、元のシルエットを維持。
- `siteAt` / `snapshotAt` / `composeScene` の過去観測は、建設年より前には新しい施設を表示しない。
- v4保存・再開後は画像まで一致することをブラウザで検査。
- 旧v4・v3・v2からの移行・未追跡期間に施設を遡及生成しない。

## 3. 見た目（D4-C）

- 大きな会堂：幅50px超の高い大屋根・広い柱列・中央入口。従来の集会所との差をシルエットで示す。
- 中庭型共同建築：60px超の左右翼棟・中央に開いた中庭・連続する回廊。小さな切妻住宅が増えただけの風景からの脱却を目指す。
- 新築の `civic` 正本がある施設だけを専用描画へ送る。旧集会所は従来どおり。
- 既存住宅屋根のあと、既存の市場などの前に描いて視認性を保護。
- 施設の前庭描画は実際の `footprint` の外にだけ置く。川や住宅敷地に衝突する場合は描かない。
- 損傷・廃墟は確定状態に基づく外観差を持ち、廃墟でも元の巨大な輪郭が残る。

## 5. Humanレビュー停止条件

A/Bの存在が景観に実質的な違いを生んでいるか、存在しない都市でも絵が不自然でないか、前景住宅・市場・橋が隠れていないかを**原寸320×180**で判断する。

建築候補が見つからない自然文明は、そのまま「建築しなかった歴史」とする。探索で土地が不足するなら、将来の合理的な区画整理・移設を独立した歴史モデルとして議論する。

**城は保留、土塁の館も保留。丘陵・入り江（H3-D）HOLD継続。Humanレビュー前のmainマージとPagesデプロイはしない。Milestone B未完了。**
