# Milestone B: confirmed-data map, limits and next design gate

Status: **partial runnable integration / Draft / Human review**, not Milestone B completion.

## Data contract

| Composed value | Authoritative source | Rules |
|---|---|---|
| year, siteIndex, population | `snapshotAt` / observed residents | No prediction or mutation |
| scale, trend | `siteAt(..., year)` -> `SiteSnapshot.visual` | Presentation parameters only |
| structures | `SiteSnapshot.objects` -> recorded `site.buildings` | Preserve ID, kind, x/y, builtYear, condition |
| footprint | existing building kind | Render grouping only; doesn't create a building |
| architecturalSeed | stable 32-bit FNV-style hash of building ID | Does not consume simulation RNG; reserved for future sprite selection |
| blocks | one view-only surrounding lot per recorded eligible building | Not a city district or residential stock |
| riverUse | usable *recorded* market/workshop or bridge | Not evidence of a quay; no invented quay building |
| ruins/overgrown ground | current building condition | Underlying historical structure persists through scale decline |

The land-use overlays in the minimal integration are *presentation cues*, not events establishing roads, workshops, or civic infrastructure. They do not alter the saved ledger.

## Non-goals and visual shortfall

This branch **does not** use scale to swap among four fixed paintings. It draws actual historical buildings in their recorded places, with limited history-based surface markings. It **does not yet** reproduce the approved Milestone A composition or satisfy the visual acceptance bar for an unmistakable historic city. The current simulation has at most three literal houses among eleven predefined facility slots per site. Copying decorative houses would misrepresent history.

## Proposed aggregate stock, requiring separate approval

Before more buildings can appear, model an additional history-backed residential stock whose *groups* are recorded without tracking each decorative roof as an independent entity:

- `ResidentialBlockState`: block ID, site ID, immutable footprint, construction/occupation year, material/style seed (assigned once), count/capacity, condition, last-renovated year.
- `ResidentialBlockEvent`: built, enlarged, damaged, abandoned, restored, repurposed; ordered by year; future-only for migrated saves.
- Rendering may materialize small sprite components deterministically from a block's count, style and geometry, **but these roofs represent the historical block's residential stock**, not new independent public facilities.
- Preserve scale history and allow old block silhouettes to survive contraction while occupancy falls.
- Civil buildings and bridge remain separate authoritative `Building` entries.
- Add a data-versioned forward migration with a recorded boundary. Historical saves at or before their legacy boundary must retain their previous visual semantics, not get retroactively urbanized.

### Acceptance tests for full B

1. Existing save fixtures and replay hashes unchanged, including past buildings.
2. Independent RNG and pure projection under later progress.
3. 1,000-year natural-play samples labeled by actual year/scale (already captured in this branch); no claim all four levels naturally emerge.
4. Full set of fixed historical fixture screenshots as a **separate** suite, with no fabricated public buildings.
5. Human-approved image comparison at native 320×180 and nearest-neighbor 4×.
6. Browser migration, chronology, old/new save compatibility and long-run performance before merge.
