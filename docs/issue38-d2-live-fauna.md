## 2. 正しさの扱い

- **保存しない**：計画は観測（確定した年・地区）から導き、セーブに何も書かない。D1bのギャラリーで、観測の前後で保存が変わらず動物を含まないことを7世界で検査している。
- **過去の観測**：観測した年までの確定状態だけを読む。1000年までしか進めていない世界と3050年まで進めた世界で、1000年以前の計画が一致する（D1bの検査）。
- **静止画と動く景観**：静止画は0秒の姿。低モーション設定・動く景観OFFは静止画の経路なので、その年の0秒の姿が出る。
- **作り直しの判断**：動く景観のプレイヤーは、見た目のキーが同じなら準備を使い回す。動物の計画は人口・区画・植物で毎年変わり得るので、キーに計画そのもの（群れと個体の位置）を加えた。前年の動物を使い回さない（D0 §10）。
- **季節の切り替え**：前の季節で描く遷移の画面は、同じpainterから作るので、同じ年の動物が描かれる（コードを読んでの確認。この遷移を描いて確かめる検査はしていない）。

## 4. 性能（Chromium、ローカル、63場面／8場面の中央値）

| 項目 | 動物なし | 動物あり |
|---|---|---|
| 静止画1枚 | 91.9ms | 104ms（+13%） |
| 動く景観の準備 | 96.5ms | 95.8ms（差は測定のぶれの範囲） |
| 動く景観1コマ | 0.6ms | 0.9ms |

時間は実行ごとに1〜2割ぶれる。最初の接続（2世界の軽い版で測定）では、静止画が約+26%、動く景観の準備が約+56%だった。内訳を測ると、主な原因は計画（ブラウザで10〜58ms）と、地面線を使わないときにも描画用データを計算していたことだった。次の2つで上の値まで下がった。

- 適性の計算で、半径の外のパッチを調べない。
- 描画用データは地面線が要るときだけ計算する。

建物の地面線の計算そのものは0.5〜21msで、動物が建物の画素に重なる場面でだけ走る。
