## 実装とゲーム本編の境界

- `src/architecture/visual-prototype.ts` は試作専用のカタログと意図的なケースを定義。文明seedから文化史を生成しない。
- `src/architecture/draw-prototype.ts` は単独のCanvas 2Dピクセル描画。背景は固定した**比較台**であり、保存された地形・河川・建築敷地ではない。
- `drawArchitectureD1Preview` は入力の`PreviewCase`を読み取り、毎回320×180のキャンバスを初期化する。ゲームの`SceneComposition`、`world-save`、RNG、実在建築台帳に一切書き込まない。
- 屋根・壁材・屋根材・窓・装飾の最小表現を分離する。屋根のアルファマスクは8種類が異なることをブラウザで確認する。
- 「大スパン」「アーチ」「金属ガラス」は**見た目の試作だけ**であり、実際の建築技術獲得、施工可能性、製造・材料輸送、建物の建設年・敷地・用途・文化伝播は未実装。
- 城塞・館は採用せず、#103の観測地点変更も行わない。
- 現行ゲームのルート描画・セーブ・歴史・配置には変更を加えない。

## Humanが審査する具体的な観点

1. **320×180px原寸で**6文化の違いを色ではなく輪郭・構造・まとまり方から感じ取れるか。4倍だけで見える違いは不合格とする。
2. 同じ文化を異なる5用途へ適用したとき、屋根や素材の共通性を感じつつ、住宅と市場・工房・会堂の用途差が伝わるか。
3. 屋根8種類、構造7種類は実際に異なる形として読めるか。`roof`だけの評価で十分としない。
4. 窓・入口・装飾の差が細かすぎる場合は、輪郭や開口面積を増やすか、表現を統合する理由を記録する。
5. 高床の支柱、アーチの荷重支持、大スパン木造、金属ガラスの構造が小さな画面で説得力を持つか。実在可能性の判定は別途D3の課題。
6. 高度な技術でも木造の素朴さを残す方向、古い文化が新技術と共存する方向へ発展可能か。
7. 過剰な線・記号・色で、静かな世界観や景観の余白を損なっていないか。
8. 実ゲームでは屋根の張り出しが河川・他の建物の上にかかり得るため、**D2で保存された建物敷地・画面の密度・手前奥の重なりを別途監査すること**。D1の絵が単独で綺麗でも占有の合格を意味しない。

各系統は`PASS / REVISE / REJECT`と理由を記録し、D2へ移る前にHuman判断を受ける。候補を却下した場合も、その候補が何であったかはギャラリーと報告に残す。

## 既知の制限と次段階

D1の画面は比較のため5建物を固定位置に置いており、現実の文明史ではない。原寸で見える差があっても、本編の物理敷地・保存・建築文化生成・地域適応・移住/交易・建替え/寿命・1万年の変貌は**未接続**である。

D2では本書を承認後に、文明ごとの建築文法を決定的に生成し、新築時の様式を保存し、同一世界3地区へ適応させる。現在の生成済み建物を描画用に置換する手段としてD1を流用してはならない。

**D1は「試して比較する」工程。単独マージしても#35は完了しない。**
