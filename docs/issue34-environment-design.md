# Issue 34：長期気候変動と土地改変

2026-11-08、D0設計案。#33の景観受け入れとPR #68の統合後、優先順位4の[#34](https://github.com/k-hsmt/namonaki-bunmei/issues/34)に着手。調査基準はmain [`16c37bc`](https://github.com/k-hsmt/namonaki-bunmei/tree/16c37bc298a642cf7b05e85acf96abe1a85da887)。本PRは設計のみで、以下の型・定数・保存拡張は未実装・未採用。

## 1. 目指す最初の変化

同じ川筋・同じ建物のまま、数十〜数百年の乾燥化で草木が疎らになり、湿潤化で回復する。水辺の土地は変化が緩やかで、離れた斜面と一様には変わらない。畑として長く使った場所は放棄後にも利用の影響が残り、回復には時間がかかる。自然回復も開発の維持も、永遠に同じ結果になるとは限らない。

最初の接続先は景観・植生・既存の土地利用。人口・食料・施設需要・災害確率への作用、川の付け替え、切り土、実在しない水路は同時に導入しない。それらは下記D3以降で、比較できる別の政策として扱う。#34全体をD1の描画試作だけで完了とはしない。

## 3. 分離する三つの記録

1. **長期環境**：世界共通の水分偏差と寒暖偏差、版付きの推移規則、導入年、最後の確定年。実測のmm・℃とは表示しない。
2. **局所状態**：保存地形に基づく淡水への距離と斜面条件、成長量、乾燥ストレス、利用による回復の遅れ。3地区は同じ気候背景を共有し、水辺・斜面・土地利用で差が生まれる。
3. **土地利用・改変**：既存の確定敷地と出典付きの開始・維持・放棄。大規模改変を追加する場合は、前後の地形・占有・取水根拠を持つ独立イベントを必要とする。

長期環境は`CivilizationState`の食料等の別名にせず、生成世界の外側に任意の`environment`を置く案とする。環境の観察記録は専用ID空間に持ち、既存年代記配列へ項目を追加しない。現在の年代記ID・建築出典・選択の同一性を保つ。

### 3.1 D1の暫定定数と規則

以下は独立試走の出発点。実測の気候・土壌モデルではなく、比較後に固定するゲーム上の仮定。

| 項目 | 試走案 | 狙い |
| --- | --- | --- |
| 世界の水分／寒暖偏差 | 整数−100〜100、導入時0 | 量の単位を偽らず、両方向へ変化可能にする |
| 水分／寒暖の目標 | 100年ごとに各−60〜60／−40〜40 | 短期の降雨抽選と分ける |
| 目標への変化 | 確定年ごとに最大1ずつ接近 | 一年で全画面が乾燥／湿潤へ切り替わるのを避ける |
| 淡水の緩衝 | パッチ内の安定陸地から淡水への最短距離dに対し `max(0,24−floor(d/2))` | 水辺の局所差。海水には与えない |
| 利用の蓄積 | 稼働する確定畑で5年ごとに1、上限40 | 農地利用の影響がただちには消えない |
| 放棄後の回復 | 利用終了から10年ごとに蓄積を1減らす | 放棄が即座の成熟林に変わらない |
| 局所水分 | 世界水分＋淡水緩衝−利用蓄積、−100〜100に制限 | 土地利用と自然条件を接続する |
| 成長量 | 四分の一年単位の整数で管理。局所水分>15は4、−15以上は2、−35以上は1、それ未満は0を年ごとに加算 | 多湿で回復し、乾燥下では遅くなる |
| 生育の制約 | 既存の速度1／2を適用し、寒暖偏差<−25でさらに半減（整数切り捨て） | 局所差を消さず、寒冷化にも意味を持たせる |
| 長い乾燥 | 局所水分<−35が連続40年ごとに植生を1段階後退 | 成長停止だけで森林が永久に残る問題を避ける |

目標値の導出には`environment-trend-v1`専用のseedハッシュを使い、文明RNGを消費しない。**読込・描画では過去の目標を再生成しない。** その区間へ実際に進んだ時に目標を確定して保存し、現在値は過去から積算する。区間の起点は導入年＋100年×区間番号とし、3地区で同じ目標を使う。目標はその時点で採用した推移パラメータであり、100年先の観測記録ではない。将来の目標や未確定年の環境を観測結果に含めない。

成長量と段階の閾値は既存v1の8／28／75／150年に対応させ、既存パッチの到達段階上限2／4も維持する。成熟分を超える成長量を無限に蓄えず600単位で止める。段階後退時は成長量もその段階の入口まで戻し、湿潤化しても即座に成熟林へ戻らない。乾燥条件が解ければ連続ストレス年数を0へ戻す。利用中の敷地は成長を止め、根元を描かない。放棄の確定後から回復を始める。

「利用の蓄積」は観察用の回復遅延値で、記録されていない実測土壌肥沃度ではない。畑が維持されている間は既存の耕作表示を尊重する。自然の下草の減少だけで収穫量や灌漑の成功を断定しない。

## 4. 確定年・順序・出典

環境が社会計算へ作用しないD1/D2では、既存エンジンの進行・確定を先に行い、環境の前回確定年から`lastObservedYear`までを積算する。バッチ内も各年の土地利用の前後を読む。同じ年の順序を次のように固定する。

1. 環境専用の目標更新とその年の気候偏差を確定。
2. 既存の確定土地履歴から年末の占有・利用状態を読み、建設・再利用・火災の攪乱を一度だけ反映。
3. 利用中は根元の成長を抑制。年末の状態を基準に、その年の利用蓄積／回復と植生の進退を積算。
4. 確定済みの環境状態と出典を保存。選択待ちの未確定年は対象にしない。

建設が成立した年の当該区画は回復させない。放棄が成立した年から回復期間を数える。出典のID・年・地点・敷地を既存正本と照合し、再同期で二重に攪乱しない。複数の同年イベントは既存の順序に従い、最後の確定利用状態を採用する。火災の範囲は#32の既存ルールを保持する。

`irrigation`や`waterworks`は座標がないため、D1/D2では局所加湿・水面・水路として投影しない。将来の灌漑は取水可能な確定淡水、対象の実在耕作地、通水経路と占有、維持・破損・放棄の履歴をそろえてから追加する。道路や橋を水路に読み替えない。

## 5. 保存と過去の再現

提案する新しい組合せは環境schema 1／`environment-coupled-v1`、植生schema 2／`patch-environment-v2`、renderer `generated-scene-v3`。現行version 5の生成世界に任意拡張する案をD2で容量・検証器と併せて確定する。名前だけを既存の許可リストに足して導入しない。

- 環境なしは既存v1植生／renderer v1・v2を保持する。環境だけ、対応植生だけ、版の不一致、未知の規則、未確定の年、欠けた出典は拒否する。破損した現行キーから旧キーへ暗黙に戻らない。
- **新規世界からの導入を既定案**とし、既存世界へ自動付与しない。旧世界の未知の気温・降水・利用蓄積を0で埋めて、既知の過去として扱わない。
- 旧世界への導入ボタンはD2の必須条件にしない。追加する場合は、既存の植生記録がある生成世界に限り、確定年Yで別途保存した導入境界を持つ。Y年までは旧投影を保ち、Y+1から新計算。未記録の過去はunknown、導入時の中立値は「新モデルの開始値」と区別する。legacy-fixedはそのまま。
- 地形・河川・既存敷地は保存された結果を読む。初期植生も保存した配列を引き継ぎ、初期生成器・#47のバイオーム生成器を読み込んで補完しない。
- 未来の読み取り、描画、地点切替、秒時計、保存操作から状態を書き換えない。バッチ・一括進行・手動／自動選択の同じ選択列で、確定済みの環境は完全一致させる。

最初の保存試作では気候区間と利用の出典、100年ごとの局所チェックポイントを使う。パッチ数は最大1320。1万年でチェックポイントは101組までとし、毎年の全配列は保存しない。地点×パッチの局所状態は数値タプルにし、未知と0を区別する。チェックポイントは初期状態と確定イベントから検証できる派生値で、独立した環境正本にはしない。

巻戻しは直前のチェックポイントから最大99年だけ進めて再構成する。最新の局所状態を過去へ使い回さない。キャッシュは世界・政策・確定履歴・観測年に結び付け、読み取り結果の変更で内部が汚染されないようにする。保存上限16MiB、標準gzip、ブラウザ容量への影響はD2で測定し、上限超過なら本番接続せず形式／間隔を見直す。

## 6. 描画と大規模改変の境界

気候の偏差と実在する植生の段階から、地表の疎密・色と草木の回復を投影する。砂漠・ジャングル等の初期バイオーム名を後付けしない。乾燥しても保存済み河川の水面を陸地に変えず、寒冷化を通行可能な氷面と解釈しない。草木の根元・樹冠の建築余白は#32、橋と人の経路は#33の判定を継続する。

静止画と動く景観は同じ環境投影を使う。「動き」を止めても長期の乾燥・回復を消さない。`sceneMotionVisualKey`に、植生段階だけでなく地表・密度・色に使う環境投影値と版を含め、同じ段階でも気候の見え方が変わった時に素材を再準備する。旧環境なしの静止画・動画は従来通りとする。

環境を観測する軽量な表示では「長期の乾燥傾向」「回復の遅い放棄地」等を、実際に記録がある時だけ示す。数値を人口の成功度や文明の総合点にしない。大域傾向とその地点の一時的な災害痕を混同しない。

切り土・段々畑・新水路・川の付け替えは、描画だけの上塗りでは追加しない。導入時は年次の地形版、影響セル、既存建築・橋・水理と歩行の再検証、実行前後の原子性、過去の地形を読むAPIが必要になる。#31の初期地形を直接変更せず、別のD4設計で扱う。

### 必須の検証

- 一括／分割／保存再開の完全一致、未確定年で停止、対象年の全状態・画素一致。
- D1/D2は環境なしと`CivilizationState`全体・RNG・選択年・災害年・建築と敷地が一致。間接的な施設未成立も新たに発生させない。
- 水辺／内陸、局所利用の違いが残り、乾燥・湿潤・回復のいずれか一方へ全世界が固定されない。
- 建物・現役畑・共同空地・橋と植生の根元・通行が衝突しない。
- 出典欠落、未来のチェックポイント、範囲外の値・再構成と整合しないチェックポイント、未知版、環境／植生／rendererの不一致を拒否。
- 旧保存のロード・明示保存・将来進行で、採用前の政策と旧過去の画像・環境unknown境界を保持。
- 1万年の圧縮前／後サイズ、実ブラウザの標準保存、quota失敗時の旧キー保持・完全エクスポートを確認。
- 1回ウォームアップ＋5回で、環境なしの同じ世界と進行時間・観測・準備を比較。暫定基準は2000年5秒／10000年25秒、比2倍以内（分母最低1秒）。既存#32基準を参考にし、D1の結果を見て採用可否を判断。
- PC・スマホ相当で年0／100／1000／10000の観測・素材準備を別計測し、毎フレームの描画p95は12fpsの83.3ms以内。実機とCPUスロットリングは区別する。

## 8. D0の判断点

推奨は「D1/D2は既存の文明計算を維持し、環境と植生・確定土地利用の接続を先に比較する」「初期バイオームは#47と分離」「旧保存は自動導入しない」。食料・災害確率への影響は、同じ乱数列でも確定史が変わるためD3の別policyとして判断する。

この設計PRのマージはD0の区切りであり、#34全体の完了や、D3/D4の本番導入を意味しない。D1の比較結果とD2の互換監査を次のレビュー単位にする。

## D1/D2実装記録（2026-11-08）

PR #69の設計統合後に実装。環境の整数モデルは `src/environment/model-v1.ts`、保存検証・過去投影は `history-v1.ts`、新規目標の生成と確定進行は `progression-v1.ts` に分離する。保存済みの目標から再生し、読込時に目標を再抽選しない。

新規世界の既定は環境schema 1・植生schema 2・renderer v3。旧配置方式の明示指定は従来通りで、既存の植生v1や植生のない保存を自動変換しない。試験用APIの第4引数で環境有無を比較できる。植生なし＋環境ありの組合せは拒否する。旧植生の専用監査・比較は、配置方式を明示してv1に固定する。

局所状態のタプルは `[四分の一年単位の成長量,乾燥ストレス年数,利用蓄積,耕作／回復の周期内年数]`。土地利用は確定した施設・橋脚・住宅・共同空地と、畑の破損／再利用履歴から得る。パッチに触れる占有をその8×8区画の成長抑制として扱う粗い生態モデルで、ピクセル単位の土壌測定ではない。複数敷地が触れても利用蓄積を二重加算しない。

自然比較は5seed×3地区×5年の75景観。制御比較は乾燥→湿潤、湿潤→乾燥、寒冷→回復、耕作→放棄の4系統×3地区×6年の72景観。後者は同じ自然史の建物を背景に、環境・植生条件だけを制御した独立試走で、確定した自然史や本番保存には混ぜない。

CIの `environment34-acceptance` に `audit.json`、`performance.json`、比較用 `index.html` と原寸／4倍画像、5世界のgzip保存を出力する。全体単体テストのCI制限は、追加の互換・保存検証を含めて10分とする。D3の灌漑・社会計算変更とD4の恒久地形改変は未実装で、#34をこのPRだけで完了とは扱わない。

ローカル監査では5世界すべてで1万年の文明state・敷地・過去観測・gzip再開・続きが一致。圧縮後は約0.78〜0.85MB、圧縮前は約7.6〜8.5MB、環境分は約1.35〜1.53MBで16MiB以内だった。100年チェックポイントは101組。数値は最終CIでも再計測する。
