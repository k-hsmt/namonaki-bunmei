## 1. 現行の分岐（調査）

- `generateDecision()`は10テンプレートから一様に抽選する（直前と同じテンプレートは避ける）。
- 提示は、世界暦60年以降・前回から85年以上の年に、毎年1.2%の抽選で決まる。テンプレートと文明の状態は結びついていない。
- 自動の選択（`chooseAutomatically`）は選択肢から一様に抽選し、乱数を1回使う。手動の選択は乱数を使わない。そのため、同じ行動でも手動と自動で以後の乱数がずれる。
- 選択の効果は指標の増減と、ラベルの正規表現による制度の更新。

## 2. 設計

### 2.1 課題に基づく提示（D0 §7：年数の定期抽選に依存しない）

- 年次の抽選はやめ、**課題が前年に生じたとき**に提示する。生じたとは、前年の記録があること、または前年に値が境界を越えたこと。状態が続く毎年ではない。
  - 試作の初版は「課題が成立している間」に提示していたが、不足や記録の慣習がほぼ常に成立していた。そのため最小間隔ごとの定期的な提示に戻ってしまい（2000年で22回、ほぼ85年おき）、「生じたとき」に改めた。
- 頻度の上限：同じテンプレートは200年以上、分岐どうしは85年以上の間隔をあける（初期値。D4cで調整）。数百年提示がない期間も起こり得る。
- 複数の課題が同時に生じた年は、カタログの順で最初のものを提示する（乱数を使わない）。

| テンプレート（templateId） | 課題（前年に生じたこと） | 出典（質問に結びつける記録） |
|---|---|---|
| 食糧の蓄えが乏しい（scarce-stores） | 経済が地区の不足を記録した（不足が3年続くと記録される） | その不足の記録 |
| 遠方からの来訪（visitors） | arrival（旅人の来訪）が起きた | arrivalの記録 |
| 大雨で橋が流された（bridge-lost） | 洪水による橋の損傷が記録され、橋が損傷したまま | 損傷の記録と洪水の記録 |
| 記録と記憶の食い違い（records-memory） | first_archiveが起きた、または記録の慣習が根づいた | その記録 |
| 人口が減った地域の住居（vacant-homes） | 住宅街区が空き家になった | 空き家の記録 |
| 豊かな季節の余剰（surplus） | foodが70以上に上がり、5年間すべての地区の充足率が0.90以上 | （記録なし）経済と指標の根拠を`evidence`に保存 |
| 水路の傷み（waterway-damage） | **停止**：水路の状態を抽選時に確定事実として読めない | — |
| 祭りの形（festival-form） | **停止**：若者の提案という前提を確かめられない | — |
| 古い木と建物（old-tree） | **停止**：古い木と建設計画を確かめられない | — |
| 川の魚の減少（fish-decline） | **停止**：魚の減少を確定するモデルがない | — |

- 停止の4件は、D2a Q2の原則（取得できない根拠は推測で補わず保留する）による。
- records-memoryの「食い違い」は、記録の慣習の成立から読む解釈を含む。

### 2.2 安定したID・行動

- templateId・actionIdを全テンプレート・全選択肢に与えた（`DECISION_CATALOG`）。内容（問い・選択肢・効果）は`decisionTemplatesV1`をそのまま使い、複製しない。
- 選択の記録（`decisions`）に、templateId・actionId・選んだ者（people／observer）を残す。年代記の選択の記録の`relatedIds`は、課題の出典の記録。
- 選択は意図であり、効果は現行の効果（指標の増減・制度の更新）のまま。物理的な成果（橋の再建等）を、選んだだけで確定させない。

### 2.3 文明自身の判断と、手動・自律で同じ世界（D0 §7）

- 文明自身の選択の重みは「1＋2×（その行動が続ける制度の強さ）/100」（1〜3）。例：共同の穀物庫の制度が強いほど「蓄えを共同で分かち合う」を選びやすい。どの行動も重みは1以上で、代替が0にはならない。
- **文明自身の選択は、分岐を提示した時点で乱数を1回だけ使って決め、選択待ちに保存する。** 選ぶ時点では、手動でも自動でも乱数を使わない。
  - 同じ行動なら、手動で選んでも人々に委ねても以後の世界は同じになる。違うのは選んだ者の記録（年代記の原因の文と`chooser`）だけ。
  - 自動の進行（観測者が介入しない）は、人々の判断に委ねることと同じ処理になる。
- 全世界版の年次処理には「自動の選択は乱数を1回使う」という検査がある。検証用の判断の方針があるときだけ、期待値を0回にした（本番は1回のまま）。

### 2.4 検証用の保存（Human：D2bで選択待ちを含む保存往復を扱う）

- 形式`namonaki-review-save`（`src/story/review-save-d2b.ts`）に、次を保存する：
  - 新しい世界のseed
  - 方針（`hardship-linked`または`hardship-linked+decisions-d2b`）
  - 0年からの操作の列（進行／選択）
  - 結果の歴史（文明の状態と建築台帳）のSHA-256
  - 年、選択待ちの有無
- 読込は、同じ方針で新しい世界から操作を再実行する。歴史のハッシュ・年・選択待ちが一致したときだけ受け入れ、何も補わない。規則は決定的なので、再実行は保存した歴史と同じになる。
- 改ざん（ハッシュ・seed・未知の項目・未知の方針）は拒否する。本番の読込口（`decodeWorldSave`）はこの形式を受け付けない。検証用の世界は本番の保存にもできない（D2aのまま）。
- 読込には再実行の時間がかかる（Nodeで5000年あたり約7秒）。検証用の形式であり、本番の保存の設計ではない（D5で別に決める）。

## 3. テスト（`tests/decision-policy-d2b.test.mjs`、4件）

- カタログ：全テンプレート・全選択肢に一意のID。停止した4件とその理由。
- 提示：前年の出典の記録があり、種類が課題と合う。間隔（85年・200年）を守る。停止したテンプレートは提示されない。選択の記録に選んだ者とID。
- 同じ行動：観測者が選んでも人々に委ねても、乱数状態と、選んだ者の記録以外の歴史が一致する。その後300年進めても一致する。違う行動なら違う世界になる。
- 保存：選択待ちで保存→読込で状態が一致する。同じ選択をすると直接進めた世界と一致する。読み込んだ世界から進めて再保存できる。改ざん・本番の読込口・本番の保存は拒否される。

### 6.4 所見（D4cへ）

- **最小間隔が実質の上限になっている。** 間隔の3分の1が85〜90年。不足の記録（地区の不足が3年続くと記録される）と空き家は、5000年のあいだに何度も生じる。そのため、85年あくとすぐ次の課題がある状態が多い。提示は課題の発生に結びついている（出典の検査は全件合格）が、頻度は最小間隔で決まっている。
  - 定期的な抽選に戻ったわけではない（間隔の90％点172年、最長544年）。ただし、課題の重みづけ（同じ課題の繰り返しの扱い、課題の深刻さによる選別）は、D4cの頻度の調整で扱う。
- bridge-lostは5件と少ない（洪水による橋の損傷そのものが少ない）。
- 停止した4テンプレートは、D3の事象モデル（水路・祭り・自然資源）で根拠を取れるようになったら、提示を再開できるか確認する。
