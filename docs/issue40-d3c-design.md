## 1. 正本と、災害復旧の実態（実装前の調査）

| 事実 | 正本 | 災害復旧系統が読むもの |
|---|---|---|
| 災害 | 年代記の出来事（`flood`・`earthquake`・`fire`・`storm`） | 損傷の記録が引く災害の記録 |
| 施設（橋を含む）の損傷・修繕・放棄・再利用 | 集落台帳の建物の状態と、その記録（`building-damaged`／`-repaired`／`-abandoned`／`-reused`、`buildingId`） | 記録 |
| 住宅街区の損傷・修繕・廃墟化 | 住宅の履歴と、その記録（`housing-damaged`／`-repaired`／`-ruined`、`buildingId`は街区のID） | 記録 |
| 水路の損傷・修繕・放棄 | 灌漑の履歴（`terrain.irrigation.events`） | 読まない（下記） |

調べた事実（6世界×5000年、エピソードなし）：

- 災害は世界あたり22〜51回。損傷の記録は、すべて同じ年の災害の記録を引いている（488件中488件）。損傷を起こさない災害はほぼない（災害のある年は、川辺・丘陵・入り江のどこかの建物か住宅が傷む）。
- 損傷した施設：79%が修繕される（中央値8年）。21%が放棄される（中央値13年）。放棄された施設の多くは後に再利用されるが、中央値160年後・最長1251年後で、再利用されないものもある。
- 損傷した住宅街区：88%が修繕される（中央値4年、最長244年）。12%が廃墟になる（中央値16年）。廃墟は後に修繕される（中央値35年後）。
- 修繕・放棄は既存の年次処理が決める（施設は、最後の工事から8年と、充足率0.92以上が3年。住宅は、損傷から4年・充足率0.94以上・人口900以上）。修繕の順番は、建物の並び順で決まる。選んだ順番ではない。
- 水路の損傷は、保守の途絶（経過年数）か、制御入力からしか起きない（`src/irrigation/lifecycle-v1.ts`）。災害による損傷はない。

D0 §4.2「災害の存在だけから被災建物・修復完了を作らない」に従い、災害の記録だけでは始めない。損傷の記録から始める。

- エピソードは、上の正本を複製しない。効果も持たない（D0 §3）。修繕・放棄・再利用は既存の年次処理だけが決める。
- 経験が将来の行動の重みに影響する経路は、D3cでは加えない（D3e・D4c）。

## 2. 経過の規則（`src/story/episode-recovery-d3c-review.ts`）

数値の閾値・期間は使わない。対象（施設・住宅街区）それぞれの記録だけで決める。

| 遷移 | 条件（確定した記録） | 根拠 |
|---|---|---|
| started | その年に、同じ年の災害を引く損傷の記録がある | 災害と損傷の記録 |
| reassessed：further-damage | 進行中に、災害による損傷がさらにある | 災害と損傷の記録 |
| reassessed：object-abandoned | 対応がない間に、損傷した対象が使われなくなる（施設の放棄・住宅の廃墟化） | 放棄の記録と、それが続く損傷の記録 |
| response-started：repair／reuse | 損傷した対象が修繕される／廃墟が再利用される | 修繕・再利用の記録と、損傷の記録 |
| reassessed：object-repaired／object-reused | 進行中の対応と同じやり方で、別の対象が回復する | 同上 |
| response-changed：to-repair／to-reuse | 進行中の対応と別のやり方で、対象が回復する | 同上 |
| response-failed：object-abandoned | 対応が進行中に、損傷した対象が使われなくなる（回復が届かなかった） | 放棄の記録と、損傷の記録 |
| resolved：restored | 関わる対象すべてが回復した | 各対象の最後の記録 |
| abandoned：left-in-ruin | 損傷したままの対象がなく、少なくとも1つが廃墟のまま | 各対象の最後の記録 |

- 対象：損傷の記録の対象（施設は`building:<id>`、住宅街区は`housing:<id>`）。損傷が広がると加わる。
- 対象の記録は、その状態に続くときだけ採る。損傷したものの放棄・修繕、廃墟の再利用（住宅は廃墟の修繕）。回復した後の放棄などは、損傷の続きではないため採らない。
- 1年に1遷移。その年に告知できない記録は、エピソードの待ち行列で次の年以降に送る。順番は、早い年の記録から、同じ年なら損傷→放棄→修繕→再利用。
- 修繕は、工事そのものを対応とする。修繕を試みて届かなかったことを示す記録はないため、試行の失敗は作らない。失敗は、対応中に対象が使われなくなったことだけ。
- 断念（left-in-ruin）：D0の「放棄により課題終了」に従う。使われなくなったことが、記録された状態の変化として損傷を終える。期間の経過では終えない。終結の後の廃墟の再利用は、エピソードのものとはしない。この件数と年数は試走で測り、D3eへ渡す。
- 修繕を待つ対象が1つでもある間は、何年でも開いたまま続く（期間の上限なし）。

### 2.1 実装しないもの

- 水路：損傷の原因が災害ではない（§1）。災害復旧の起点にも経過にもしない。保守の途絶による水路の損傷は、災害復旧とは別の課題（試走では件数だけ測る）。
- 生活基盤の悪化だけを起点にすること：損傷のない不足は、食料系統（D3a）が扱う。重ねて起点にしない。
- 修繕の優先順位：順番は建物の並び順で決まっている（§1）。選んだ順番として主張しない。

## 3. 独立の照合（`scripts/lib/history40-recovery.mjs`）

定義とは別に書いた照合で、年代記だけを読む。対象ごとの記録の並び（損傷・修繕・放棄または廃墟化・再利用）から、すべての遷移の主張を確かめる。

- 開始・損傷の拡大：損傷の記録が、引いている災害の記録と同じ年で、その災害もエピソードが引いている。開始なら、記録はすべてその年のもの。
- 放棄・修繕・再利用：記録の種類が理由と合い、対象のその時点の状態に続き、その損傷の次の記録である。損傷の記録も一緒に引いている。
- 失敗と対応の記帳：失敗は対応中だけ。方針変更は別のやり方へだけ。
- 終結・断念：回復した／損傷したままの対象がなく、廃墟がある。
- 取りこぼし：災害によるすべての損傷が、ちょうど1回、復旧エピソードに引かれている。関わる対象の後の記録（修繕、または放棄とその後の回復）が、エピソードの終わりより前なら、ちょうど1回引かれている。

## 5. テスト（`tests/episode-recovery-d3c.test.mjs`、4件）

- 実世界（seed 23、900年）：災害による損傷で始まり、修繕で回復し、損傷が広がる。起点には必ず損傷の記録があり、それが引く災害も起点に含む。修繕を244年待った住宅街区のエピソードは、修繕されるまで開いたまま続く。全体の検査と、独立の照合が合格する。
- 実世界（seed 11、700年）：対応中の放棄が失敗になり、対応のない放棄は再評価になり、廃墟を残して断念で終わる。放棄は、続く損傷の記録を引く。
- 照合は、出典が支えない主張（災害を引かない損傷、年代記にない修繕、引かれていない修繕、対象が損傷したままの終結）を検出する。
- エピソードなしの世界と、文明・建築台帳が一致する（効果なし）。
