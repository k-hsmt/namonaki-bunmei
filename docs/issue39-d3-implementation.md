# Issue #39 D3｜記録された変化から、その年の風景へ

- Issue: [#39 歴史を発見する観察体験](https://github.com/k-hsmt/namonaki-bunmei/issues/39)
- 設計: D0詳細設計 `docs/issue39-historical-discovery-d0.md`（PR #161）の §7・§8.2・§10 D3。前工程は[D1](issue39-d1-implementation.md)と[D2](issue39-d2-implementation.md)（D2はHumanレビューで全項目了承済み）
- 範囲：調査パネルの各変化から、その確定年を観測する操作。2画面比較（D4）は含めない。

## 1. 体験

- 調査パネルの履歴の各行に「この年の風景を見る」ボタンを置いた。押すと、その変化の確定年を観測する。
- 移動は#29の共通入口`observeYear()`を通る。そのため、次がすべて同じ確定年にそろう。
  - 風景のCanvas
  - 年代記
  - 文明ステータス
  - 歴史グラフ（観測中の年の印と表示窓）
  - スクラバー
- 移動すると自動進行を止める（#29と同じ）。
- 年代記には、その変化に結び付いた記録（D1の`linkedChronicleId`）を表示する。結び付く記録がない変化では、従来どおりその年までの最新の記録を表示する。
- 移動後も調べるモードと選択中の対象はそのまま。パネルはその年で再検証され、その年より後の変化は出ない。
- 観測中の年の行は「この年を観測中」と表示し、押しても何もしない。
- 最終確定年を選ぶと、ライブ表示に戻る（#29と同じ）。
- 選択待ちの文明でも、行に出るのは最終確定年までの変化だけ。過去の年を見ている間、選択肢は隠れる。「現在へ戻る」で、待っている選択がそのまま戻る。

## 3. 実装上の判断

- 観測中の行のボタンは`disabled`にせず、`aria-disabled="true"`とした。`disabled`のボタンはフォーカスを持てず、キーボードで押した直後にフォーカスが失われるため（テストで検出）。移動後は、同じ変化の行のボタンへフォーカスを戻す。
- 構成要素の`generations`（建築世代）の行には、ボタンを付けていない。建て直しは履歴の行（「再利用（建て直し・第N世代）」）から移動できるため。

## 4. テスト

`tests/browser/historical-inspector.test.mjs`に3件を追加（D2の5件と合わせて計8件、すべて成功）。

1. 橋の1135年（損傷）と777年（建設）へ移動したとき、次を確認した。
   - 観測中の年・スクラバー・年代記の見出し（その変化の記録）・ステータス・グラフの要約がその年になる。
   - 風景が、その年の本番静止画と全画素一致する。
   - パネルの状態がその年のものになり、その年より後の行が出ない。
   - 観測中の行は押せない表示になる。
   - キーボードのEnterで移動した後も、フォーカスが同じ行に残る。
2. 自動進行中に移動すると進行が止まり、選択中の対象と調べるモードが保たれる。その後に年は動かない。
3. 選択待ちの文明（seed 42、最初の分かれ道で停止）では、全対象の行が最終確定年以内である。過去へ移動すると選択肢が隠れ、「現在へ戻る」で再び表示される。

全体回帰の結果は §5。
