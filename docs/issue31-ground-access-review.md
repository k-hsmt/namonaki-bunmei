## 実装と境界

`src/terrain/ground-access-review.ts`はD2の検証済み結果RLEを読み、正規座標で敷地を検査する。本編engine・旧地形・保存キーへの依存と変更はない。

- 半開矩形の全セルで地表、水面、地盤、grade、標高差を検査する。
- 実占有と未建設予約を区別し、自分自身の予約だけを除外する。廃墟等の占有を解除する機能はない。
- 幅2pxの通路を2×2窓原点の4近傍グラフで表現する。BFSはN/E/S/W順、親は初回訪問で固定する。
- 南側入口とprimary rootの経路を候補の仮占有後に調べる。既存の接続済み入口を切断する建設はHOLDし、既に孤立した入口を新規切断と誤認しない。
- unknown/partial履歴・未確定年・画面外をHOLDする。原本地形・占有・敷地を変更しない。
- 入口・経路はレビュー結果であり、道路の確定履歴として保存しない。

`reviewPhysicalPlot`は地表条件だけの前段検査。`clear`でも建設許可ではない。
`reviewGroundAccess`は畑以外の水際距離2px未満も拒否するが、候補を検査する段階であり、社会条件、用途スコア、候補選択、最新占有での確定トランザクションをまだ実装していない。通常施設の本番ゲートとして使用してはならない。
橋のdeckを歩行可能にするAPIはD3-Cまで公開しない。未検証の水上矩形を渡すことで川越えを許可する抜け道を作らない。

`initial-access-review.ts`は年0の家屋・畑の同時成立を調べる独立提案API。
2×2窓の被覆地表面積順で成分を調べ、画面端rootを持たない孤立島を除く。
家屋は水際8〜32pxを優先し、seed専用hashで同点を解く。水域なしでは成分の窓原点の重心へ寄せる。
仮占有後の家屋入口から最短の画面端rootを選び、他成分の自然rootとは区別する。
畑を仮占有して家屋とrootの接続が残ることを共通ゲートで再検査する。
畑の候補順は現時点では家屋入口からの既存通路距離順という試走用の順序で、最終用途スコアを実装したものではない。
結果は家屋・畑の敷地とrootの提案だけ。D2の`initialPlan:null`や実建設履歴を書き換えない。

`placement-search-review.ts`は通常建物・住宅の試走用順位を探索する。
`4×Dcore + 3×Dneighbor + Pwater + Pslope + Pdepth + T`、住宅だけ近隣係数6、Tは独立hashの0..3。
既存占有上の距離場から下限を求め、下限順に仮占有後の接続と正確な距離を検査する。
最良確定スコアより残りの下限が大きい場合だけ打ち切り、同点はy,xで固定する。候補件数による打切りはない。
全候補を仮占有して調べるexhaustiveモードと、小規模な陸地・水路反例3ケースで結果の敷地・スコア・経路が一致した。
試走hallの探索は年0家屋・畑の提案を仮占有して行う。これはhallの社会的成立や建設年0を認める意味ではない。
畑・civic・共同空地の用途固有順位は未実装なので、この探索APIはそれらを明示HOLDする。
動的キャッシュ・積分表・訪問頂点数の計測は未実装であり、長期性能の保証はまだない。

## Q6の修正候補

Humanより「暫定値を修正してから試走」「指定はないので適切な値を選ぶ」と指示を受けた。
通路のトポロジーを維持しつつ、敷地内の段差を厳しくした。これは**比較用の候補**で、永続化される`terrain-placement-v1`の承認ではない。

| 項目 | D0暫定値 | 今回の候補 |
| --- | --- | --- |
| 住宅・家屋・工房・穀物庫・畑のgrade | ≤1 | ≤1 |
| 同じ用途の敷地内標高差 | ≤2 | ≤1 |
| hall・市場・civic・共同空地のgrade | 0 | 0 |
| 同じ用途の敷地内標高差 | ≤1 | 0 |
| 通路幅／候補格子 | 2px／2px | 2px／2px |

敷地内の段差を減らし、スプライトだけの上下移動や無記録の造成に頼らず足元を合わせるための変更。
平坦用途の標高差0は連続したgrade0地表では通常冗長だが、基礎が水平である条件を明示する。
斜面用途をすべてgrade0に制限する案は、丘陵の土地利用を過度に削るため今回採用しない。

## 固定12seedの物理比較

seedはD2比較セットと同じ `[1,3,6,29,85,131,7,198,10,12,21,24]`。成功例への差替えなし。
12世界の生成成功、36地区で6サイズを比較した。生成失敗0。これは生成器が全seedで成功する保証ではない。
各候補は2px格子の全範囲で列挙。試した全候補数＝修正後の合格数＋各HOLD理由数を検査する。

| 丘陵・12地区合計 | 旧条件の物理候補数 | 修正後 | 減少 |
| --- | ---: | ---: | ---: |
| 家屋18×7 | 50,870 | 43,165 | 7,705 |
| 畑26×14 | 32,943 | 30,559 | 2,384 |
| 住宅18×8 | 48,163 | 42,269 | 5,894 |

川辺・海岸では今回の修正で物理候補数は変わらなかった。flat用途も変更なし。
丘陵のcivic44×22・56×30は**候補数0の地区がある**。狭谷や段丘で大敷地が成立しない可能性を成功に言い換えない。
44×22が0の具体例はseed85・21のH07。今回の定数修正より前から0である。
候補は互いに重なるので、この数は収容棟数ではない。通行・既存占有・水際余白・社会条件を加えるとさらに減る。
建設HOLD、都市到達、景観密度、Q5予約方式、2,000/10,000年のgenerated進行を比較した結果ではない。

`scripts/review-ground-access.mjs`は原寸・nearest-neighbor4倍・家屋物理候補原点オーバーレイ・36場面一覧・全理由別JSONを出力する。
紫点は合法な家屋の左上候補原点で、建設済み家屋ではない。左右反転は投影時だけ適用する。
家屋を赤、畑を黄で表示する`initialPlan`／`initialPlanLarge`画像は年0提案の検査用敷地表示であり、実ゲームの完成景観ではない。白2×2がprimary root、黒2×2が核入口。
