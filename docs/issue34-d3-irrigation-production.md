# Issue 34 D3-B：灌漑の本番接続設計

PR #76のマージでD3-A（独立試走・比較・性能評価）が完了した。基準はmain `7c7b033`。本書はD3-Bの最初の成果物（B0）であり、本番接続の実装前に保存・導入・占有・歩行・動画の契約を定める。文書の統合だけでD3-BやD3全体を完了としない。

## 1. 到達する挙動

新しい世界では、確定した灌漑の出来事があり、実在する畑まで合法な経路が見つかったときにだけ水路ができる。通常の3地点の画面、過去の観測、静止画、動く表示、保存後の再開が、同じ水路と局所の植生を参照する。溝が残る間は人・荷車・草木の根元を避け、埋戻し後は通行可能に戻る。水路を描くために建物や川の位置を動かさない。

既存の世界はそのまま開いて進行できる。環境を記録している生成世界だけが、現在の確定年から「これからの水路を記録する」を選べる。古い灌漑の文面から水路を作らず、導入前の景観と生態系を保つ。食料・人口・工事労働への作用はD3-C、地形そのものの恒久変更はD4とする。

## 2. A3から採用する初版の判断

[A3の資料](issue34-d3-irrigation-acceptance.md)と[CI artifact](https://github.com/k-hsmt/namonaki-bunmei/actions/runs/42470899853/artifacts/13613304827)を基に、以下を本番初版の案とする。本書の実装に際して別の値へ黙って差し替えず、変更するときはruleを分けて同じ比較を更新する。

## 4. 保存契約：世界は1つ、生態系も1つ

新規の本番灌漑世界は `format: namonaki-world-save`、`version: 6`、`schemaVersion: 1` とする。生成地形専用で、`terrain-placement-v3 / field-only` と `rendererId: generated-scene-v6` を組み合わせる。v5と同じ地形・河川・文明・敷地・植生の出典を使い、世界を水路の中へ再格納しない。

以下の識別子と構成はB1で実装する新契約の案であり、現在のreaderが受理する形式ではない。

- `irrigation` は `schemaVersion: 1 / ruleId: irrigation-production-v1`、`introducedYear`、`confirmedThrough`、`systems`、`events`、`attempts` を持つ。`base`、`baseHash`、`controls`、試走の`status`は持たない。環境のcheckpoint/currentもここへ複製しない。
- production geometryは `schemaVersion: 1 / ruleId: irrigation-geometry-v1`。A1と同じ取水・出典・畑・経路・全幅セルを持つが、`review-only`を本番許可として流用しない。中立の幾何validatorと、各形式の厳密なheader検証を分ける。試走を改名してインポートする機能は作らない。
- `environment` は `schemaVersion: 2 / ruleId: environment-irrigated-v1`。気候のruleと`climateStart`、既存の`targets`と`uses`、水路を反映したcheckpoint/currentを持つ。大域の環境開始は0年、水路の開始は`irrigation.introducedYear`で区別する。旧 `environment-coupled-v1/v2` のschemaと意味は変更しない。
- 各checkpoint/currentは年・環境state・その時点のchannel stateを結合する。環境state内の年も一致させる。台帳から得た状態と異なるchannelを保存しない。導入前はchannelをnullとし、「導入前」の区別は境界年で決める。
- 植生の初期patchと確定攪乱は既存の `patch-environment-v2` を保持し、環境からの成長投影を新ruleへdispatchする。植生データだけを見て灌漑済みと判定しない。

環境の`confirmedThrough`、水路の`confirmedThrough`、`lastObservedYear(state)`は等しい。文明の未確定年を上限にしない。全データは元世界のseed・terrain revision・親shape/stream・畑の基礎原因・年・IDの関係で検証する。SHA-256は署名ではないため、試走の元世界ハッシュを消す代わりに参照検証を省略することはない。

本番台帳には `controlled-input` の原因も制御入力も受理しない。自然の`chronicle`、確定した`land-use`、親イベントを持つ`policy-clock`だけを許可する。新設時の幾何、点検・修復時の現在の適合、後発占有、期限、状態、台帳順序、非成立の判断入力を再生して照合する。不成立receiptの探索量と原因は検証するが、不成立の最適性を読込時の新探索で証明しない点はA2と同じ。

未知版・未知キー・形式の混在・未来年・二重原因・欠けた原因・他世界の水路・重複適用・不整合なcheckpoint・制御入力を拒否する。JSON上限16MiB、gzip目安4MiBを継承し、毎年の全セル・全植生・派生mask・歩行経路・タイマーは保存しない。

### 4.1 既存世界への導入

対象はv5の生成世界で、記録済み環境とcoupled vegetation、`terrain-placement-v3`を持つもの。v1/v2 placementの世界では、既存の「対岸にも広がる」明示切替を先に行えるが、水路の導入操作で成長policyまで変更しない。環境を持たない世界とlegacy-fixedへの環境生成・水路導入は、この機能へ混ぜない。

現在の確定年をJとすると、以下を原子的に作成する。

1. 文明・RNG・敷地・気候の確定値と、J年までの植生・環境stateをそのまま引き継ぐ。
2. `introducedYear: J`、空の水路台帳、J年の環境とchannel nullを境界とする。J年の灌漑原因も処理せず、J+1から有効とする。
3. 旧環境のcheckpointはJまでを保持し、Jが100年境界でなければ正確な境界stateを1つ追加する。J以降はJを起点に100年ごと＋currentを保存する。導入前の読取は旧checkpointから最大99年、導入後も境界または直前checkpointから最大99年を再構成する。
4. 気候の既存targetとゆっくりした推移の開始年を維持する。新規世界は現在の穏やかな気候ruleを使うが、旧世界の導入操作で気候を変更しない。旧気候をゆっくりにする操作は、統合環境でも未来の次の100年境界だけを変更できるようにする。

J年以前は元のrenderer/appearanceを使う。v6の表示設定に導入前のrenderer ID（v3/v4/v5）を明記し、元の環境appearanceと整合を検証する。J+1以降はv6の水路対応描画へ切り替えるが、元のappearanceを引き継ぎ、導入と同時に景観の詳細度を更新しない。v6で後から「環境の景観を詳しくする」を選ぶ場合はJ+1以降のappearanceだけを更新し、保存した導入前rendererは保持する。新規世界のJ=0の基礎景観はv5を使い、A3の年0と一致させる。

導入済みの世界へ再実行しても変更しない。導入後に過去を観測して境界を移動しない。未確定の選択待ちでもJは`lastObservedYear`を使い、選択確定後にJ+1以降の原因を一度だけ処理する。導入の失敗時は元のsession・観測年・保存を保持する。

### 4.2 保存発見と旧契約

v5のreader/writer、旧renderer、旧ruleの将来進行を保持する。v5保存を開いたり保存しただけでv6のモデルへ変換しない。gzipは外側のversionを内側と一致させ、v5/v6の混在を拒否する。

新しいブラウザの保存先は `namonaki-story-v6` とし、発見順はv6→v5→v4→v3→v2。v6キーが存在して壊れているときは停止し、古いキーへフォールバックして別の歴史を黙って開かない。

**保存先のキーと世界の形式versionを区別する。** 新しいアプリの明示保存は旧世界を含めてv6キーへ書く。旧世界のpayloadはv5のまま（plainまたはversion 5のgzip）でよい。これにより、v6の世界を開いた後に旧世界を明示保存しても、古いv6キーが次回起動で優先される不具合を避ける。v5以下のキーは削除せず、読込・導入・新規作成はどのキーへも自動書込しない。保存先への1回の`setItem`が失敗したら元の値とsessionを保ち、完全なJSONの書出しを維持する。

## 5. 本番の進行と検証

`advanceWorldSession`、手動／自動の`chooseWorldSession`は同期を保持する。非同期の試走APIをUIから呼び、そのたびに元世界の保存・復元・SHA計算を行う構成にはしない。外部入力の非同期検証は読込境界に集め、所有するsessionの通常進行では確定した差分だけを積算する。

1. 既存の文明・施設・住宅・共同空地・橋を進め、選択待ちで停止する。
2. 前回の確定年+1から新たな確定年まで、同年の土地利用・建築の履歴を確定順に読む。
3. 後発占有による埋戻し→維持期限・放棄・埋戻し時計→稼働畑の休止→灌漑原因による新設・点検・修復→畑の復旧による再開、の順でA2と同じ状態遷移を適用する。
4. その年の最終的な稼働状態と工事攪乱を、気候・土地利用と同じ環境runnerへ渡す。D2環境を先に全期間積算してから別の環境を保存する二重方式は採用しない。
5. checkpoint/currentを確定し、全構成が成功してから新しいsessionを返す。未確定年の期限・水分・工事を先取りしない。

新しい自然原因だけが新経路を探索できる。読込・観測・描画・再書出しは保存された決定を再生し、経路と気候を生成しない。writerを読み込まないcold loadと、探索関数を例外にした検証を継承する。A3の独立試走と本番ではwire形が異なるため、同じ入力の幾何・状態遷移・receipt・全年度の環境stateを正規化した意味の比較も行う。

新設の最適化・世代切替で文明stateの差が出たら、D3-Cの結果として許容せずBの不具合として扱う。工事に社会的負担を反映しないBの仮定では、建築優先も含めてD2の完全な文明state・RNGが一致する必要がある。

### 5.1 重い読込の扱い

A3のCIでは1万年の完全検証読込がPC約6.01秒／CPU4倍約25.25秒、静止画準備の中央値最大が約138／579msだった。温まった観測最大約3.9／18.5msやフレーム時間と混同しない。

B1はデコードから検証済みsessionの採用までを非同期の入口にまとめる。外部値を上限検証・所有するコピーへ固定してからawaitを挟み、呼出元の変更を検証後へ持ち込まない。年次再生と大きい走査は小さなバッチに分け、ブラウザへ制御を戻す。バッチ計算の目標予算は8msとし、JSON parse・gzip等のネイティブ処理は別に時間とlong taskを測る。同期APIの外側で単にPromiseへ包んだだけを応答性の改善とは扱わない。

読込中は既存の待ち表示を描画してから処理し、進行・選択・導入・保存の同時実行を止める。検証途中のstateを描画しない。検証済みの深く凍結した正確なオブジェクトだけ所有キャッシュへ入れ、`restoreWorldSession`・候補検査・初回描画で全履歴を再検証しない。JSONやstructuredClone後の値を検証済みとみなさず、保存されたフラグも信用しない。

UIは成功後にsessionを一度だけ採用する。失敗時は旧session・保存値を保持して復旧の入口を残す。async境界で実測が遅い場合も検証を省略せず、段階ごとの時間・最長タスクを公開して最適化する。

## 6. 同じ水路viewを描画・歩行・水面へ渡す

`GeneratedSceneGround`へ、その観測年・地点の `channelView` を追加する。viewは導入状態、系統ID・状態、全幅セル、順序を持つ経路と取水を持ち、派生した占有／通水maskは準備時にだけ作る。地形の`physics.surface`や保存済み河川の所有を水路のために書き換えない。

| 状態 | 溝の描画 | 全幅の通行禁止・根元回避 | 加湿 | 溝の流れ |
| --- | --- | --- | --- | --- |
| 導入前／系統なし | なし | なし | 0 | なし |
| active | 水のある溝 | あり | 接続範囲のみ | 取水から畑へ |
| idle | 乾いた溝 | あり | 0 | なし |
| damaged | 破損した乾いた溝 | あり | 0 | なし |
| abandoned | 放棄跡 | あり | 0 | なし |
| retired | 溝なし、環境履歴の回復を投影 | なし | 0 | なし |

溝の占有は矩形の外接範囲に拡張せず、幾何の全セルを使う。2×2の歩行窓について、どれかのセルが溝と重なれば窓を無効にする。既存の橋crossingもこの禁止を解除しない。水路を渡る新しい橋は本段階ではない。

静止した人、動く人、歩行痕、荷車は同じ禁止maskを使う。荷車はアンカーだけでなく車輪を含む地上の占有全幅を照合する。既存の施設入口・住宅入口・access rootの到達性は新設・適合検証で保持し、動く人の経路計画はこのmaskに草木・荷車の追加blockerを重ねる。到達できない活動は描かず、移動や瞬間移動で穴埋めしない。植物は根元の2×2（低木は3×2）で判定し、樹冠の張り出しは許す。

静止画と動く表示は、同じ描画部品と色を使う。地形・環境地表→地上の草・歩行痕→水路→自然水面の橋等の既存layerと草木・人→建物上層という重なりを既存layerに合わせて構成し、水路を建物や橋の上へ描かない。実装では共通の地表水路layerを静止／動画両方から呼び、A3の独立rendererを通常UIへそのまま登録しない。

自然の川／海のmask・流れは維持する。水路の流れは別のtrackとして、`active`の保存済み経路の隣接順に沿って取水から畑へ進める。描けるpixelは全幅セルと可視layerの交差だけで、青い色を検出しただけで通水と判定しない。破損・休止・放棄の年にはtrackを除去する。地形で決まる自然水面trackと、水路trackを混ぜて川の流向を変えない。

歩行・植物・水面は320×180の正本座標で処理し、最後に表示のmirrorを一度だけ適用する。`sceneMotionVisualKey`と経路cache keyには系統ID・状態・経路／占有revisionを含め、破損・修復・埋戻し・地点切替で古い準備を再利用しない。台帳全体を毎フレームhashせず、確認済みviewの不変なキーを準備時に作る。

12fps上限、非表示タブ停止、reduced-motion、動く表示の停止設定は維持する。秒時計・描画回数・タブ切替で年次モデルや台帳・RNGを変えない。停止表示には同じ観測年の静止layerを使い、A3で省略した人・荷車を本番では共通maskに基づいて戻す。

## 7. UIの操作と失敗時の挙動

- 新規の既定世界はB3完了後にv6へ切り替える。seedの毎回ランダム生成と明示seedでの再現は維持する。
- 旧世界の導入ボタンは対象条件を満たす未導入sessionにだけ表示し、「今までの風景はそのまま、これからの水路を記録します」と説明する。操作後も観測年・地点を保ち、自動進行を停止する。明示保存までブラウザの保存は更新しない。
- 川辺では観測年の水路状態を短く示せるが、歴史上の灌漑の出来事がすべて水路建設に成功したとは表示しない。導入前は「水路の記録はまだありません」とし、「水路が存在しない」と断定しない。非成立の技術的診断は比較資料へ残し、通常の操作へ探索上限やrule IDを露出させない。
- 導入中・読込中は二重操作を止める。未知版・破損保存・容量超過では保存を上書きせず、現sessionまたは起動時の復旧画面とJSON読込を残す。

## 8. 実装と受け入れの順序

| 単位 | 成果物 | 統合条件 |
| --- | --- | --- |
| B0（本書） | A3の判断、保存・導入・年次・描画の契約 | 実装箇所と旧契約への影響が具体化されている。実装済みとは扱わない |
| B1 | 中立kernel、本番台帳・統合環境・v6 reader/writer・所有と非同期検証 | 新旧の意味の一致、完全保存・過去・再開・改変拒否、導入前の値を検証。公開の保存許可リスト・新規既定・導入UIはまだ切り替えない |
| B2 | 本番水路view、静止layer、共通歩行mask、水路の動画track | 左右鏡像・各状態・入口保持・人と荷車と根元・水面clip・cache破棄を検証。テスト用入口で統合し、通常UIへ部分機能を公開しない |
| B3 | session・保存発見・新規既定・旧世界の明示導入・UIの原子的採用、CI資料 | B1/B2をまとめて公開し、cold load・全景観・長期・容量・進行・動く表示の性能が成功 |

B1/B2の内部モジュールが先に統合されても、v6入力を公開readerで受理して描画不能なsessionを作らない。B3でallowlist・renderer・session dispatch・UIを同時に有効にする。旧試走形式を本番readerへ追加する近道は使わない。

### 必須の検証

1. **旧世界**：v5 renderer v1〜v5の基準RGBA、旧環境の継続とgzip、v2〜v4の移行を保持。v6キー破損時の発見停止、v6を開いた後に旧世界を明示保存した次回起動、保存失敗とJSON復旧を確認する。
2. **導入境界**：J=0、99、100、任意の途中年、選択待ち、二度目の導入。J以前の全生態系・静止RGBA、文明・敷地・RNG・気候targetが一致し、J年の灌漑を遡って処理しない。v3/v4の景観や旧気候を勝手に更新しない。
3. **新旧比較**：自然seed 1／21／29／42／198の1万年。A3との全水路台帳・幾何・環境の意味の一致、D2との完全な文明state、他2地区と気候の一致。9900→10000の保存再開、年単位／一括／分割／手動選択と自動選択を確認する。
4. **reader境界**：writer・世界生成・気候生成・新探索を遮断してcold load、過去観測、再書出し。不正原因・別世界・制御入力・checkpoint・版の混在・gzip長・導入年改変を拒否。凍結前の入力やawait中の呼出元変更を検証し、所有を偽装したフラグを受理しない。
5. **状態と描画**：自然の全状態遷移前後、制御による休止／復旧・破損／修復・後発建築のsynthetic fixtureを区別。左右岸・mirror・入口・橋・畑・予約壁・2px全幅を検査する。人・荷車・草木の根元と歩行痕が溝を避け、流れがactiveの可視セル外を塗らない。
6. **画面操作**：地点・年・現在への復帰、読込失敗、選択待ち、導入・保存・再読込・JSON、動く表示on/off、reduced-motion、タブ非表示。全操作で保存値が描画回数に依存しない。保存読込の待ち表示と応答性を確認する。
7. **容量と性能**：A3と同じ自然5世界、全保存16MiB／gzip目安4MiB。seed 42の2000／10000年、seed 21の2000年を1回warm-up＋5回中央値で計測。年次・保存準備込み全体を別々に示し、2000年5秒／1万年25秒・同等範囲の基準比2倍以内を要求する。初期生成・導入は別記し、読込や描画を年次の時間へ混ぜない。
8. **観測と動画**：D2の30条件を含むA3の42条件（0／99／100／575／615／1000／10000年×3地区×PC／CPU4倍）に稼働・破損・放棄・埋戻しを追加する。cold restore・初回観測・温まった観測・準備・毎フレーム描画を別に出す。動く表示はp95 83.3ms以内。各5回と分布を保存し、CPU低速化を実機と呼ばない。初期準備と読込のlong task、待ち表示が実際に描かれることも記録する。

B3の資料は `artifacts/environment34-irrigation-production/` に、自然／制御を区別した原寸・4倍の境界比較、状態別の短い動画、台帳・診断・意味の一致監査、旧保存導入前後、容量と全性能値を出力する。人・荷車込みの本番画面でレビューし、状態機械の図だけで景観を受け入れ済みとは扱わない。

## 9. D3-Bの完了と後続

B1〜B3の統合と受け入れで、水路の成立・維持・停止が通常の風景・過去・保存・人の歩行に現れる状態をD3-B完了とする。設計PR、kernel単体、独立rendererの完成を代用にしない。

D3-Cでは工事負担・収穫・資源と食料／人口への作用を独立比較し、結果と歴史差を見て採用・延期を判断する。D3-Bで社会計算を維持したことを、その判断の完了とはしない。D4の切り土・段々畑・河川の付け替えは地形revisionと恒久占有の新契約が必要で、本番水路を載せただけで完了しない。Issue #34は引き続き開いたままとする。

## B1〜B3の実装記録

`production-types-v1.ts` / `production-history-v1.ts` / `production-progression-v1.ts` に本番台帳・統合環境・境界付き導入・writerとreaderを追加した。本番geometryのheaderは独立し、内部adapterでA1の幾何・A2の状態機械と効果を共有する。本番保存に元世界・元世界ハッシュ・制御入力・試走headerや第二の環境を入れない。導入前と以後のcheckpointは同じ環境履歴へ格納する。

外部のv6は既存の地形・文明・敷地検証の後、記録した決定で全環境を再生して照合する。年次再生は8msを目標にバッチを切って制御を戻し、検証済みの深く凍結したworldだけを所有する。JSON解析と既存の地形・文明の構造検証は同期処理であり、その全体が8ms以内になるとの保証ではない。保存読込の総時間は正式計測へ残す。元世界の復元・ハッシュ・独立試走APIは通常進行から呼ばない。

`presentation-v1.ts` に全幅セル・根元判定・溝の描画を集約し、通常の地表、静止した人・荷車・歩行痕、動く人、草木、動画の流れへ接続した。自然の河川・海の物理は書き換えず、溝の流れだけを稼働中の可視セルへclipする。破損・休止・放棄で停止し、埋戻しで占有を除去する。通常の12fps・非表示タブ停止・reduced-motionの仕組みを使う。

新しい既定の世界生成は `createNewIrrigatedWorld` をUIから呼ぶ。既存の `createNewWorld` はD2の版付き生成入口として残し、A2/A3の完全保存・旧renderer基準・対照世界を再現する。本番v6を独立D2試走へ渡す操作は拒否する。通常sessionのv6進行は10000年までとする。

旧世界では「これからの水路を記録する」を明示したときだけ導入し、年・地点・過去の画像と古い保存を保持する。新しいアプリの明示保存先はv6キーで、旧世界のpayloadはv5のまま保存できる。発見・失敗時停止・gzipの内外version照合を接続し、未知・破損v6を旧キーで置き換えない。

追加した単体検証は自然5世界のA3との全イベント・判断・環境投影、完全なD2文明、gzipと分割再開、任意年の導入、選択待ち、改変拒否、古い世界を保存し直した次回発見を扱う。ブラウザではwriter・新探索を遮断した読込、人と根元と可視水路mask、全状態の再描画、旧世界導入前のピクセル、通常画面のv6再読込と破損停止を確認する。既存の保存テストは保存先と新規世界の版の変更を反映し、旧キー不変の検証は残す。

CIの `irrigation-production` は、年次と保存準備の正式性能、自然5世界×1万年とA3の全値・過去・9900年からのgzip再開、本番rendererの固定年と状態遷移前後、通常画面の動画、PC／CPU4倍の46条件を生成する。`audit-irrigation-production.mjs`、`benchmark-irrigation-production.mjs`、`review-irrigation-production.mjs` を順に使用する（性能→監査→描画の順）。出力は本書の `artifacts/environment34-irrigation-production/` で、全5回の準備時間と各120フレームの描画分布を残す。現時点の計測結果・CI状況は実装PRに記載し、資料の生成だけで景観が受け入れ済みとはしない。
