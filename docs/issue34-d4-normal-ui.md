# Issue 34 D4-C2：通常画面と最終比較

D4-Bの小規模整地の景観は利用者が「可」と判定した。幾何と見た目を変えず、[C0の契約](issue34-d4-production-design.md)と[C1の本番正本](issue34-d4-production-implementation.md)を通常画面へ接続する。河川・海岸の工事、盛り土、#34全体のクローズは含まない。

## 通常画面で変わること

新しい文明は `createNewTerrainWorld` を使い、年0から丘陵の小規模整地を記録する。スタートごとのseedはこれまで通り一度だけ抽選し、指定seedでの再開始も残す。旧世代のfactoryは版別の意味を変えない。

既存v7を開いた場合、そのままの世界を表示する。「これからの丘陵で整地を始める」で確定年Jから明示導入する。選択待ちと10000年では導入できない。過去を観測したまま導入しても観測年と画素を保ち、Jより未来の判断だけを始める。v5／v6から水路・経済の導入を飛ばさない。

丘陵の説明は観測年で台帳を絞り、整地の作用件数、承認済みで翌年から使える平場、未耕作／耕作／耕作終了／建築利用を区別する。導入前の年には未来の件数を表示しない。Bの14件には耕作例がないため、「段々畑ができた」と説明しない。追加の掘削費用・直接収穫ボーナスはどちらも0である。

## 非同期操作と失敗時

v8の進行と選択は専用async APIへ渡す。旧世界は従来の同期APIへ委譲し、同期APIへv8を渡すと明示拒否する。手動と自動の進行・選択を同じ入口に集め、busyで二重実行を止める。await後は操作番号と元worldを照合し、候補の3地区を描画確認してから採用する。描画に失敗した場合は元world・観測年・記録表示へ戻す。

保存も元worldから完全packetを作り、書き込み直前に操作番号を確認する。v8保存は旧v7キーを残す。旧v7等の明示importは、表示しただけではキーを変えず、その世界の保存成功後に限って優先キーを削除する。quota失敗では既存キーを削除しない。削除だけが失敗した場合は、書き込み自体は成功したが優先保存を切り替えられなかったことを表示する。

破損v8は旧v7へ黙って戻らず、復旧用importを提示する。復旧のnative読込と書出しには新規world producerが不要。BGMは別のジェスチャー経路のままとし、世界の非同期処理で音声の初期化を遅らせない。

## 最終比較と確認方法

`artifacts/environment34-terrain-production/index.html` は独立進行した実v7と本番v8を比較する。両方の完全保存を通常画面へimportできる。各工事の前・翌年・15年後・300年後、3地区、9指標、最初の歴史差、6種の同年地面図を残す。画像は通常のnative readerとobserverで生成し、Bの公開trial runner／codecで本番世界を作らない。

840枚のRGBA固定参照は本番化前のPR99成功CIから取得したまま。比較データの5世界も本番化前に固定した意味世界・経済・phase・実工事と照合する。年次3ケース、plain16MiB／gzip4MiB、最大記録容量、PCとCPU4倍の46観測条件の描画p95≤83.3msを引き続き検査する。初回native読込・観測・素材準備は描画frameと分けて記録し、CPU4倍を実機計測とは扱わない。

`terrain-review.webm` は比較用の別画面ではなく、seed42の本番v8を開いた通常アプリを録画する。丘陵の100・101・116・1000年を巡り、動く景観・観測年・保存の不変と完全exportの同一性を確認する。Safari相当のWebKit／iPhoneレイアウトと実BGM信号は既存の両engineテストでも新規v8を使って確認する。

単体とブラウザでは旧v7の明示導入、過去保持、Y/Y+1、手動／自動選択の一度だけの確定、二重操作の拒否、v8／v7のキー共存と切替、quota、破損優先キー、invalid／trial import、producer遮断下のnative復旧、上限年、新規seedを確認する。

レビュー順は #99 → #100 → #101 → C2。利用者の景観受け入れは引き継ぐが、リモートのマージは利用者が行う。全CIの成功と通常画面の証拠を揃えるまでD4の最終実装完了とは報告しない。
