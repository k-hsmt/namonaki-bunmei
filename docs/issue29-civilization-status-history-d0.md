# Issue #29 D0詳細設計｜文明ステータスバーと歴史グラフ

- Issue: [#29 観測UI｜文明ステータスバー＋歴史グラフ](https://github.com/k-hsmt/namonaki-bunmei/issues/29)
- 状態：**D0設計案／Humanレビュー用。文書のみ。**
- 目的：320×180pxの風景・年代記の観測を妨げず、**確定した文明全体の指標**と、その歴史を同じ観測年で読む。
- 優先規約：[AGENTS.md](../AGENTS.md)。旧セーブの互換のためのreader・補完を新設せず、**現行世界の保存・再現・未来遮断**を維持する。

## 0. Human確定事項

| 判断 | 結論 |
| --- | --- |
| 過去データ・保存 | **A**：新しい文明は世界暦0年から5指標の確定履歴を持つ。旧保存形式の後方互換性は原則維持しない |
| グラフの置き方 | **B**：Canvas直下のコンパクトな5指標ステータスバーを常時表示。グラフは指標を選ぶと1件だけ展開 |
| グラフから過去観測 | **C**：マウス等のPC操作は直接年移動。タッチ操作は年／値の仮選択後に「この年を観測」で確定 |

**このD0で未採用の仕様を勝手に確定したことにはしない。** 20年前差分、200年を初期期間、50/200/全期間、重要イベントマーカー、人口の縦軸の取り方などは本書の**実装提案値**。S2/S3の比較結果とHumanレビューにより調整できる。

## 1. 目的・非目的

- **勝敗、総合得点、ランキング、成功／失敗判定を追加しない。** 人口・文化の増加を善、減少を悪として着色しない。
- 新指標の創作、文明の年次進行ルール・食料や社会の計算式・確率・乱数消費を変えることを禁止。
- 表示するのは文明**全体**。現在の「川辺／丘陵／入り江」地点切替に連動する**地区人口とは別**。地区を変えても5つの文明全体指標は変わらない。
- 初期の5指標：**人口**（単位 人／指定年は既存`ObservationLedger`）、**食料**（`CivilizationState.food`／0〜100）、**結束**（`cohesion`／0〜100）、**知識**（`knowledge`／0〜100）、**文化**（`culture`／0〜100）。
- 衛生・幸福度は独立した年次正本がないため**実装対象外**。既存の他指標から「幸福度」「衛生」として推定・捏造しない。
- 疫病・豊作など年代記からの原因の新しい自動推論、地域別ダッシュボード、描画演出での履歴変更も対象外。

## 2. 既存コード上の真実と変更境界

- `src/story/observations.ts`：人口は100年チェックポイント＋年次差分を、`commitObservation()`で一確定年ずつ記録。`observationAt()`で指定年の地域別と合計を復元。
- `src/story/engine.ts`：年次`step()`中に選択`pending`が発生すると**途中の内部`state.food/cohesion/knowledge/culture`が更新済み**であり得る。`finishYear()`が呼ばれるのは選択確定後。`lastObservedYear()`は未確定の選択年より1年前。
- `src/story/generated-state-review.ts`：新規生成世界の状態と観測境界を厳密に検証。`observation`の現在の必須フィールドを保守的に拡張する必要がある。
- `src/climate/climate-world-v1.ts`：最新の外側の保存は**v10/schemaVersion 2**。内部`ArchitectureProductionSave`に文明`state`があり、読み込みは外側だけでなく内側のバリデータを通る。
- `src/main.ts`：`viewedYear`が過去観測の中心。`rewind-year`／年代記のクリック／`return-now`などを統合する。現在は過去の食料・結束・知識について「記録なし」と表示し、文化は既存の下段統計欄にない。
- `index.html`、`assets/style.css`：Canvasと既存`.stats`が離れている。S2ではCanvas外の直下へ新バーを追加し、下段の重複値は整理する。

## 3. 保存される年次記録の正本

### 3.1 初版の推奨データ構造

既存の`ObservationLedger`内に、**人口以外の4指標**だけを保存する。人口は既存台帳を参照し、二重保存しない。

```ts
interface ConfirmedMetricLedger {
  readonly ruleId: 'civilization-metrics-v1';
  readonly firstYear: 0;
  // values[year] = [food, cohesion, knowledge, culture]
  readonly values: readonly (
    readonly [number, number, number, number]
  )[];
}
```

この型は概念型であり、実際に`ObservationLedger`の`metrics`フィールドへ置く構成をS1の第一候補とする。種々の試作用`CivilizationState`生成・内部所有・外側v10 packetと同時に検証できるようにする。

- **新規生成時**：世界暦0年の確定値を記録し、`values.length===1`。
- **確定年yの進行後**：`values.length===lastObservedYear+1`。人口`blocks`と追加履歴の**確定年境界が完全一致**。
- **未確定の選択待ち**：内部状態の`state.year===lastObservedYear+1`だが`values`には当年のスロットを**作らない**。過去観測は直前の確定値を参照。
- **選択確定後**：その年の値を1回だけ確定。自動選択・手動選択・保存復元後の選択で同じ結果。
- **内部値**：すべて有限数、0〜100。保存時の丸め・`Float32`量子化はしない。表示のみに丸めを使い、小数の元値を保つ。
- **過去**：現在値・イベントや折れ線から逆算して埋めない。年番号による配列参照は厳格に境界検査する。
- **人口**：既存`observationAt(...,y)`の確定人口を利用。`state.population`は未確定年に変化済みの可能性があるので表示用の過去人口には利用しない。

### 3.2 確定処理の原子性

`finishYear()`の**人口`commitObservation`と同じ確定境界**で指標を1回だけ書く。既存人口コミット後に失敗して片側だけ保存される経路を避け、事前に入力・年次を検査してから一緒にコミットするAPIをS1で設計する。例えば`commitObservation(ledger, year, metrics)`の中で次の全条件を確認してから更新する。

1. `year`は`lastYear+1`であり、同年二重コミット・年飛び・負の年を拒否。
2. 人口の確定値と4指標が数値範囲・構造条件を満たす。
3. 人口ブロックを更新し、4指標を追加し、**同じ観測境界**を更新する。エラー時は不整合な「人口だけ確定」を残さない。
4. サンプル（既存10年ごとの`samples`）は従来のまま**図の正本にしない**。

`step()`／`choose()`の前後で追加の文明用`SeededRng.next()`は呼ばず、既存年次処理・人口・社会・経済効果を変更しない。

### 3.3 保存形式の境界

初期案：外側の`ClimateWorldSave`を**v10/schemaVersion 3**に改め、完全な観測指標履歴を必須にする。ただしS1で厳密な保存入れ子の依存を確認し、`v11`が明確な責務分離になる場合は差分・理由を示してHumanレビューを受ける。**旧v10/schemaVersion 2を読めるようにするmigrationは作らない**。

- `validateClimateWorldSave()`、内側`validateGeneratedState()`等、通過する**すべての現行バリデーション境界**を更新し、正確なバージョン・フィールド・履歴長・年・型・有限値・範囲を検査。
- 正常確定時は、`values[lastObservedYear]`と`state.food/cohesion/knowledge/culture`の一致を確認。**pending中は内部状態が暫定値である**ため、暫定`state.*`と直前の確定値を一致させる検証を禁止する。代わりに、確定履歴の長さと最終確定年の一貫性を検証。
- 既存の厳格な`sameWire`等に沿い、未来の記録・欠けた年・重複・不正数値・不明フィールドを拒否。**過去値を勝手に補修しない**。
- 新形式へ変更した結果、古い保存が開けない場合は**理由を伝え、保存キーの消去・自動上書きは行わない**。再開は新規文明から。
- `world-storage.ts`のgzip包み・16MiB未圧縮制限、v10系列の圧縮保存4MiB制限を守る。失敗した場合、指標履歴だけを落として成功にしない。

### 3.4 容量と長期

上限10,000年なら**10,001行 × 4数値 = 40,004数値**。IEEE754 64bitの概算生数値部分は約313KiBだが、**JSONの表記長は異なり**、他の文明世界・地形・植物・住宅履歴を含む総セーブとの比較が必要。圧縮前後と所要時間を実測する。

当初は**毎年確定値をそのまま保存する配列**。人口のような100年チェックポイント＋差分にするかは実測によってのみ再判断。浮動小数点差分の復元誤差や四捨五入を避けることを優先。

## 4. 共通の読み取り契約

提案API：
```ts
type CivilizationMetricKey =
  | 'population' | 'food' | 'cohesion' | 'knowledge' | 'culture';

interface CivilizationMetricObservation {
  readonly year: number;
  readonly population: number;
  readonly food: number;
  readonly cohesion: number;
  readonly knowledge: number;
  readonly culture: number;
}

function observeCivilizationMetrics(
  state: Readonly<CivilizationState>,
  confirmedYear: number,
): CivilizationMetricObservation | null;
```

- `confirmedYear`は0以上の確定整数年、`confirmedYear<=lastObservedYear(state)`。不正値・未確定・未来は読み取れない。正本自体が破損している場合は**nullで黙って補完せず検証失敗**。
- このAPIをステータス・グラフ・各年の読み上げ・差分計算で共用。UI側で`state.food`から過去値を作り直さない。
- 20年前差分（初期案）：`V(y)-V(y-20)`。`y<20`は**「比較対象なし」**（「欠測」ではない）。人口は人数差、他は指標の差、％増減にはしない。増加＝善／減少＝悪を示唆する色は使わない。
- 表示丸め：人口は整数、4指標は小数第1位を初期候補。保存・差分計算は丸め前の値。差分が表示上0.0なら`±0.0`などの無評価な表示。
- 地区切替では同じ`state`・`year`の文明全体5指標が同値であることを検証する。

## 5. 観測UI：ステータスバーは常時、グラフは選択時だけ

配置：`index.html`の`scene-frame`内、Canvasの**外側**・景観の補足行付近に**「文明全体の状態」**を追加し、年代記本文の前へ。既存の`.stats`には文明名・出自などの説明的要素を残す一方、同じ指標を二重管理しない。

- **常時**：人口・食料・結束・知識・文化の5つ。観測年`y`の値と20年前差分（年数不足なら比較対象なし）。Canvasの上には載せない。
- **クリック／タップ**：1指標だけを選択。Canvas下に同じ画面でグラフを展開。別指標で差替え、閉じるで非表示。**初期状態は閉じる**。
- ステータスバー自体に、スコアの「満点」や勝敗の色／総合値を導入しない。人口を固定上限で100%の進歩バーにしない。
- グラフ未展開でも5指標は可読。既存の説明文や年代記は残し、Canvasの比率`320×180`を変えない。
- PCでは5指標横並び。スマホではタップ領域・長い人口値を優先し**3+2折返しを第一候補**。横スクロールはD2の原寸比較で検証。テキストと数値は色なしでも識別可能。

## 6. グラフ：期間・単位・年を管理する

### 6.1 1指標ずつ表示

- **初期提案**：直近200年、切替`50年／200年／全期間`。ただし文明開始から年数不足の範囲を世界暦0年で切り詰める。
- グラフは**確定したデータ**のみに基づき、表示する年の上限は`lastObservedYear(state)`。
- 50年・200年：連続する前年の値を折れ線で描く。全期間も正本は1年ごとに保持し、実画面では後述の縮約を利用。
- 人口：絶対人数と人単位を表示。固定の「理想人口」や進捗上限は設けない。縦軸は原則0以上で、可視域のデータ上限を基準に上限を選び、目盛りを明示。**0起点か拡大縦軸かの表示比較**はS3のHumanレビュー対象。
- 4指標：**0〜100の同じスケール**。各指標は単独プロットとし、人口と複数軸で重ねない。
- 最小／最大／表示軸の範囲、色／マーカー／選択点に数値ラベルを付け、色覚・タッチでも判別可能。
- 不正・未来・欠落の記録を直線補間しない。A案の新規世界では欠測なしが契約なので、欠落を発見した場合は記録バリデーションの失敗として扱う。

### 6.2 観測年と表示範囲の分離

少なくとも次の二つは区別する：
1. **`selectedObservationYear`**：Canvas・ステータスバー・年代記・過去スライダーが共通で指す**確定観測年**。
2. **`graphViewport`**：表示している期間・始点・終点（どの時代を探索しているか）。過去の年を選んでも**表示範囲を自動再センタリングしない**。

- グラフ展開の初期は現在の最後の確定年を終点とする。
- ライブ観測中は通常、確定年が進むのに合わせて範囲を追従してよい。ただし、利用者がグラフで過去を観測し始めたら**表示範囲を固定**し、前後年を比較しやすくする。
- 「現在へ戻る」で最後の確定年を再選択し、グラフを現在まで追従できるようにする。期間変更は表示範囲を明示的に変更する操作。
- 1年未満の位置・10,000年を越える位置・未確定年の選択を許さない。
- グラフ表示範囲の年数が乏しい場合でも、範囲外に空の「架空の年」を書かない。

### 6.3 全期間の縮約

- 10,001年分を狭い幅へそのままプロットして線で埋め尽くさない。**保存データは削らず、描画点だけを間引く**。
- 一定の横幅セル／区間に入った確定値の**先頭・末尾・最小・最大（元の年付き）**を保つ縮約を候補にし、短期間の飢饉等の急落が平均化で消えないことを確認。
- 縮約はイベント時刻・人口値を変えない。タップ・ポインタが選ぶのは**実際の整数年とその年の正本値**であり、集約平均や間引き点の仮値ではない。
- 初期表示で全10,001点をDOM要素1個ずつへ展開しない。描画はSVG単一路／Canvas等をS3で比較、静的HTMLのアクセシビリティ情報は別に保持。
- 毎フレームのグラフデータ再走査は禁止。年次の確定更新／指標・期間・画面サイズ変更をキーにデータ投影を更新。既存の高速進行描画間引き（`main.ts`の1.4秒節流）を尊重する。

## 7. Human決定C：グラフから過去へ移動する操作

**デバイス名・User-Agentで判定しない**。実際の入力方式（例：`PointerEvent.pointerType==='mouse'`／`'touch'`、必要なら`matchMedia('(pointer: coarse)')`を補助）で分岐し、タッチ付きPC・外部マウス付き端末にも整合する。合成clickによる二重実行を防ぐ。

| 入力 | 選択 | 実行 |
| --- | --- | --- |
| マウス・トラックパッド | 確定年へヒットテスト／最近傍年へスナップ | **クリック時に直接**共通観測関数を呼ぶ |
| タッチ | 候補年と**その年の正本値**を一時表示 | **「この年を観測」**ボタンで確定するまでCanvas・年代記は移動しない |
| キーボード／支援技術 | 年入力・±1年・候補値を読み上げ | **明示的な確定操作**で移動（誤操作を防ぐ） |
| イベントマーカー | マーカーの年、件数・タイトルを表示 | 同じ入力方式の規則に従い、該当年へ移動 |

スマホの全期間グラフでは1pxが数十年になり得る。そこで**年を直接選べる数値入力、±1年操作、前後イベントへの移動**を備え、タップ座標だけで1年を正確に選ぼうとしない。

タッチの候補選択はUI一時状態であり、まだ`viewedYear`や履歴に書かない。複数タップをしたら候補のみ更新し、最終的な確定ボタンでその時点の候補年を採用する。新しく進行・再開始・別の世界をロードした場合、**仮選択を破棄**して異世界への誤遷移を防止。

### 7.1 過去観測の共通入口

現行`main.ts`の`inspect()`・`rewind-year`・`return-now`・年代記行にある分散した年移動操作を、新しい共通年選択の契約に整理する。

概念型：
```ts
type ObservationSelection =
  | { readonly mode: 'live' }
  | { readonly mode: 'historical'; readonly year: number };
```

- **live**：現在の最後の確定年を観測。分岐選択待ちなら選択UIは残すが、バー・グラフ・Canvasは前年の確定履歴だけを表示する。
- **historical**：整数かつ`0<=year<=lastObservedYear(state)`の年だけ。自動進行・選択タイマーを停止し、Canvas・ステータス・グラフの選択印・年代記・`rewind-year`を**同じ年**へ同期。
- グラフのビューポートは共通観測年とは別に管理。年選択の度にグラフ範囲が飛ばない。
- **現在へ戻る**：共通入口で`live`へ戻し、グラフ範囲を再び現年へ追従。現行の`viewedYear=null`相当。
- 直近確定年と`state.year`の差に注意：pending中、`year=state.year`は**まだ観測できない**。既存スライダーの`y===state.year`判定は、`lastObservedYear`による判断へ統合し、確定した過去扱いかライブ扱いかの混乱を防ぐ。
- 同じ年で世界・Canvas・年代記が一致していることをE2Eで確認。グラフから新しい年へ移動しても文明年次処理を呼ばない。
- 画面内でグラフ位置・スクロールを不必要にリセットしない。フルリレンダーではなく必要な状態だけ差分更新できるかS2/S3で確認。

## 8. 年代記イベントマーカー

- マーカーは**実際の`RecordEntry`（`year,id,tag,important`等）だけ**から取得。未来年、未確定の選択の途中イベント、構造上存在しない事象をマーカーにしない。
- 初期提案：`important===true`、または人間が別途指定した種類など、**重要な年だけ**を控えめな縦線・点にする。何を「重要」と定義するかは記録の既存属性に従う。
- 同年複数イベントはまとめて「n件」と表示し、タイトル・年への詳細参照を提供。全期間では画素当たり重なりが大きくなるためさらに密度を制限しても**元のイベントを削除しない**。
- 選択したイベントと人口増減の関係を**原因として断定しない**。チャートは「その年に記録された出来事」として示す。
- 年代記本文や既存の建築注記をコピーして、未記録の「新たな歴史イベント」を追加しない。

## 9. UIの細部・アクセシビリティ

- 用語は「文明全体」「世界暦◯年」「人数」「0〜100の指標」。幸福度・生産力の表記に置き換えない。
- 色のみで意味を伝えず、数値・軸・指標・増減方向を文字・記号で示す。緑＝成功、赤＝失敗の評価色は使わない。
- タップ対象とキーボードフォーカスは十分な大きさを確保。モバイルでCanvas縮尺・年代記本文の可読性を破壊しない。
- 自動進行中でもグラフ展開・指標切替・速度変更が文明乱数や確定史に影響しない。過去観測を**確定した瞬間**に自動進行停止。
- UIが描画に失敗した場合も、セーブや文明の状態は保護する。空白グラフやダミー値で偽装しない。

## 12. D0結論

文明全体の数値は「勝ち負け」ではなく、同じ世界が歩んだ時間を観測するための記録。**人口は既存確定履歴、残る4指標は世界暦0年から欠落のない新規台帳**を正本とする。未確定年の途中値・過去の推測値を表示しない。

人間の視線はまず景観に向く。ステータスバーで小さな変化に気づいた時だけグラフを開き、数値の曲がり角から同じ年の風景と年代記へ戻る。**C案の入力契約で操作の正確さと軽やかさを両立**し、画面の静けさを保つ。

本PRがHumanにマージされた後、**S1は保存正本と厳密検証のみ**を最初の実装範囲とし、UIの同時実装や旧セーブmigrationは行わない。
